# 写作规范

目标不是「写得漂亮」，是**三个月后的自己能直接照着做**。

## 一页一件事

一页只回答一个问题。写不下了就拆页，再用链接串起来。

## 结论先行

第一段就是结论。背景、推导、例外放后面，读者随时可以停。

## 标题层级

- `#` 只出现一次，就是页面标题
- 正文从 `##` 开始，最多到 `####`
- 标题写「做什么」，不写「概述」「其他」

## 链接

站内用相对路径，换域名不会断：

```markdown
[写作规范](writing.md)
[示例条目](../notes/example.md)
```

外链写完整地址，并在正文里说清「点进去能看到什么」。

## 图片

放在 `docs/assets/`，用相对路径引用，写清 alt 文字：

```markdown
![备份流程的三个步骤](../assets/backup-steps.png)
```

## 代码

围栏代码块必须标语言，否则不高亮：

````markdown
```bash
mkdocs serve
```
````

## 提示块

需要强调「别这么做」时用：

```markdown
!!! warning "先备份"
    这条命令会覆盖目标文件。
```

渲染成：

!!! warning "先备份"
    这条命令会覆盖目标文件。

## 别做的事

- 不写「点击这里」「详见上文」——链接文字要能独立看懂
- 不在正文里堆日期；日期进[更新日志](../about/changelog.md)
- 不整篇复制外部文章，写摘要 + 原链接

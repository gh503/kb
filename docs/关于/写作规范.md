# 写作规范

目标不是写得漂亮，是**三个月后的自己能直接照着做**。

## 文件与目录命名

- 目录名就是学科名，中文：`工程/开发/`
- 条目文件名用中文名词短语，**不带编号、不带日期**：`内存泄漏排查.md`
- 短：2–12 个字，能直接当标题用
- 不用空格和标点；需要分隔时用连字符：`杭州-社保转移.md`
- 路径定了就别改——改一次，URL 断一次

!!! note "排序靠 nav，不靠文件名"
    侧栏顺序由 `mkdocs.yml` 里的 `nav` 决定。文件名塞 `01_` 只会让路径变丑，
    而且每插入一条就要重排后面所有文件。

## 放哪一科

一条笔记只能有一个主学科。判断标准不是"内容属于哪"，是**你下次会去哪一页找**。

跨学科不复制两份，用链接互指：

- 「备份怎么做」→ 做法在[运维](../工程/运维/index.md)，家里的备份习惯在[生活](../日常/生活/index.md)
- 「政策怎么落地」→ 文本在[政治](../人文/政治/index.md)，推进方法在[项目管理](../商业/项目管理/index.md)
- 「模型老答错」→ 能力与评测在 [AI](../智能/AI/index.md)，接进服务的写法在[开发](../工程/开发/index.md)

## 一页一件事

一页只回答一个问题。写不下就拆页，再用链接串起来。

## 结论先行

第一段就是结论。背景、推导、例外放后面，读者随时可以停。

## 标题层级

- `#` 只出现一次，就是页面标题
- 正文从 `##` 开始，最多到 `####`
- 标题写「做什么」，不写「概述」「其他」

## 条目状态

学科页的条目表有「状态」一列，只用三个值：

| 值 | 含义 | 什么时候用 |
| --- | --- | --- |
| 草稿 | 有结论，没验证过 | 刚写完，先占位 |
| 整理中 | 结论可用，缺细节或例子 | 用过一次，还想补 |
| 稳定 | 用过两次以上，没再改 | 可以依赖它做决定 |

## 条目类型与学段

自然科学不按"操作步骤"组织，按**问题**组织。每条先声明两件事：

```markdown
> **学段** 初中–高中 ｜ **类型** 机制 ｜ **链** 四季
```

**五种类型**（回答的是哪个问题）：

| 类型 | 回答 | 例子 |
| --- | --- | --- |
| 机制 | 它怎么运转的 | 天空为什么是蓝的 |
| 边界 | 在什么范围内成立 | 不粘锅涂层怕多热 |
| 量级 | 大概多少，够不够用 | 一块电池能存多少焦耳 |
| 误区 | 大家都信但错在哪 | 重的物体先落地 |
| 对比 | 两个东西差在哪 | 云为什么白、天空为什么蓝 |

**五个学段**（写到什么程度）：

| 学段 | 写到什么程度 |
| --- | --- |
| 小学 | 现象 + 一个比喻，**不出现公式** |
| 初中 | 定性机制 + 一个能自己验证的日常例子 |
| 高中 | 一个定量关系 + 单位，能代入算 |
| 大学 | 模型与近似条件，能自己推一遍 |
| 研究生 | 边界、争议、未解，标明证据强度 |

**一条链天然跨学段**：小学看结论，高中看公式，研究生看"哪里还没搞懂"。
同一个现象不要按学段重复写五页——把深的那层写成链上的下一环，用链接串起来。

## 人文条目的额外规矩

自然科学的条目只需要"结论可验证"。人文条目还要多两道手续，否则很容易写成情绪。

### 一、「事实与判断」小节必须有

每页在「边界」之前放一节 `## 事实与判断`，至少三条：

```markdown
## 事实与判断

- **事实**：有史料或统计支撑的
- **事实**：同上
- **判断**：我的解释，或者学界的某一种解释
```

理由：人文内容的争议往往不在数据，而在**从数据到结论那一步**。
把这一步显式写出来，读者才能只引事实、不替我背书。

### 二、交叉链接宁缺不错

指向别的学科的链接，**语义必须成立**：读者点过去应该"接着想看"，而不是"凑数"。

```text
好：[季风为什么会失灵](../自然/地理/季风为什么会失灵.md)   ← 饥荒的成因之一
差：[保温杯为什么能保温](../自然/物理/保温杯为什么能保温.md) ← 为了让断链检查过关而硬凑
```

上面两行只是示例写法，不是真链接——**规范里的例子不要做成可点的链接**，否则示例一过期就变成断链。

断链检查保证的是"不 404"，保证不了"有意义"。**没有合适的，就整段不写。**

### 三、只写历史，不写当代

判断类内容最容易滑向现实议题。这一域的边界是：**只处理已经进入史料的制度与人**，
不做现实政策的立场表达。讨论现代机制时，只讲历史案例与机制本身，并标明"不对现实政策作主张"。

## 商业条目的体例

商业内容最容易写成"心得"：听着有道理，用起来没法落地。所以不用学段，改用**深度 + 证据强度**。

```markdown
> **深度** 入门 ｜ **类型** 取舍 ｜ **链** 渠道怎么选
```

**三档深度**：入门（是什么、怎么算）→ 实操（怎么做、阈值多少）→ 取舍（什么时候不该这么做）。

每页固定四件东西：

1. **可代入的公式或清单**：给数就能算
2. **数字与阈值**：区间 + 适用条件
3. **证据强度**：这一节必须写，标明是**实测 / 公开经验 / 推断**——没有实测就直说
   - 阈值小节统一叫 `## 数字与阈值`，不要另起名字（速查表要靠它定位）
4. **不适用的情况**：什么生意、什么阶段不该照做

第 3 条是这一域的底线。没有实测数据却写成"经验证明"，就是骗人。

## 别做的事

- 不写「点击这里」「详见上文」——链接文字要能独立看懂
- 不在正文堆日期；日期进[更新日志](更新日志.md)
- 不整篇复制外部文章，写摘要 + 原链接
- 不写没有上下文的代码片段和命令

## 排版：让人能一路读下去

正文栏宽固定 **700px**、字号 17px、行高 1.9——中文约 38–40 字一行。这些值在
`docs/stylesheets/reading.css` 里，改一处全站生效。

**四层视觉权重**，写的时候按这个顺序安排内容：

```text
最亮   结论        自动变成浅底卡片（由 CSS 对 ## 结论 生效，不用手写样式）
次亮   数字与阈值   紧跟在结论后面，给能代入的数
正常   正文         推导、例子、命令
最轻   证据强度 / 不适用 / 常见错法 / 往下追 / 相关   —— 读作页脚注
```

五个"页脚注"小节自动降级为 15px 灰色、无下划线，**它们不该和正文抢注意力**，但仍要写全。

### 什么时候加图

**能画成"关系"或"变化"的时候就画**，纯文字讲不清的优先加图：

| 该画 | 例子 |
| --- | --- |
| 有先后顺序 | 编译五步、DNS→TCP→TLS→HTTP |
| 有层级 | 证书链、内存分区 |
| 有量的对比 | 排序耗时、扫描 vs 索引 |
| 有分叉 | 故障安全的分支 |

写法：在页面里留一行 `<!-- kb-chart:名字 -->`，然后跑 `python3 scripts/gen_charts.py`。
图是**内联 SVG**，用 `currentColor` 与 CSS 变量取色，深色模式自动跟着变，不额外下载文件。

**图里的数字必须来自实测或可直接计算的公式**，且在 caption 里写明条件。
画不出来的别硬画——一张装饰图比没有图更糟。

### 一条链的四页要能互跳

每页顶部有一条 `kb-chain` 导航（由 `scripts/add_chain_nav.py` 生成），当前页高亮、不可点。
**不要手改这一行**，改完链表重跑脚本即可。

**必须写成 Markdown 链接**，容器要带 `markdown` 属性：

```html
<div class="kb-chain" markdown>
<span class="kb-chain__label">本链四页</span> <span class="kb-chain__now">当前页</span> · [下一页](下一页.md)
</div>
```

原始 HTML 的 `<a href="x.md">` 不会被 MkDocs 重写（它只处理 Markdown 链接），
构建后仍是 `x.md`，从 `/A/B/C/` 点进去就是 404。`check_kb` 现在会拦这一类写法。

## 排版上别做的事

- 不用 emoji 当小标题（搜索会变噪音，读起来也跳）
- 不在一段里塞三种字号
- 不为了"看起来专业"加装饰性表格
- 同一页不超过 2 张图：图多会打断阅读节奏

# 快速开始

## 本地预览

需要 Python 3.9 以上。

```bash
git clone https://github.com/gh503/kb.git
cd kb
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
mkdocs serve
```

打开 <http://127.0.0.1:8000/kb/>。改 `docs/` 下的任何文件都会**自动热更新**。

> 本地预览的地址带 `/kb/` 前缀，因为 `site_url` 是 `https://gh503.github.io/kb/`。
> 直接开 `http://127.0.0.1:8000/` 也行，会 302 跳过去。

## 目录结构

```text
kb/
├── mkdocs.yml              # 站点配置：导航、主题、搜索
├── requirements.txt        # 依赖，本地和 CI 同一份
├── docs/
│   ├── index.md            # 首页（六张领域卡片）
│   ├── 基础/ 工程/ 商业/ 人文/ 自然/ 日常/
│   │   ├── index.md        # 领域页：这一域收什么
│   │   └── <学科>/index.md      # 学科页：收什么、不收什么、条目表
│   ├── 关于/               # 快速开始、写作规范、更新日志
│   └── assets/             # 图片
└── .github/workflows/      # 推送后自动构建并发布
```

## 加一条内容（最常见）

1. 在对应学科目录下建文件，例如 `docs/工程/开发/内存泄漏排查.md`
2. 在 `mkdocs.yml` 的 `nav` 里，`开发:` 下面加一行：

   ```yaml
   - 内存泄漏排查: 工程/开发/内存泄漏排查.md
   ```

3. 打开 `docs/工程/开发/index.md`，在条目表里加一行（一句话 + 状态）
4. 本地 `mkdocs serve` 看效果
5. 提交推送：

   ```bash
   git add -A
   git commit -m "开发：内存泄漏排查"
   git push
   ```

> 漏了第 2 步会怎样：CI 直接失败。站点配了 `validation.omitted_files: warn` + `--strict`，
> 没进 `nav` 的页面会被当成错误拦下来——**不会悄悄消失**。

## 加一个学科（很少做）

1. `docs/<领域>/<学科>/index.md`，复制一个现成的学科页改
2. `mkdocs.yml` 里对应领域下加一段
3. 领域页和首页的表格/卡片里补一行
4. 更新 [更新日志](更新日志.md)

## 发布

```text
git push → GitHub Actions（构建 + 严格校验）→ GitHub Pages（线上）
```

- 只有 `main` 分支触发
- 构建日志：仓库 **Actions** 标签页
- 线上：<https://gh503.github.io/kb/>

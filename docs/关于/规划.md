# 规划：剩下四个域怎么建

> 现状（2026-10-25）：自然、人文、商业、日常四域已成体系。
> 基础、工程、智能、网络四域已建成，现进入**内涵扩充**阶段：
> 第一批新增 10 个学科（计算机/算法与数据结构/操作系统/数据库/概率论/线性代数/高等数学/软件安全/主机安全/硬件安全）。
> 已完成：**工程四科 32 条 + 概率论 8 条**（均本机实测支撑）。其余：线性代数、高等数学、安全三科。

## 为什么按这个顺序

```text
第一优先 工程（开发/测试/运维/设计）  每天用，错一次就留坑
第二优先 网络（TCP-IP/网络通信/安全） 排障靠它，不学就只会重启
第三优先 智能（AI/机器人）            变化快，先立骨架，不追新闻
第四优先 基础（通用基础/数学/逻辑）    最底层，最后写反而更清楚
```

**先写"能马上用"的，后写"要沉淀"的。** 四个域共用同一套体例，不另立规矩。

## 每个学科怎么切链

一条链 = 一个能一路追问下去的问题，4 页一链。下面是初定的 24 条链。

### 工程（12 条链）

| 学科 | 链 | 四页 |
| --- | --- | --- |
| 开发 | 代码怎么写得能改 | 命名 → 函数长度 → 何时该抽象 → 注释写什么 |
| 开发 | 调试怎么少走弯路 | 二分定位 → 最小复现 → 日志怎么打 → 假设怎么验 |
| 开发 | 代码评审怎么看 | 先看什么 → 什么必须拦 → 意见怎么提 → 自己怎么自审 |
| 测试 | 测试写在哪一层 | 单元/集成/端到端 → 什么该测 → 覆盖率怎么读 → 什么不该测 |
| 测试 | bug 怎么写得能被修 | 最小复现 → 环境信息 → 期望与实际 → 优先级怎么定 |
| 运维 | 线上出事怎么处理 | 先止损 → 谁指挥 → 信息怎么同步 → 复盘怎么写 |
| 运维 | 监控看什么 | 四个黄金信号 → 阈值怎么定 → 告警噪音怎么降 → 看板怎么设 |
| 设计 | 界面为什么难用 | 可见性 → 反馈 → 一致性 → 出错怎么恢复 |
| 设计 | 流程怎么画才不漏 | 状态与转移 → 边界情况 → 空状态 → 一次只让做一件事 |

### 网络（6 条链）

| 学科 | 链 | 四页 |
| --- | --- | --- |
| TCP-IP | 一次请求经过了什么 | DNS → TCP 握手 → TLS → HTTP |
| TCP-IP | 为什么慢 | RTT → 带宽延迟积 → 队头阻塞 → 重传与拥塞 |
| 网络通信 | 长连接还是短连接 | keep-alive → 轮询/SSE/WebSocket → 心跳 → 断线重连 |
| 安全 | 口令与登录怎么才算安全 | 哈希与加盐 → 限速 → 多因素 → 常见自欺 |
| 安全 | HTTPS 保护了什么 | 证书链 → 中间人 → HSTS → 常见误解 |

### 智能（3 条链）

| 学科 | 链 | 四页 |
| --- | --- | --- |
| AI | 模型输出怎么验 | 幻觉从哪来 → 检索增强 → 评测集 → 什么时候不该用 |
| AI | 提示词怎么写才稳定 | 结构化输入 → 示例 → 输出约束 → 失败重试 |
| 机器人 | 机器人怎么知道自己在哪 | 里程计 → 传感器融合 → SLAM 概念 → 误差为什么累积 |

### 基础（5 条链）

| 学科 | 链 | 四页 |
| --- | --- | --- |
| 通用基础 | 怎么把一个问题说清楚 | 定义问题 → 事实与判断 → 找反例 → 结论怎么表达 |
| 通用基础 | 怎么判断信息可不可信 | 来源 → 数据怎么读 → 相关与因果 → 承认不知道 |
| 数学 | 够用的概率直觉 | 期望值 → 基础率谬误 → 独立与不独立 → 用区间不用点 |
| 数学 | 够用的统计 | 平均与中位 → 样本偏差 → 显著性与效应量 → 图表怎么骗人 |
| 逻辑 | 论证怎么拆 | 前提与结论 → 有效与可靠 → 常见谬误 → 怎么反驳 |
| 逻辑 | 定义与分类 | 定义怎么写 → 边界案例 → 互斥与穷尽 → 类比何时有效 |

## 技术域的一条额外规矩

**能测的就测，测不了的说清楚。**

```text
可以实测：本机跑一条命令得到的数字（解析耗时、压缩比、握手轮次）
          正文必须写明：环境、命令、样本量
不能实测：别人的机器、生产环境、别人的团队数据
          标"公开经验"或"推断"，不冒充实测
```

这条是为了让工程/网络域比前四个域更硬——**它们的价值就在于能被验证**。

## 一次结构返工（记录下来）

第 145 次更新索引时，替换"## 条目"段的脚本把新内容（以"## 链"开头）插到了旧"## 链"**之后**，
导致 6 个学科页出现**两个"## 链"小节**——旧的只有 1 行、新的有 2 行。

发现方式：用"每个 index 里 `## 链` 出现次数"做体检，一次查出 6 个。
修法：保留箭头行最多的那个小节，删掉其余。

**教训**：替换小节时，锚点必须包含被替换的小节本身，不要用"下一个标题"当右边界。

## 关于"实测"

全站**只有网络域 6 个页面标的"实测"是真的在本机跑过命令**（DNS 计时、curl 分阶段耗时、连接复用、gzip 压缩比、TLS 协商、证书链验证），
正文均写明了环境（Ubuntu 22.04 + 本地代理）与不可外推的部分。

**其余全部为公开经验/推断/公式**。四个速查页的页尾都写明了这一点，各域不同：

基础 0 条（另有 4 个算例已用代码核验）

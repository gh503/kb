# 什么时候该做免费版

> **深度** 取舍 ｜ **类型** 边界 ｜ **链** 钱怎么收

## 结论

**只有当"多一个免费用户的边际成本接近零"且"他能自然转成付费"时才做。**
否则免费版是拿现金买口碑：支持成本、服务器成本、投诉处理，全都要真金白银。

## 三个前置条件

| 条件 | 检查方式 |
| --- | --- |
| 边际成本 ≈ 0 | 加一个用户几乎不增加成本（软件可，人工服务不可） |
| 转化路径清晰 | 免费用户在哪一步会撞到限制，自然升级 |
| 支持负担可控 | 免费用户不占用大量人工答疑 |

三条缺一条，免费版就会变成成本中心。

## 常见的免费形态

| 形态 | 适合 | 风险 |
| --- | --- | --- |
| 功能受限免费 | 工具类，核心功能可体验 | 免费者永远用不到付费点 |
| 用量免费额度 | API、云服务 | 被刷额度，成本失控 |
| 时间免费试用 | 高客单、需上手 | 试用期太短，客户没来得及验证 |
| 社区版/开源 | 开发者产品 | 商业版卖不动 |

## 数字与阈值（经验区间）

```text
免费转付费：2%–5% 常见，超过 10% 属优秀
免费用户支持成本：常被低估，人工类产品尤其高
免费额度：设上限 + 速率限制 + 异常告警，三条都要
```

## 证据强度

- **公开经验**：freemium 转化率区间与成本结构是被广泛记录的经验
- **推断**："三条件"是按成本与转化逻辑列的检查清单
- **未验证**：我没有自己产品的免费转付费实测数据

## 不适用的情况

- 高客单 B2B：免费用户不是决策者，试用要跟着真实业务场景走
- 服务型生意：边际成本高，免费等于白干

## 常见错法

- **免费版做得太好**：没有升级理由
- **免费版做得太差**：用户试完就走了，还留下差评
- **不设用量上限**：一次异常就能把当月成本打穿

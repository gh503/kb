# 合同里必须写清什么

> **深度** 取舍 ｜ **类型** 边界 ｜ **链** 报价怎么给

## 结论

**范围、验收、付款、终止这四件事写清，其余都是锦上添花。**
合同不是为了打官司，是为了让双方在没有争议的情况下把事做完。

## 四件必写

| 条款 | 写什么 | 不写的后果 |
| --- | --- | --- |
| 范围 | 交付物清单 + 变更流程 | 无限加需求 |
| 验收 | 标准、期限、默示通过 | 验收无限拖 |
| 付款 | 节点、比例、逾期后果 | 尾款拖着 |
| 终止 | 谁可终止、怎么结算 | 想退出退不了 |

## 变更流程（最容易被忽略）

```text
任何范围变更：
1. 书面提出（邮件即可）
2. 说明对价格与工期的影响
3. 双方书面确认后才执行

默认规则：未确认的变更不做，或做但不视为已同意
```

**没有变更条款，合同签完就等于范围开放。**

## 默示验收

约定"交付后 N 个工作日内未提出书面异议，视为验收通过"。没有这一条，
客户可以永远"还在看"。

## 还有几条值得写

- **知识产权**：交付后归谁、能不能用于案例宣传
- **保密**：双方互负，期限多久
- **责任上限**：一般不超过合同金额（重大过失除外）
- **争议解决**：协商、调解、仲裁或诉讼，写清地点

## 数字与阈值（经验判断）

```text
默示验收期：5–10 个工作日
变更确认：书面，邮件可
责任上限：常为合同总额
```

## 证据强度

- **方法**：四类核心条款来自合同实务
- **建议值**：默示验收期来自经验
- **推断**："变更流程比条款细节更重要"是按争议来源推的

## 不适用的情况

- 极小金额（几百元）：合同成本高于收益，用订单+聊天记录即可
- 平台标准合同：条款不可改，只能选择接不接

## 常见错法

- **抄一份模板不改**：模板里的条款与你的交付方式不匹配
- **只签不存档**：变更散落在聊天记录里
- **不写终止**：合作不下去时没有退出路径

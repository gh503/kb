# 一个项目三个领导怎么定优先级

> **深度** 入门 ｜ **类型** 取舍 ｜ **链** 组织的摩擦

## 结论

**让三个领导当着彼此的面吵一次，比你在中间传十次话有用。** 多头汇报的核心问题不是你不够努力，
而是**没有人知道另外两个人的优先级是什么**——一旦放到同一张桌上，多数冲突当天就能收敛。

## 先分清三种"多头"

| 类型 | 表现 | 解法 |
| --- | --- | --- |
| 真多头 | 三个人都有资源决定权 | 定一个主责人 + 一次对齐会 |
| 假多头 | 一个人拍板，其余提意见 | 只需确认谁拍板 |
| 流程多头 | 各管一段（预算、技术、业务） | 画清分段边界 |

**第二种最常见，也最好解决**：多数争议来自"以为对方能决定"。

## 一次对齐会怎么开

```text
参会：三个领导 + 你（不要更多）
时长：45 分钟
议程：
  1. 我念一遍当前排期与三条冲突（5 分钟，不许打断）
  2. 每人说一句"我最不能延的是什么"（各 5 分钟）
  3. 当场定：本月哪两件事做、哪一件停（20 分钟）
  4. 记录：谁同意的、什么时候复审

结束条件：有一份写着日期的结论。没有结论 = 会白开。
```

## 会后要做的两件事

1. **把结论发给三个人**：同一份文字，不做"分别告知"（分别告知 = 制造理解偏差）
2. **下一次冲突时引用它**：\"按 3 月 5 日定的顺序，这件事排第二\"

第 2 条决定这次对齐有没有长期效果。

## 数字与阈值（经验判断）

```text
对齐会：45–60 分钟，超过就容易变成抱怨会
参会人数：≤ 4 人，多一个就多一倍跑题
复审节奏：每月一次，或里程碑变化时
无结论比例：一次会开完仍没定，说明缺的是层级，不是沟通
```

## 证据强度

- **公开经验**：多头汇报导致的优先级冲突是矩阵组织的常见问题
- **区间**：会议时长与人数来自经验
- **推断**："当面吵比中间传话有效"基于信息损耗判断，未实测

## 不适用的情况

- 强矩阵组织且上级之间本身有矛盾：需要更上一级裁定，不是你能解决的
- 紧急事故：先处置，事后补对齐

## 常见错法

- **分别汇报**：每个人都以为自己的事最重要
- **自己替领导排序**：你不是决策人，排错了责任在你
- **开会不记录**：下次同样的问题再吵一遍

# 交接清单要写什么

> **深度** 实操 ｜ **类型** 方法 ｜ **链** 事怎么交接

## 结论

**写"离开后会发生什么"，而不是"我做过什么"。** 前者是风险清单，后者是履历。
交接的目标不是让人知道你多忙，是让事情在你不在时不出事。

## 五类必写

| 类别 | 写什么 | 为什么 |
| --- | --- | --- |
| 在跑的事 | 每件事的当前状态、下一步、截止日 | 避免断在半路 |
| 有期限的 | 到期日、逾期后果 | 时间是唯一不能补的东西 |
| 权限与账号 | 谁有权限、怎么申请、密码托管在哪 | 没权限就动不了 |
| 卡着的事 | 卡在谁、卡了多久 | 不写就会被遗忘 |
| 联系人 | 外部对接人、内部决策人 | 关系不能继承，只能转交 |

## 格式建议

```text
事项：一句话
状态：进行中 / 等外部 / 已停
下一步：谁、做什么、什么时候
风险：如果不做会怎样
```

**"风险"那一行是清单的价值所在。** 没有它，清单只是流水账。

## 交接的三个时点

1. **提前一周**：发清单，让对方来问（而不是你讲）
2. **交接当天**：一起过一遍"有期限的"和"卡着的事"
3. **交接后一周**：主动问一次"有没有卡住"

第 3 步最容易被跳过，也最能暴露清单的漏洞。

## 数字与阈值

```text
清单长度：单页到两页，超过说明没提炼
"有期限的"事项：必须逐条核对日期
交接后一周内的问题数：> 5 个说明清单不合格
```

## 证据强度

- **方法**：风险导向的交接清单是运维与项目管理里的通用做法
- **建议值**：长度与问题数来自经验
- **推断**："让对方来问"基于主动回忆优于被动听讲的常识

## 不适用的情况

- 临时请假 1–2 天：写"三件最重要的事"就够
- 岗位取消（业务关停）：重点转为数据归档与客户告知

## 常见错法

- **只写做了什么**：接手人不知道下一步
- **口头交接**：说完就忘，且无法核对
- **不交出权限**：交接了但动不了，等于没交接

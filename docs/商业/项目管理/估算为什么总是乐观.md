# 估算为什么总是乐观

> **深度** 入门 ｜ **类型** 误区 ｜ **链** 为什么总会延期

## 结论

因为**你估的是"顺利情况"，不是"平均情况"**。人做估算时默认一切按计划走，
而现实里总有返工、等待、插队——这不是能力问题，是估算方式的系统偏差。

## 三种偏差

| 偏差 | 机制 | 表现 |
| --- | --- | --- |
| 规划谬误 | 只想象顺利路径 | 估 3 天，实际 8 天 |
| 锚定 | 先说的数难改 | 领导说两周，就按两周排 |
| 忽略等待 | 只算动手时间 | 等接口、等审批没算进去 |

## 一个可用的做法：参考类预测

```text
1. 找 5 件"同类、同规模"的旧任务
2. 看它们实际花了多久
3. 用中位数或 75 分位，而不是你现在的直觉
4. 明确写出：估算的 50% 概率值与 90% 概率值
```

没有历史数据时，用**结构化拆分**：把任务拆到半天以内，再逐项估，
最后加上"等待与返工"一项（经验上占 20%–30%）。

## 数字与阈值

```text
个人任务：实际常是直觉估计的 1.5–2 倍
含外部依赖的任务：再加 20%–30% 的等待
缓冲：给出区间（如 5–8 天），不给单点
```

## 证据强度

- **公开研究**：规划谬误是决策心理学里较稳定的发现
- **经验区间**："乘以 1.5–2"是工程与项目管理的常见经验值，不同任务差异大
- **推断**：等待占 20%–30% 是经验估计，未在我自己的项目上系统测过

## 已知的薄弱处

**"乘以 1.5–2"不能用在探索性任务上。** 探索的产出本身不确定，
乘一个系数只会得到一个看起来精确的假数字。探索该给时间盒（"花 3 天看能做到哪一步"），
不是估完成时间。

**能推翻它的证据**：同一类任务里，你的实际耗时稳定在直觉的 1.1 倍以内——
说明你的直觉已经校准，此时再乘 1.5 反而是浪费。

## 不适用的情况

- 真正重复过很多次的任务：已经有了参考类，直觉反而更准
- 探索性任务：应该给时间盒，而不是估"完成时间"

## 常见错法

- **被砍缓冲就砍质量**：缓冲被压掉时，先减范围而不是减测试
- **用最好员工的速度当团队速度**：估算要按执行者算
- **不记录实际耗时**：没有数据，下次还会乐观

# 供应商延期怎么办

> **深度** 取舍 ｜ **类型** 边界 ｜ **链** 优先级怎么排

## 结论

**先判断它是不是关键路径，再决定投入多少。** 不在关键路径上的延期，改计划就行；
在关键路径上的，只有三种解法：加缓冲、换方案、改承诺——**催是最没用的那种**。

## 三个动作按顺序

| 顺序 | 动作 | 适用 |
| --- | --- | --- |
| 1 | 确认是否在关键路径 | 不在：调整顺序，不动交付 |
| 2 | 要一个可信的新日期 | 在：让对方给出依据，而不是"尽快" |
| 3 | 选解法 | 加缓冲 / 并行备用方案 / 改对外承诺 |

## 问供应商的四句话

```text
1. 现在卡在哪一步？（要具体到环节，不是"在推进"）
2. 是新问题还是老问题？（老问题说明能力或意愿有问题）
3. 你需要在你这儿解决，还是在我这儿解决？
4. 如果明天还不能动，最早什么时候能给？
```

第 3 句最重要：**很多"供应商延期"其实是自己这边没给齐东西。**

## 合同层面能提前做的

- 付款与里程碑绑定，不按时间付
- 写清延期的后果（违约金、替换权）
- 保留备选供应商，哪怕不用
- 关键交付要求提供"中间可见物"（每周一次进度物）

## 数字与阈值（经验判断）

```text
关键路径缓冲：预留总工期的 15%–25%
供应商"尽快"：通常等于"至少一周后"
连续两次延期：启动备选方案，不再等
```

## 证据强度

- **公开经验**：关键路径与缓冲管理是项目管理通用做法
- **区间**：15%–25% 缓冲与"两次延期"规则来自经验，非实测
- **推断**："催最没用"基于激励结构：催促不改变对方的能力与优先级

## 不适用的情况

- 唯一供应商且不可替换：只能谈条件（分期、部分交付、共同承担）
- 已进入验收阶段：重点转为"按标准判合格与否"，而不是进度

## 常见错法

- **只催不换**：把管理动作当成解决方案
- **一次性压全部缓冲**：后面没有余量应对自己的问题
- **不写中间可见物**：等到截止日才知道延了

# 复盘为什么常常没用

> **深度** 取舍 ｜ **类型** 误区 ｜ **链** 为什么总会延期

## 结论

因为复盘常变成**追责会**或**感想会**，最后产出的是"下次注意"。
有用的复盘只做一件事：**改一条可执行的动作**，并指定谁在什么时候做完。

## 三种无效复盘

| 类型 | 表现 | 结果 |
| --- | --- | --- |
| 追责型 | 找谁的错 | 下次没人说真话 |
| 感想型 | "沟通要加强" | 没有可执行动作 |
| 清单型 | 列 20 条改进 | 一条都没落地 |

## 一个能落地的格式

```text
事实：发生了什么（只写可核对的，不写评价）
原因：为什么会这样（区分"直接原因"与"条件"）
动作：改哪一条流程/清单/阈值
责任与时间：谁、什么时候、怎么验证
```

规则：**一次只改一条**。改三条等于没改，因为没人记得住，
也无法判断是哪条起了作用。

## 数字与阈值（经验建议）

```text
复盘会时长：45 分钟内
改进项：1–2 条，超过 3 条基本不会执行
验证点：下一个项目/下一个迭代结束时回看
```

## 证据强度

- **公开经验**：复盘流于形式是普遍的团队问题
- **建议值**：时长与条数来自经验，没有对照实验
- **推断**："一次只改一条"基于注意力与执行力的常识

## 不适用的情况

- 重大事故：需要完整时间线与多方参与，不能压缩到 45 分钟
- 一次性项目：没有下一次，改动作没意义，只做记录

## 常见错法

- **用"态度问题"归因**：态度无法改，流程可以
- **只复盘失败**：成功的项目也值得看"哪一步侥幸"
- **没有验证**：改完不回头看，等于没改

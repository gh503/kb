# 文档写了没人看怎么办

> **深度** 取舍 ｜ **类型** 边界 ｜ **链** 组织的摩擦

## 结论

**多数文档没人看，不是写得不好，是"看它不能解决当下的事"。** 文档要挂在动作上：
决策前要读、交接时要交、出事时要查——挂在动作上才有人看。

## 三种文档，三种活法

| 类型 | 谁看 | 怎么保证被看 |
| --- | --- | --- |
| 决策记录 | 三个月后的自己 | 挂在决定旁边，改方案时强制读 |
| 操作手册 | 新人 | 入职第一周必须照做一遍 |
| 会议结论 | 参会人 | 当天发出，附"下一步" |

**"知识库"式的文档最容易死**：谁都不需要它，于是谁都不看。

## 让它被看的三招

1. **挂在必经路径上**：提交代码、发起变更、交接工作，都必须引用某份文档
2. **短**：一页能说完的不要写三页
3. **过期就删**：留着过时文档，比没有更糟——它会让人不再信任文档

第 3 条最难，也最重要。

## 一个判断

```text
写完一个月，有没有人主动打开过？
没有 → 它不解决任何人的当下问题，删了或改挂到动作上
有 → 看的是哪一段？把那段提前，其余压缩
```

## 数字与阈值（经验判断）

```text
单页字数：决策记录 300–600 字，操作手册按步骤
更新频率：文档与代码/流程的偏差超过 1 个月，视为过期
维护成本：一份没人看的文档，每年消耗的维护时间远超它的价值
```

## 证据强度

- **公开经验**："文档要挂在工作流上"是知识管理的常见结论
- **推断**："过期文档比没有更糟"基于信任损耗判断
- **未验证**：具体字数阈值因团队而异

## 不适用的情况

- 合规/审计要求：必须留存，即使没人读
- 探索性项目的笔记：本来就是给自己看的，不必强求他人阅读

## 常见错法

- **追求覆盖率**：什么都写，结果没人信
- **建大而全的知识库**：三个月后全是过时内容
- **只写不删**：文档越多，查找越难

# 谁该拍板：决策权怎么分

> **深度** 实操 ｜ **类型** 方法 ｜ **链** 组织的摩擦

## 结论

**每个决定只有一个名字。** 不写名字，就等于默认"谁都可以否决"——
而"谁都可以否决"的结果是没人推进。

## 一张决策表就够

| 决定类型 | 谁拍板 | 谁必须被问 | 谁只需被告知 |
| --- | --- | --- | --- |
| 范围增减 | 产品负责人 | 技术、业务 | 全员 |
| 排期调整 | 项目经理 | 需求方 | 相关团队 |
| 技术方案 | 技术负责人 | 项目经理 | 业务 |
| 预算超支 | 部门负责人 | 财务 | 项目组 |

三列的含义不同：**拍板是一个人，被问是提供输入，被告知是知情权。**
混在一起，就会变成"人人有责、无人负责"。

## 决策的三种边界

```text
1. 可以自己定：影响范围小、可逆
2. 必须问一句：影响他人排期、成本超阈值
3. 必须上报：不可逆、涉及对外承诺

把这三条写进团队约定，比每次都问"这个我能定吗"快得多。
```

## 升级路径要事先说清

**没有升级路径，冲突就会变成拖延。** 约定：超过 N 天没定，自动升级给上一级；
不用等到"吵起来"才找人。

## 数字与阈值（经验判断）

```text
升级线：超过 3 个工作日未决 → 升级
决策记录：一次决定 4–8 行（定什么、为什么、谁定、何时复审）
可逆/不可逆：不可逆的决定，参与人至少多一个
```

## 证据强度

- **方法**：单一负责人与决策权限表来自管理实践（如 RACI 的简化用法）
- **推断**："谁都可以否决等于没人推进"是按否决权结构推的
- **未验证**：具体升级天数在不同组织差别很大

## 不适用的情况

- 高度共识型小团队（3–5 人）：写表反而增加形式
- 强监管决策（安全、合规）：必须走流程，不能个人拍板

## 常见错法

- **一张表列五个"负责人"**：等于没有负责人
- **只写拍板不写被告知**：被跳过的人会在执行阶段反弹
- **升级被当成告状**：要把升级写成流程，不是冲突

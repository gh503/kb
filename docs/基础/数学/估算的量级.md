## 结论

**估算的目标是"对到 2–3 倍以内"，不是精确。**
本机实测：`sha256` 算 100 MB 用 **434 ms（231 MB/s）**，而常见估算写 500 MB/s——**差 2.2 倍**；
1e7 次 Python 整数加法 **1339 ms（7 Mops/s）**，比"每秒上亿次"的直觉慢一个数量级。

## 估算的三步

```text
1. 拆成可估的乘法：数据量 × 每字节成本
2. 每一项都用"上下界"而不是点值
3. 算出结果后回代一次：与已知量对比（1 GB 内存拷贝约 0.1–0.3 s）
```

**"说不出量级"** 通常在第一步卡住：不知道该乘什么。

## 本机可复现（已实测）

```bash
python3 - <<'PY'
import hashlib, time
b=b"x"*(100<<20); t=time.perf_counter(); hashlib.sha256(b).digest()
print(f"sha256 100 MB：{(time.perf_counter()-t)*1000:.0f} ms")
t=time.perf_counter(); s=0
for i in range(10_000_000): s+=i
print(f"1e7 次加法：{(time.perf_counter()-t)*1000:.0f} ms")
PY
```

本机输出：

```text
sha256 100 MB：434 ms → 231 MB/s
1e7 次整数加法：1339 ms → 7 Mops/s（Python 循环）
```

## 常见量的参考区间

```text
内存随机访问：~100 ns；顺序读：~10 GB/s 量级
SSD 顺序读：0.5–3 GB/s；HDD：100–200 MB/s
同机房 RTT：0.1–1 ms；跨洲：150–300 ms
sha256：单核数百 MB/s（本机 231 MB/s）
Python 循环：每秒千万级；C 循环：每秒十亿级
```

**"差一个数量级"** 是估算的常态：2–10 倍都可接受，100 倍说明模型错了。

## 什么时候必须实测

```text
影响决策的量（要不要加机器、要不要换存储）→ 实测
只是排除方案的量（明显差 100 倍）→ 估算够
经验值来源不明的（"一般认为 500 MB/s"）→ 实测
```

**"估算 500、实测 231"** 差 2 倍不影响"要不要上缓存"的决定，但会影响容量规划。

## 数字与阈值（本机实测）

```text
sha256 100 MB：434 ms（231 MB/s），估算值 500 MB/s 偏高 2.2 倍
1e7 次 Python 加法：1339 ms（7 Mops/s）
经验：估算误差 2–3 倍内可用；超过 10 倍要回头查模型
经验：决策相关的数一律实测，参考值只用来排除
经验：写下估算的每一步，方便事后定位错在哪一项
```

## 证据强度

- **实测**：两个速度来自本机
- **公开经验**：常见量级区间
- **推断**：不同机器差异可达 3–10 倍，跨机器外推要打折扣

## 不适用的情况

- 需要精确容量规划：估算只能定范围，最终要压测
- 安全相关阈值（限速、锁定期）：必须实测与压测

## 常见错法

- **用别人机器上的基准数**
- **把"每秒上亿次"套到解释型语言**
- **估完不回代**，量级错了也不知道

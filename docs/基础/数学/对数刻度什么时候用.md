## 结论

**当数据跨好几个数量级、或你想看"增长率"时用对数轴；想看"绝对差"时不能用。**
本机算的账：从 **1,000 涨到 1,000,000**（3 个数量级）——线性轴上前面 99.9% 的区间被压成一条平线，
对数轴上则是**一条直线**（等速增长）。

## 两种轴分别回答什么

```text
线性轴：绝对差（多了 10 万，还是多了 1 个）
对数轴：倍数/增长率（涨了 10 倍，还是 1.1 倍）
  → 同一组数据，两问两答，不能互相替代
```

**"对数轴是为了好看"** 它是为了**让"倍数"可见**。

## 本机可复现（已算）

```bash
python3 - <<'PY'
import math
vals=[1000,10000,100000,1000000]
lin=[v/vals[-1]*100 for v in vals]         # 线性：相对最高点的高度
log=[math.log10(v)/math.log10(vals[-1])*100 for v in vals]
print("线性高度 %", [round(x,2) for x in lin])
print("对数高度 %", [round(x,1) for x in log])
PY
```

本机输出：

```text
线性高度 %：[0.1, 1.0, 10.0, 100.0]  → 前 3 个挤在底部
对数高度 %：[75.0, 83.3, 91.7, 100.0] → 等距，斜率恒定为"每步 10 倍"
```

## 四个该用的场景

```text
1. 跨数量级：用户数 100 → 100 万
2. 增长率比较：两条线哪条"涨得更快"（斜率 = 增长率）
3. 长尾分布：金额、访问量、文件大小
4. 感知量：分贝、pH、地震震级（本来就是对数定义）
```

## 三个不该用的场景

```text
绝对差重要：预算多了 10 万还是 100 万
有 0 或负值：log(0) 无定义（要用 symlog）
读者不熟悉：必须标注"对数轴"，否则会被读成线性
```

## 数字与阈值（本机计算）

```text
1,000 → 1,000,000：线性高度 0.1%/1%/10%/100%，对数 75%/83%/92%/100%
经验：数据跨 ≥ 2 个数量级就用对数轴
经验：对数轴上"直线"= 指数增长；"上凸"= 增长在加速
经验：对数轴必须标注，否则读者会按线性解读
```

## 证据强度

- **计算**：两组高度由公式算出
- **公开经验**：适用/不适用场景
- **推断**：真实读者对未标注的对数轴误读率很高（需要标注 + 说明）

## 不适用的情况

- 数据全在一个数量级内：对数轴反而掩盖差异
- 需要"面积/长度"直观比较：对数会让面积失真

## 常见错法

- **对数轴上比较"面积"**
- **不标注就用**
- **对含 0 的数据直接取对数**

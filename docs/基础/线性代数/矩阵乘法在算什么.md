## 结论

**矩阵乘法就是"每个输出元素 = 一行 × 一列"的内积，代价是 2n³ 次浮点运算。**
n=512 时约 **2.7 亿次**乘加——这个量级决定了它必然要做缓存优化。

## 定义展开

```text
C[i][j] = Σ_k A[i][k] · B[k][j]
```

三层循环，最内层是"乘加"。**顺序可以换（i,j,k 六种排列），结果不变，速度差几倍**——这就是下一节的主题。

## 代价怎么估

```text
每个 C 元素：n 次乘 + n 次加 = 2n 次浮点运算
C 有 n² 个元素 → 2n³ 次
n=256 → 3.4e7；n=512 → 2.7e8；n=1024 → 2.1e9
```

**"2n³"是硬下限**（朴素算法），Strassen 能降到约 n^2.8，但常数大、数值稳定性差，工程上很少用。

## 本机可复现（已实测）

```c
/* mm.c：同一对矩阵，三种循环顺序 */
for(i) for(j){ s=0; for(k) s+=A[i][k]*B[k][j]; C[i][j]=s; }   /* ijk */
for(i) for(k){ a=A[i][k]; for(j) C[i][j]+=a*B[k][j]; }         /* ikj */
```

本机输出（gcc 11.4.0 `-O2 -march=native`，i5-7300HQ）：

```text
n=256  ijk 36.6 ms | ikj 19.1 ms | 分块64 14.6 ms | 分块256 10.9 ms
n=512  ijk 331.3 ms | ikj 115.7 ms | 分块64 95.5 ms | 分块256 99.9 ms
```

**同一份数据、同样的结果，最慢与最快差 3.4 倍**（n=256）。

## 为什么顺序会影响结果（但结果不变）

```text
A[i][k] 是行访问，B[k][j] 是行访问
ijk：内层 k 变，B[k][j] 每次跳一整行 → 缓存不友好
ikj：内层 j 变，B[k][j] 连续 → 缓存友好
```

**"内层循环要走连续内存"** 是这一节唯一要记住的规则。

## 数字与阈值（本机实测 + 公式）

```text
浮点运算次数 2n³：n=256 3.4e7，n=512 2.7e8
n=256：ijk 36.6 / ikj 19.1 / 分块64 14.6 / 分块256 10.9 ms
n=512：ijk 331.3 / ikj 115.7 / 分块64 95.5 ms
本机 L3 6 MB，缓存行 64 B
```

## 证据强度

- **实测**：四组耗时为本机 C 程序输出
- **公式**：2n³ 的运算次数
- **公开经验**：缓存行 64 B、内层连续访问的原则

## 不适用的情况

- 稀疏矩阵：不该用稠密乘法，2n³ 完全不适用
- 小矩阵（n<32）：循环开销比缓存效应更显著

## 常见错法

- **以为"数学等价就性能等价"**
- **用 Python 三层循环做矩阵乘法**（见下一节，慢 600 倍）
- **忽略矩阵是行优先还是列优先存储**

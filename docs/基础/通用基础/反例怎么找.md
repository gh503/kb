## 结论

**写不出反例的判断，多半不是判断。**
本站实测：全站 813 篇里 **47%（383 篇）**写了「不适用的情况」；只看四域（工程/网络/基础/智能）是 **89%（250/280）**。
差距说明：**模板不是难点，想不想承认边界才是**。

## 反例有三种，别只找一种

```text
1. 直接反例：存在一个 A 不满足 B（最强）
2. 边界反例：在极端参数下失效（最常见）
3. 代价反例：结论仍成立，但代价大到没人用（最容易忽略）
```

**"这个方法更快"** 的代价反例是"快 10%，但要多维护一套系统"。

## 本机可复现（已实测）

```bash
python3 - <<'PY'
import pathlib
pages=[p for p in pathlib.Path('docs').rglob('*.md') if '订阅' not in str(p) and '关于' not in str(p)]
both=sum(1 for p in pages if '## 不适用的情况' in p.read_text(encoding='utf-8') and '## 常见错法' in p.read_text(encoding='utf-8'))
print(both, len(pages))
PY
```

本机输出：

```text
全站：383 / 813（47%）
四域（工程/网络/基础/智能）：250 / 280（89%）
常见错法条数：中位 3 条（最少 2、最多 4）
```

## 三种找法，按成本排

```text
1. 极端取值：参数取 0、取最大、取负数、取空值
2. 换环境：换机器、换网络、换数据规模
3. 换视角：让"被这个方法影响的人"来挑（运维、客服、新人）
```

**"想不到反例"** 常常是因为只在原环境里想。

## 找到反例之后

```text
1. 写进「不适用的情况」，一条一句
2. 如果反例很常见，把结论改成有条件的（"在 X 下成立"）
3. 如果反例罕见但致命，加进「常见错法」
```

**"加了边界反而显得不自信"** 恰恰相反：写了边界的结论才有人敢用。

## 数字与阈值（本机实测）

```text
全站模板完整率 47%（383/813）｜四域 89%（250/280）
常见错法中位 3 条
经验：每条结论至少 1 个「不适用」条目
经验：反例优先取"极端参数 + 换环境"两类
经验：代价反例最容易被漏，专门问一句"如果它成立，谁要付代价"
```

## 证据强度

- **实测**：两个完整率与条数来自本站扫描
- **公开经验**：反例三分类、极端取值法
- **推断**：47% 与 89% 的差距主要来自早期批次没有强制模板

## 不适用的情况

- 定义性陈述（"三角形有三条边"）：反例不存在，也不需要
- 操作步骤：边界写在步骤里，不必单列

## 常见错法

- **只写"一般情况下"，不写具体边界**
- **反例写成"某些场景"**，等于没写
- **把反例当免责声明**，结论里不做任何修正

## 结论

**先说结论，再说依据，最后说不确定性。** 顺序反了，听的人要自己拼答案。
而**不确定性必须说**——不说，等于把判断包装成事实。

## 四段结构

```text
1. 结论：一句话，可执行或有明确指向
2. 依据：2–4 条，每条可核对
3. 不确定性：哪里可能错、错到什么程度
4. 下一步：需要谁做什么决定
```

**"不确定性"这一段是可信度的来源**：全称肯定的表达，反而让人怀疑。

## 结论要写成什么样

| 差 | 好 |
| --- | --- |
| 建议优化一下 | 建议把 A 换成 B，预计 P99 从 2s 降到 500ms |
| 可能有问题 | 在 1000 并发下会超时，当前上限约 600 |
| 需要进一步调研 | 需要确认 X，若 X 成立则走方案 B，否则走 A |

**"若 X 则 A，否则 B"** 是最有用的表达：它让听的人知道该决定什么。

## 不确定性的三种说法

```text
证据不足：目前只有 3 个样本，不能外推
条件未验证：假设了 QPS 不变，若翻倍结论会变
范围限制：这个结论只适用于室内场景
```

**具体说"哪里不确定"**，比笼统说"仅供参考"有用。

## 长度与颗粒度

```text
口头/消息：结论 1 句 + 依据 2 条
文档：结论 1 段 + 依据分条 + 不确定性 1 段
汇报：先给结论页，细节放附录
```

**"结论页 + 附录"是最省时间的结构**：忙的人只看第一页。

## 数字与阈值（经验判断）

```text
结论长度：1–3 句
依据条数：2–4 条（超过说明没提炼）
不确定性：至少 1 条
汇报材料：结论在前 1 屏
给决策者的版本：≤ 1 页
```

## 证据强度

- **公开经验**：结论先行、依据可核对、标明不确定性
- **方法**：四段结构属可操作框架
- **推断**："不说不确定性等于包装成事实"按表达效果推的

## 不适用的情况

- 探索性讨论：先发散，结论后置
- 需要铺垫情绪的场合（坏消息）：可先给背景，但结论仍要早出现

## 常见错法

- **按时间顺序讲过程**：听的人不知道重点
- **只给结论不给依据**：无法判断可信度
- **全称肯定**：不留余地，错一次就失信

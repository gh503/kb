## 结论

**分类要满足两条：类与类不重叠（互斥），所有情况都有着落（穷尽）。**
缺互斥 → 同一件事被算两次；缺穷尽 → 有些情况无处安放，只能塞进"其他"。

## 两条判据

```text
互斥（MECE 的 ME）：任一成员最多属于一个类
穷尽（MECE 的 CE）：任一成员至少属于一个类
```

**合起来才叫 MECE**：不重不漏。

## 一个反例

```text
分类：新用户 / 老用户 / 活跃用户 / 付费用户
问题：一个"付费的老用户"同时属于 3 类 → 不互斥
      "注册但从未登录"的用户不属任何一类 → 不穷尽
```

**改成按一个维度切**：

```text
按活跃度：7 日内登录 / 30 日内登录 / 超过 30 日未登录
（互斥且穷尽，因为以"最后一次登录距今天数"为唯一依据）
```

**"按一个维度切"是做到 MECE 的最快办法。**

## 一个能算的检查

```text
各类占比之和 = 100%？
  = 100% → 可能互斥且穷尽
  > 100% → 有重叠（不互斥）
  < 100% → 有遗漏（不穷尽）
```

**"加起来超过 100%"是重叠最直接的证据**，在报表里很常见。

## 什么时候不需要 MECE

```text
多标签场景（一篇文章多个主题）
探索性分析（先发散再收敛）
按不同维度分别统计（活跃 + 付费，本来就是两个维度）
```

**"同一维度内 MECE"就够**：不同维度交叉是正常的。

## 分类数量

```text
3–7 类最易用（人一次能记住的范围）
超过 7 类：考虑分两层
"其他"占比 > 10%：说明分类没穷尽，或需要新增一类
```

**"'其他'是分类质量的温度计"**：它越大，说明你的分类越不合用。

## 数字与阈值（经验判断）

```text
占比和：应 = 100%（±1% 因四舍五入）
类别数：3–7；超过 9 考虑分层
"其他"占比：≤ 10% 可接受
检查频率：分类用于决策前必查
```

## 证据强度

- **公开经验**：MECE 的两条判据、按单一维度切、占比和检查
- **公式**：占比之和 = 100% 是逻辑推论，可直接验证
- **推断**："3–7 类易用"按短期记忆容量推的

## 不适用的情况

- 多标签/多维度分析：不需要单维 MECE
- 层级分类：每层内 MECE 即可，不必全局

## 常见错法

- **把多个维度混进同一层**：必然重叠
- **用"其他"兜底但不检查占比**
- **互斥了但没穷尽**：漏掉的情况无人负责

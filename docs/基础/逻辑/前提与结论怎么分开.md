# 前提与结论怎么分开

> **深度** 入门 ｜ **类型** 方法 ｜ **链** 论证哪里断了

## 结论

**先把一段话拆成"主张什么"和"凭什么"，再检查两者之间有没有桥。**
大多数争论不是结论对立，而是**各自默认了对方没说出口的前提**。

## 三件套

```text
前提：用来支持结论的事实/假设
结论：作者想让你接受的判断
隐含前提：没写出来、但论证必须依赖的那一句
```

**"隐含前提"是 90% 分歧的所在**：它没被说出来，所以没人检查。

## 一个拆解示例

```text
原文：这个方案上线太慢了，我们应该换掉它。
结论：应该换掉这个方案
明面前提：上线太慢
隐含前提：上线速度比其它因素（成本、稳定性、迁移代价）更重要
```

**拆出隐含前提后，争论点就清楚了**：到底该不该把"上线速度"排第一。

## 识别结论的四个信号

```text
因此 / 所以 / 可见 / 说明 → 后面通常是结论
应该 / 必须 / 建议 → 规范性结论
"我认为""我的判断是" → 显式标记
```

**没有这些词时，看"哪句需要别的句子支撑"**：需要支撑的是结论。

## 三种常见结构

| 结构 | 形态 | 检查点 |
| --- | --- | --- |
| 单前提 | A，所以 B | A 是否为真、A→B 是否成立 |
| 多前提 | A 且 B，所以 C | 前提是否齐全、是否互相冲突 |
| 链式 | A→B，B→C，所以 C | 每一环是否都成立 |

**"链式"最容易断**：中间某一环弱，整条链就弱，但表面上读起来很顺。

## 一个自检

```text
把结论遮住，只看前提：这些前提能推出那句话吗？
把前提遮住，只看结论：它需要什么才能成立？
```

**两个方向都问一遍**，能发现"前提不足"与"结论过大"。

## 数字与阈值（经验判断）

```text
前提数：2–4 条（超过通常有重复或可合并）
隐含前提：至少找出 1 条
链长：超过 3 环时，逐环标注可信度
```

## 证据强度

- **公开经验**：前提/结论/隐含前提的三件套、结论标识词
- **方法**：拆解步骤属可操作框架，非实证结论
- **推断**："隐含前提是分歧所在"按论证结构推的

## 不适用的情况

- 纯叙事/描写：没有论证结构
- 数学证明：前提显式，不需要"找隐含前提"

## 常见错法

- **把例子当结论**：例子只支持，不证明
- **把重复当论证**：换个说法说同一件事
- **攻击前提的真假却不管推理**：可能推理本身就不成立

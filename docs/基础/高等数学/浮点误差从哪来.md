## 结论

**浮点只有约 16 位有效数字，两个来源：表示误差（0.1 存不准）与相消误差（大数相减）。**
本机实测：`0.1+0.2 != 0.3`；`(1e16+1)-1e16 = 0`；`sqrt(1e16+1)-1e8 = 0`（真值 5e-9）。

## 三个典型现象

| 现象 | 本机结果 | 原因 |
| --- | --- | --- |
| `0.1+0.2` | `0.30000000000000004` | 0.1 无法用二进制精确表示 |
| `(1e16+1)-1e16` | `0.0` | 1 被大数"吃掉" |
| `sqrt(1e16+1)-1e8` | `0.0` | 相消（两个相近大数相减） |

**"相消"是最危险的一种**：相对误差被放大到无法使用。

## 本机可复现（已实测）

```python
print(0.1+0.2)                      # 0.30000000000000004
print((1e16+1)-1e16)                # 0.0
print(math.sqrt(1e16+1)-1e8)        # 0.0
print(1/(math.sqrt(1e16+1)+1e8))    # 5.00000000372529e-09
```

本机输出：

```text
0.1+0.2 = 0.30000000000000004  (== 0.3? False)
(1e16+1)-1e16 = 0.0  （应为 1）
sqrt(x²+1)-x 在 x=1e8: 0.000e+00  等价改写 1/(sqrt(x²+1)+x) = 5.000e-09
```

**最后一行是标准解法**：把"相减"改成"相加后取倒数"，灾难性相消消失。

## 求和顺序也会算错

```text
1 + 1e-16 + 1e-16 + …（100 万个 1e-16）
朴素累加：1（每个 1e-16 都被吃掉）
Kahan 补偿：1.0000000001（正确）
```

本机输出：

```text
朴素 1
Kahan 1.0000000001
精确 1.0000000001
```

**"1e6 个小量相加等于没加"** 在统计、金融累计里非常常见。

## 怎么防

```text
1. 避免相近大数相减（改写公式）
2. 累加大量小数用 Kahan/成对求和
3. 比较浮点用容差，不用 ==
4. 金额用整数分，不用 float
```

**"金额用整数"是最省心的**：把元换成"分"，整数运算没有表示误差。

## 数字与阈值（本机实测）

```text
双精度有效位约 15–16 位（ε≈2.2e-16）
0.1+0.2 = 0.30000000000000004
(1e16+1)-1e16 = 0
1e6 个 1e-16 朴素求和丢失全部
经验：判断相等用 |a-b| < 1e-9·max(1,|a|,|b|)
```

## 证据强度

- **实测**：四行输出为本机 Python 结果
- **公式**：双精度 ε=2.2e-16、相消放大 1/相对误差
- **公开经验**：Kahan 求和、金额用整数

## 不适用的情况

- 定点/整数运算：没有表示误差（但会溢出）
- 高精度库（decimal/mpfr）：可缓解，代价是慢

## 常见错法

- **用 `==` 比较浮点**
- **金额用 float 累加**
- **在公式里制造相近大数相减**

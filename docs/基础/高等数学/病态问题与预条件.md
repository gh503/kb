## 结论

**条件数决定"你能算到多准"，而预条件不是万能的。**
本机实测（100×100 对称正定、CG 迭代 200 步上限）：
**cond=1e2 时 101 步收敛、误差 1.9e−11；cond=1e8 时 200 步后误差仍有 4.99。**
而加上对角预条件（Jacobi）后，**这门构造矩阵反而更慢：453–500 步**。

## 条件数在说什么

```text
cond(A) = |λmax| / |λmin|
  → 输入相对误差被放大多少倍到输出的相对误差
cond=1e8、双精度（eps≈2.2e−16）→ 可用的有效位数只剩约 8 位
cond > 1e16 → 双精度已经分不清，解没有意义
```

**"算不出来"往往是问题本身病态，不是代码有 bug。**

## 本机可复现（已实测）

```bash
python3 - <<'PY'
import numpy as np, math
rng = np.random.default_rng(2)
def make_spd(n, cond):
    Q, _ = np.linalg.qr(np.random.default_rng(1).normal(size=(n, n)))
    d = np.logspace(0, math.log10(cond), n)
    return Q @ np.diag(d) @ Q.T
def cg(A, b, iters=200, tol=1e-10):
    x = np.zeros(len(b)); r = b - A@x; p = r.copy(); rs = r@r
    for k in range(iters):
        Ap = A@p; alpha = rs/(p@Ap); x += alpha*p; r -= alpha*Ap
        rs2 = r@r
        if math.sqrt(rs2) < tol: return x, k+1
        p = r + (rs2/rs)*p; rs = rs2
    return x, iters
def pcg(A, b, iters=500, tol=1e-10):
    x = np.zeros(len(b)); M = 1/np.diag(A); r = b - A@x; z = M*r
    p = z.copy(); rz = r@z
    for k in range(iters):
        Ap = A@p; alpha = rz/(p@Ap); x += alpha*p; r -= alpha*Ap
        if np.linalg.norm(r) < tol: return x, k+1
        z = M*r; rz2 = r@z; p = z + (rz2/rz)*p; rz = rz2
    return x, iters
for cond in (1e2, 1e4, 1e6, 1e8):
    A = make_spd(100, cond); b = A@np.ones(100)
    x, k = cg(A, b)
    _, k2 = pcg(A, b)
    print(f"cond={cond:.0e}: CG {k} 步（误差 {np.linalg.norm(x-np.ones(100)):.2e}）｜ Jacobi-PCG {k2} 步")
PY
```

本机输出：

```text
cond=1e2: CG 101 步（误差 1.89e-11）｜ Jacobi-PCG 200 步
cond=1e4: CG 200 步（误差 1.70e-03）｜ Jacobi-PCG 453 步
cond=1e6: CG 200 步（误差 2.06e+00）｜ Jacobi-PCG 500 步
cond=1e8: CG 200 步（误差 4.99e+00）｜ Jacobi-PCG 500 步
```

## 为什么预条件这次没用

```text
这对矩阵是 Q·diag(1…1e8)·Qᵀ 构造的，对角线元素已经被"抹平"
  → 取 1/diag(A) 做预条件，几乎等于乘一个常数
  → 不改变条件数，只增加每步开销
有效的预条件要"贴近 A 的结构"：不完全 Cholesky、多重网格、区域分解
```

**"预条件不是套公式"**：对角预条件只对"对角占优"的矩阵有用。

## 什么时候该换方法

```text
cond < 1e3：直接法（LU/Cholesky），一步到位
1e3–1e6：CG + 好预条件，或用 GMRES
> 1e6：先问"这个问题本身能不能改"（换基、正则化、加先验）
> 1e12：双精度基本到极限，考虑高精度或重述问题
```

**"正则化"** 常比"更好的求解器"更有效：给 AᵀA 加 λI 就是把条件数压下来。

## 数字与阈值（本机实测）

```text
cond=1e2 → CG 101 步，误差 1.9e−11
cond=1e4 → 200 步，误差 1.7e−3
cond=1e6 → 200 步，误差 2.06
cond=1e8 → 200 步，误差 4.99
Jacobi 预条件在这组构造矩阵上 453–500 步（更差）
经验：CG 的迭代步数约与 √cond 成正比
经验：cond > 1e12 时先怀疑建模，而不是求解器
```

## 证据强度

- **实测**：八组步数与误差来自本机 numpy
- **公开经验**：√cond 的迭代复杂度、正则化思路
- **推断**：预条件的有效性依赖矩阵来源，本机这组是人为构造的反例

## 不适用的情况

- 小规模、良态：直接解即可
- 稀疏且对角占优：Jacobi 往往有效（本机的反例不适用于这类矩阵）

## 常见错法

- **条件数很差还硬解，然后把噪声当结论**
- **以为"加预条件一定更快"**
- **用正常方程 AᵀA 解最小二乘**（条件数平方）

# 开发

> 把想法变成能跑的代码，并且让它别坏。

## 收什么

- 踩过的坑和修法，按"现象 → 原因 → 处理"写
- 能直接复制的工具链配置（装什么、改哪一行、怎么验证）
- 技术选型的取舍理由：当时有哪些选项、为什么选这个、代价是什么

## 不收什么

- 官方文档的复述——直接给链接
- 没有上下文的代码片段（贴了但不知道在什么项目里跑）

## 条目

还没有条目。第一条建议写**昨天真正卡住你十分钟的那件事**——不是"最佳实践"，是真实故障。

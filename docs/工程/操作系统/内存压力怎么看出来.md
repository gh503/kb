## 结论

**`free` 里的 `free` 列几乎没用，要看 `available` 和换出活动。**
本机实测：总量 **24.5 GB**，`MemAvailable` **18.6 GB（76%）**，`Cached` **14.3 GB**，
swap 24.0 GB 里已用 **3.6 GB**（`SwapFree` 20.4 GB）——**这台机器有内存压力，但不紧张**。

## 四个数，按重要性排

```text
MemAvailable：还能给新进程多少（最该看的）
Cached：被页缓存占着但可回收
SwapUsed 与其增速：被换出去的匿名页（增速比绝对值重要）
PSI memory some/full：有多少时间在等内存
```

**"free 只剩 1 GB"** 在 Cached 14 GB 的机器上是正常状态。

## 本机可复现（已实测）

```bash
grep -E 'MemTotal|MemAvailable|Cached|SwapTotal|SwapFree' /proc/meminfo
cat /proc/pressure/memory
```

本机输出：

```text
MemTotal 24,492,988 kB（24.5 GB）｜MemAvailable 18,636,732 kB（18.6 GB）
Cached 14,335,228 kB（14.3 GB）｜SwapTotal 24.0 GB、SwapFree 20.4 GB（已用 3.6 GB）
PSI memory：some avg300 = 0.13% ｜ full avg300 = 0.05%
```

## 判断"够不够"的三条线

```text
可用率 > 25%：宽松
可用率 10%–25%：紧但可用，开始看 swap 增速
可用率 < 10% 或 PSI memory full 持续 > 1%：已经在换页，性能会塌
```

**"swap 用了就是坏事"** 不成立：少量换出冷页是正常的；坏事是**持续换入换出**。

## 加内存还是省内存

```text
加内存：缓存命中率低、页缓存被频繁回收、PSI memory 持续高
省内存：单个进程 RSS 异常增长（先查泄漏）、缓存策略可调
换机器：内存带宽/通道数限制（这是另一类问题，看 NUMA 与带宽）
```

## 数字与阈值（本机实测）

```text
24.5 GB 总内存 ｜18.6 GB 可用（76%）｜14.3 GB 页缓存
swap 24.0 GB，已用 3.6 GB ｜ PSI memory some 0.13%、full 0.05%
经验：可用率 < 10% 或 PSI full > 1% 视为紧张
经验：swap 增速 > 10 MB/s 持续一分钟，要查是谁在涨
经验：RSS 增长要先排除"缓存型增长"（页缓存不算进程 RSS）
```

## 证据强度

- **实测**：五个数值来自本机 `/proc`
- **公开经验**：三条可用率线、swap 增速判据
- **推断**：容器里 `MemAvailable` 反映宿主，cgroup 限额要看 `memory.max`

## 不适用的情况

- 容器限额场景：要看 cgroup v2 的 `memory.current/max` 与 `memory.pressure`
- 实时系统：内存锁定（mlock）后可用内存不是可用性指标

## 常见错法

- **盯着 `free` 列报警**
- **把页缓存当泄漏**
- **swap 一有使用就重启服务**

## 结论

**`/proc/sys` 下有 1320 个可调项，而"调参"通常是在没有测量的情况下改其中一个。**
本机实测：共 **1320** 个可写参数；常用五个的现状是
`vm.swappiness=10`、`vm.dirty_ratio=20`、`vm.dirty_background_ratio=10`、`vm.overcommit_memory=0`、`net.core.somaxconn=4096`。

## 调参之前必须先有这三样

```text
1. 一个可复现的慢：什么命令、多慢、慢在哪一步
2. 一个对照：改之前的数据（不是"感觉快了"）
3. 一个能证伪的预期：这个参数应该让哪个指标变成多少
```

**"网上说 swappiness 调到 1 会快"** 是别人的机器、别人的负载。

## 本机可复现（已实测）

```bash
find /proc/sys -type f | wc -l          # 1320
sysctl vm.swappiness vm.dirty_ratio vm.dirty_background_ratio vm.overcommit_memory
```

本机输出：

```text
1320 个可调文件
vm.swappiness = 10 ｜ vm.dirty_ratio = 20 ｜ vm.dirty_background_ratio = 10
vm.overcommit_memory = 0 ｜ net.core.somaxconn = 4096
```

## 五个参数各自管什么

```text
swappiness：多愿意把匿名页换出（10 = 尽量不换）
dirty_ratio：脏页占内存多少时，写进程自己开始回写（20%）
dirty_background_ratio：多大时后台开始回写（10%）
overcommit_memory：0 = 启发式允许超额分配
somaxconn：listen backlog 上限（本机 4096）
```

**改 dirty_ratio 只会改变"什么时候卡"，不会让磁盘变快**——这是最常被误解的一条。

## 什么情况下值得调

```text
值得：明确的固定负载 + 可复现指标 + 参数与指标有直接机制关系
不值得：偶发变慢、不知道瓶颈在哪、改了没人复测
危险：同时改多个参数（出了问题无法归因）
```

## 数字与阈值（本机实测）

```text
1320 个可调参数 ｜ 常用五个：swappiness 10、dirty 20/10、overcommit 0、somaxconn 4096
经验：一次只改一个，并记录改动前后的同一指标
经验：写在 /etc/sysctl.d/ 里而不是临时 sysctl -w（重启就丢）
经验：改完必须能解释"为什么这个参数会影响这个指标"
```

## 证据强度

- **实测**：1320 与五个默认值来自本机
- **公开经验**：一次一个、写进配置、要有机制解释
- **推断**：真实负载的参数敏感性差别很大，同一条经验不能跨机型搬

## 不适用的情况

- 容器里：很多参数是宿主的，容器内改了不一定生效
- 云主机：部分参数被虚拟化层接管

## 常见错法

- **照着博客改一串参数**
- **用 `sysctl -w` 临时改，重启后"又变慢了"**
- **改了 dirty_ratio 就以为磁盘变快**

## 结论

**`write()` 返回成功，只说明数据进了页缓存（page cache），没进磁盘。**
本机实测：写 8 MB（2000 次 4 KB）只用 **8.91 ms**，速度 **920 MB/s**——这个数远超这块盘的真实写入能力。

## 一次写入的三站

```text
用户缓冲区  →  page cache（内核内存）  →  磁盘
   write() 返回在这里 ↑
```

**"返回"发生在第二站之前**：所以进程崩了数据还在（在 page cache 里），机器断电就没了。

## 本机可复现（已实测）

```c
/* io.c：三种写法各写 2000 × 4 KB = 8 MB */
write(fd, buf, 4096);                          /* ① 普通 buffered */
write(fd, buf, 4096); fdatasync(fd);           /* ② 每次落盘 */
/* ③ 打开时带 O_DIRECT，绕过 page cache */
```

本机输出（gcc 11.4.0，/tmp 在 /dev/sda3 上）：

```text
buffered write   2000×4KB    8.91 ms  ( 919.7 MB/s)
write+fdatasync  2000×4KB 14820.18 ms  (   0.6 MB/s)
O_DIRECT write   2000×4KB   117.57 ms  (  69.7 MB/s)
```

**三个数差三个数量级，原因只有一个：数据到没到磁盘。**

## 为什么 buffered 能到 920 MB/s

```text
write 只做内存拷贝（用户态 → 页缓存）
真正的落盘由内核线程（writeback）异步做
所以快的是"拷贝"，不是"磁盘"
```

**"920 MB/s"不是磁盘速度**：这台机器的 O_DIRECT 只有 69.7 MB/s，那才接近真实写入能力。

## 页缓存什么时候被刷下去

```text
脏页超过 dirty_ratio（本机 20%）→ 强制回写
脏页在内存里待太久（dirty_expire）→ 后台回写
调用 fsync/fdatasync → 立即回写并等完成
内存压力大 → 回收时回写
```

**"写完不 fsync 也不丢"只在下一次回写之前成立**。

## 数字与阈值（本机实测）

```text
buffered 8 MB        8.91 ms（919.7 MB/s）
每次 fdatasync       14820.18 ms（0.6 MB/s）→ 平均每次 7.41 ms
O_DIRECT 8 MB        117.57 ms（69.7 MB/s）
dirty_ratio          20（本机）
```

## 证据强度

- **实测**：三行速度均为本机 `io.c` 输出，文件系统 `/dev/sda3`
- **公开经验**：page cache 语义、writeback 触发条件
- **推断**："920 MB/s 是内存拷贝速度"由与 O_DIRECT 的对比推的

## 不适用的情况

- 数据库要求持久性：必须 fsync 或用 O_DIRECT + 自己的日志
- 网络文件系统（NFS）：`write` 语义与本地不同，可能同步落盘

## 常见错法

- **以为 write 成功 = 数据安全**
- **用 buffered 写入速度评估磁盘**
- **在需要持久化的场景省掉 fsync**

## 结论

**进程只有两个来源：`fork` 复制一个，或者 `fork` + `exec` 换一个程序。**
本机实测：复制一个进程 **357 µs**，复制再换成另一个程序 **1,600 µs**，而创建一个线程只要 **131 µs**。

## 三个原语

```text
fork()   复制当前进程（几乎不复制内存，靠写时复制）
exec()   用新程序替换当前进程的代码与数据
wait()   回收子进程的退出状态（不调用就留僵尸）
```

**"fork 不复制内存"是关键**：它只复制页表，父子共享物理页，谁写谁触发复制。

## 本机可复现（已实测）

```c
/* bench.c：分别测 fork+wait、fork+exec、pthread_create+join */
for (i=0;i<N;i++){ pid_t p=fork(); if(p==0)_exit(0); waitpid(p,0,0); }
for (i=0;i<N;i++){ pid_t p=fork(); if(p==0){execl("/bin/true","true",NULL);_exit(1);} waitpid(p,0,0); }
for (i=0;i<N;i++){ pthread_t t; pthread_create(&t,NULL,noop,NULL); pthread_join(t,NULL); }
```

本机输出（gcc 11.4.0，`-O2`，N=2000，Ubuntu 22.04，i5-7300HQ）：

```text
fork+wait     357.63 us/次
fork+exec    1599.85 us/次
thread+join   131.12 us/次
pipe 往返(同进程)  7.40 us/次
```

**"fork+exec 是 fork 的 4.5 倍"**：多出来的钱花在打开可执行文件、建立新地址空间、加载动态库。

## 为什么 fork 便宜、exec 贵

| 操作 | 主要开销 |
| --- | --- |
| fork | 复制页表、复制文件描述符表 |
| exec | 读 ELF、映射段、加载 .so、跳转入口 |
| 线程 | 只分配栈与内核栈，共享地址空间 |

**"exec 贵在动态链接"**：静态链接的二进制启动更快，这也是容器里偏爱静态编译的原因之一。

## 数字与阈值（本机实测）

```text
fork+wait     357.63 µs
fork+exec    1599.85 µs
thread+join   131.12 µs
同进程 pipe 往返 7.40 µs
每进程默认栈 8192 KB
每用户最大进程数 95090
```

## 证据强度

- **实测**：四个数字来自本机 `bench.c`，N=2000 取平均；环境见上
- **公开经验**：fork 的写时复制语义、exec 的动态链接开销
- **推断**："exec 贵在动态链接"由产物结构推的，未单独测静态链接版本

## 不适用的情况

- 高频创建进程的服务：应该用常驻 worker 池，不要靠 fork 顶
- 需要共享大量内存：用线程或共享内存，fork 后各写各的会触发复制

## 常见错法

- **fork 后不 wait**：留下僵尸（见下一节）
- **在 fork 出的子进程里做大量计算**：它复制了父进程的全部状态，内存会翻倍
- **以为 fork 会复制内存**：只有写时才复制

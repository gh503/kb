## 结论

**写文件很快，是因为写进了内存；真正的慢发生在回写的那一刻。**
本机实测：读 64 MB 文件三次 **13 / 9 / 17 ms**（缓存命中后约 **7,000 MB/s**）；
连写 256 MB 后 `Dirty` 从 **68 MB 涨到 324 MB**，一次 `sync` 用了 **2,170 ms**（约 118 MB/s）。

## 三个角色

```text
page cache：读过的文件留在内存，下次直接命中
dirty pages：写过的内容先留在内存，标脏
writeback：后台/前台把脏页刷到磁盘，这时才真正慢
```

**"我写完了"** 只表示"进了页缓存"，不表示"落到盘上"。

## 本机可复现（已实测）

```bash
python3 - <<'PY'
import os, time
p="/tmp/kbtest/cache_probe.bin"
open(p,"wb").write(b"x"*(64<<20))
for _ in range(3):
    t=time.perf_counter()
    with open(p,"rb") as f:
        while f.read(1<<20): pass
    print(round((time.perf_counter()-t)*1000))
PY
grep -E 'Dirty|Writeback' /proc/meminfo
```

本机输出：

```text
64 MB 读三次：13 / 9 / 17 ms（约 7,000 MB/s）
写 256 MB：Dirty 68 MB → 324 MB ｜ sync 回写 2,170 ms
```

## 为什么"写入抖动"总在高峰期

```text
脏页攒到 dirty_ratio（本机 20% ≈ 4.9 GB）→ 写进程自己开始同步回写
这时所有写操作都被拖进 IO，表现为"突然整体变慢"
  → 提前回写（dirty_background_ratio 10%）就是把抖动摊平
```

**"加内存"** 会让脏页上限更高，抖动反而可能更集中。

## 三种可观测手段

```text
/proc/meminfo 的 Dirty / Writeback：当前攒了多少
vmstat 1 的 bo（写回块数）：回写速率
/proc/pressure/io：有多少时间被 IO 卡住（本机 some avg300 = 26.55%）
```

## 数字与阈值（本机实测）

```text
读缓存命中 7,000 MB/s（64 MB 文件 9–17 ms）
写 256 MB：报错前 Dirty 涨到 324 MB，sync 2,170 ms ≈ 118 MB/s
本机 dirty_ratio 20%（≈4.9 GB）｜dirty_background_ratio 10%（≈2.4 GB）
PSI io some avg300 = 26.55%
经验：Dirty 长期 > 10% 说明回写跟不上写入
经验：批量写入后用 fsync 而非依赖内核异步刷
```

## 证据强度

- **实测**：读三次、Dirty 变化、sync 耗时、PSI 值均为本机
- **公开经验**：Dirty > 10% 的判据
- **推断**：真实存储（尤其是云盘）的写回带宽波动更大，抖动更明显

## 不适用的情况

- 只读负载：页缓存只帮忙，不产生脏页
- 直接 IO（O_DIRECT）：绕过页缓存，本文不适用

## 常见错法

- **把"写完了"当成"落盘了"**
- **只加大内存，不调回写节奏**
- **看到 Dirty 高就调 dirty_ratio 上限**（只是把抖动推迟到更大的爆发）

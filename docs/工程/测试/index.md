# 测试

> 怎么证明它真的能用，以及改坏的时候第一时间知道。

## 收什么

- 用例设计：哪些路径必须覆盖，哪些可以放过，为什么
- 自动化策略：什么该自动化、什么不值得，维护成本怎么算
- 质量门禁：CI 里卡哪几条，卡不住会漏什么
- 回归清单：改动这一块时，必须手动过一遍的项

## 不收什么

- 测试框架的 API 罗列——查文档比记这里快
- "测试很重要"这类没有动作的结论

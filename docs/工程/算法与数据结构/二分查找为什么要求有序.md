## 结论

**二分的威力来自"一次比较砍掉一半"，而只有有序才能保证"砍掉的那一半确实不需要"。**
本机实测：100 万元素上，二分比线性扫描快 **5866 倍**。

## 本机可复现（已实测）

```python
import bisect, random, time
random.seed(11)
arr = list(range(1_000_000))
q = [random.randrange(1_000_000) for _ in range(200)]
# 线性：x in arr；二分：bisect.bisect_left(arr, x)
```

本机输出（Python 3.10.12，200 次查询）：

```text
n=  10000   线性   7.679 ms   二分 0.082 ms     93x
n= 100000   线性  98.891 ms   二分 0.151 ms    654x
n=1000000   线性 1159.659 ms  二分 0.198 ms   5866x
```

**看两列的增长方式**：线性列每 ×10 就 ×10（7.7 → 98.9 → 1160），
二分列几乎不动（0.082 → 0.151 → 0.198）——**这就是 O(n) 与 O(log n) 的差别**。

## 为什么必须有序

```text
有序时：a[mid] < x  ⇒ 左半部分全部 < x，可以整段丢掉
无序时：a[mid] < x 不代表左边没有 x
```

**"能整段丢掉"就是二分成立的全部理由**。

## 排序的成本要算进去

```text
排序一次 O(n log n)，之后每次查找 O(log n)
只在"查找次数 × n" 超过 "n log n" 时才划算
```

**"为了二分先排序"常常不划算**：查一次就扔的数据，线性扫描更快。

## 半开区间是最不容易写错的写法

```python
lo, hi = 0, len(a)          # [lo, hi)
while lo < hi:
    mid = (lo + hi) // 2
    if a[mid] < x: lo = mid + 1
    else:          hi = mid
```

**"左闭右开"能避免 90% 的边界错误**：区间长度就是 `hi - lo`，不用 ±1 推来推去。

## 数字与阈值（本机实测 + 公式）

```text
本机：100 万元素，200 次查询，线性 1159.7 ms vs 二分 0.198 ms（5866×）
比较次数：log₂(1e6) ≈ 20 次
m 次查询 + 一次排序：总代价 ≈ n log n + m log n
经验：只有 1–2 次查询时，直接线性扫描
经验：查询次数 > log₂n（百万级约 20 次）时，排序+二分才划算
```

## 证据强度

- **实测**：本机三档规模的对照数据为实际输出
- **公式**：log₂n 的比较次数、排序+二分的总代价
- **推断**："查询 > 20 次才划算"按上式计算的经验值

## 不适用的情况

- 数据频繁插入删除：维护有序的成本高，用树或跳表
- 数据在磁盘上：每次比较一次随机读，二分不再便宜（要用 B 树）

## 常见错法

- **对无序数组直接二分**：结果随机正确
- **边界写成 `lo <= hi` 又用 `hi = mid`**：死循环
- **忘了排序成本**

## 结论

**开放寻址比链地址快，但它有一个"拿空位当标记"的经典坑。**
本机实测（200 万个键、装载因子 ≈ 0.9、100 万次查询）：
**链地址 58 ms，开放寻址 41 ms（快 1.4 倍）——但开放寻址只命中了 999,999 个键。**
少的那一个，键值恰好是 0，被当成了"空位"。

## 两种冲突处理

```text
链地址（chaining）：每个桶挂一个链表，冲突就挂上去
  → 装载因子可以 > 1；删除简单；缓存不友好（指针跳转）
开放寻址（open addressing）：冲突就往后找空位（线性探测/二次探测/双散列）
  → 连续内存、缓存友好、更快；但删除要用墓碑；装载因子必须 < 1
```

**"更快"的代价是对装载因子敏感**：α 超过 0.7 后线性探测的探测长度暴涨。

## 本机可复现（已实测）

```bash
cat > /tmp/hash.c <<'C'
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#define N 1000000
#define CNT 2000000
typedef struct node { unsigned long k; struct node* next; } node;
static unsigned long h(unsigned long k){ k^=k>>33; k*=0xff51afd7ed558ccdUL; k^=k>>33; return k; }
static double now(){ struct timespec t; clock_gettime(CLOCK_MONOTONIC,&t); return t.tv_sec*1000.0+t.tv_nsec/1e6; }
int main(){
  size_t cap = 2200000;
  unsigned long *keys = malloc(CNT*sizeof(unsigned long));
  for (size_t i=0;i<CNT;i++) keys[i] = i*2654435761UL;
  node **buckets = calloc(cap, sizeof(node*));
  double t0=now();
  for (size_t i=0;i<CNT;i++){ node*n=malloc(sizeof(node)); n->k=keys[i]; size_t b=h(keys[i])%cap; n->next=buckets[b]; buckets[b]=n; }
  double t1=now();
  long found=0;
  for (size_t i=0;i<N;i++){ size_t b=h(keys[i])%cap; for(node*n=buckets[b];n;n=n->next) if(n->k==keys[i]){found++;break;} }
  double t2=now();
  printf("链地址：插入 %.0f ms ｜ 1e6 次查询 %.0f ms（命中 %ld）\n", t1-t0, t2-t1, found);
  unsigned long *tab = calloc(cap, sizeof(unsigned long));     /* 0 表示空 */
  t0=now();
  for (size_t i=0;i<CNT;i++){ size_t b=h(keys[i])%cap; while(tab[b]) b=(b+1)%cap; tab[b]=keys[i]; }
  t1=now();
  found=0;
  for (size_t i=0;i<N;i++){ size_t b=h(keys[i])%cap; while(tab[b]){ if(tab[b]==keys[i]){found++;break;} b=(b+1)%cap; } }
  t2=now();
  printf("开放寻址：插入 %.0f ms ｜ 1e6 次查询 %.0f ms（命中 %ld）\n", t1-t0, t2-t1, found);
  return 0;
}
C
gcc -O2 -o /tmp/hash /tmp/hash.c && /tmp/hash
```

本机输出：

```text
链地址：插入 249 ms ｜ 1e6 次查询 58 ms（命中 1000000）
开放寻址：插入 196 ms ｜ 1e6 次查询 41 ms（命中 999999）
```

**"命中 999,999 而不是 1,000,000"** 就是那个 bug：键 0 与"空位标记"撞了。

## 怎么避免这个坑

```text
1. 用独立的占用位图（occupied bitmap），不拿键值当标记
2. 用哨兵值域之外的键（如键域加偏移）
3. 存 (key, occupied) 结构体，或用 tombstone 表示已删除
```

**"键值域包含你的空标记"** 是开放寻址最常见的实现错误，而且只在特定数据上暴露。

## 装载因子的实测影响

```text
α < 0.5：线性探测平均探测 1–2 次，比链地址快
α ≈ 0.9：探测长度接近 5–10 次，优势缩小甚至反转
α → 1：探测长度爆炸，必须扩容
```

**"扩容要趁早"**：α 到 0.75 就翻倍，比等到 0.95 再扩便宜得多（后者要重插全部元素）。

## 数字与阈值（本机实测）

```text
2e6 键、cap 2.2e6（α≈0.91）：链地址 58 ms / 开放寻址 41 ms（1.4×）
链地址插入 249 ms ｜ 开放寻址插入 196 ms
开放寻址因"0 当空标记"少命中 1 个键
经验：α ≤ 0.5 用开放寻址；α 高或要频繁删除，用链地址
经验：线性探测在 α=0.5 时平均约 1.5 次探测，α=0.9 时约 5.5 次
```

## 证据强度

- **实测**：六个数与那次"少一个键"来自本机 C 程序
- **公开经验**：探测长度的理论值
- **推断**：链地址的指针跳转在现代 CPU 上代价更大，实际差距随负载变化

## 不适用的情况

- 键很少（几百个）：随便哪种都行
- 键不可哈希/需要范围查询：用树而不是哈希表

## 常见错法

- **拿 0 或 -1 当空标记，而键域包含它们**
- **删除时直接把槽位置空**：后续探测链断了，查不到后面的键
- **装载因子到 0.95 才扩容**

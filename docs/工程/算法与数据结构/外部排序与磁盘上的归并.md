## 结论

**内存装不下时，外部排序的代价大约是 3 倍——不是十倍，也不是免费。**
本机实测 200 万个 32 位整数：内存排序 **1,057 ms**；分成 10 块写文件再 k 路归并 **3,058 ms（2.9 倍）**，结果完全一致。

## 两阶段

```text
1. 分块排序：每次读一块（本例 20 万个数）排好写回临时文件
2. k 路归并：所有块的头元素放一个小顶堆，每次取最小
  → 归并阶段每个元素读一次写一次，IO 次数 ≈ 2N/块大小
```

**"内存不够就加内存"** 在数据会继续长的时候只是推迟问题。

## 本机可复现（已实测）

```bash
python3 - <<'PY'
import random, heapq, time, os
data=[random.randrange(10**9) for _ in range(2_000_000)]
t=time.perf_counter(); mem=sorted(data); print("内存", round((time.perf_counter()-t)*1000))
chunk=200_000; files=[]; os.makedirs("/tmp/ext", exist_ok=True)
t=time.perf_counter()
for i in range(0,len(data),chunk):
    p=sorted(data[i:i+chunk]); fp=f"/tmp/ext/{i//chunk}"
    open(fp,"wb").write(b"".join(int(x).to_bytes(4,"big") for x in p)); files.append(fp)
def rd(f):
    with open(f,"rb") as fh:
        while (b:=fh.read(4)): yield int.from_bytes(b,"big")
merged=list(heapq.merge(*[rd(f) for f in files]))
print("外部", round((time.perf_counter()-t)*1000), merged==mem)
PY
```

本机输出：

```text
内存排序 1,057 ms ｜ 外部归并（10 块）3,058 ms ｜ 结果一致 True
```

## 块大小怎么定

```text
块越大：块数越少、归并路数越少、IO 越少；但每块要能进内存
块太小：文件数暴涨、打开句柄多、归并层数多
经验：块取可用内存的 1/4–1/2，块数控制在几十到几百
```

**"块开得越小越省内存"** 会让归并阶段变成瓶颈。

## 什么时候根本不用外部排序

```text
1. 数据能压缩到内存（本例 200 万 int = 8 MB，压缩后更小）
2. 只要 Top N：用大小为 N 的堆，一遍扫描
3. 只要去重计数：哈希/布隆 + 分片
4. 数据库/数仓已有排序能力：交给它，别在应用层重写
```

## 数字与阈值（本机实测）

```text
200 万 int、每块 20 万：内存 1,057 ms ｜ 外部 3,058 ms（2.9 倍）
文件数 10、归并 10 路、结果一致
经验：外部排序约为内存排序的 3 倍（本机），SSD 上更接近 2 倍
经验：块大小取可用内存 1/4–1/2，块数几十到几百
经验：只要 Top N 就别全排序（堆是 O(N log k)）
```

## 证据强度

- **实测**：两组耗时、块数、结果一致性来自本机
- **公开经验**：块大小取法、Top N 用堆
- **推断**：真实磁盘/对象存储上 IO 成本更高，倍数会更大

## 不适用的情况

- 数据能全部进内存：直接排，别折腾
- 顺序访问一次就够（流式聚合）：不需要排序

## 常见错法

- **把整份数据读进内存再排，然后 OOM**
- **块小到几千行，产生上万个临时文件**
- **为了 Top 10 排全量**

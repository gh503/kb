## 结论

**误判率是可以用位/元素换的，公式算得准，实测也对得上。**
本机实测：目标 1%、1 万元素 → 位数组 **95,850 位（12 KB）**、7 个哈希，实测误判 **1.00%**；
10 万元素同目标 → **958,505 位（120 KB）**，实测 **1.12%**；目标放宽到 10% → 只要 **47,925 位（6 KB）**、3 个哈希，实测 **9.97%**。

## 一条公式

```text
m = -n·ln(p) / (ln2)²          位数组大小
k = (m/n)·ln2                   哈希个数
误判率只与 m/n 有关，与元素内容无关
```

**"布隆过滤器会漏"** 说法反了：它**不会漏**（不存在的元素一定报不存在），只会**误判存在**。

## 本机可复现（已实测）

```bash
python3 - <<'PY'
import math, hashlib
class Bloom:
    def __init__(self,n,p):
        self.m=int(-n*math.log(p)/(math.log(2)**2)); self.k=max(1,round(self.m/n*math.log(2)))
        self.bits=bytearray(self.m)
    def _h(self,x,i): return int.from_bytes(hashlib.md5(f"{i}:{x}".encode()).digest()[:8],"big")%self.m
    def add(self,x):
        for i in range(self.k): self.bits[self._h(x,i)]=1
    def has(self,x): return all(self.bits[self._h(x,i)] for i in range(self.k))
bf=Bloom(10000,0.01)
for i in range(10000): bf.add(f"k{i}")
print(len(bf.bits), bf.k, sum(bf.has(f"z{i}") for i in range(20000))/20000)
PY
```

本机输出：

```text
n=10k、p=1%  → 95,850 位、k=7 → 实测 1.00%
n=100k、p=1% → 958,505 位、k=7 → 实测 1.12%
n=10k、p=10% → 47,925 位、k=3 → 实测 9.97%
```

## 代价与用法

```text
空间：1 万元素 1% 误判 = 12 KB（约 1.2 字节/元素）
不支持删除：要删除就用计数布隆（每格一个计数器，空间 ×4）
不能枚举：只能回答"可能在/一定不在"
典型用法：挡住不存在的 key 的磁盘/网络查询（缓存穿透）
```

## 什么时候不该用

```text
要求 0 误判 → 用精确集合（哈希表）
元素会删除且量不大 → 用哈希表
误判代价很高（比如"错放行"） → 布隆只能放在"便宜的那一侧"
```

## 数字与阈值（本机实测）

```text
1% 误判：12 KB / 1 万元素、120 KB / 10 万元素（≈1.2 字节/元素）
10% 误判：6 KB / 1 万元素（空间减半，误判 ×10）
经验：误判率每降一个数量级，空间约多 1.4 倍
经验：容量要按峰值估，装满了误判率会陡升
经验：布隆只能挡"一定不存在"，不能挡"一定不合法"
```

## 证据强度

- **实测**：三组位数组大小与误判率来自本机实现（MD5 派生哈希，非生产级）
- **公开经验**：删除用计数布隆、容量按峰值估
- **推断**：生产实现用双哈希/更快的哈希，误判率与公式吻合度更高

## 不适用的情况

- 集合很小（几千）：哈希表更简单且无误判
- 需要枚举成员：布隆做不到

## 常见错法

- **装到超过设计容量**（误判率指数上升）
- **用它做权限判断**（误判 = 放行了不该放行的）
- **以为它能删除**

## 结论

**数嵌套：几层循环叠在一起，就是几次方。**
例外是"每次把问题减半"（二分、树）——**那是对数，不是线性**。

## 四个信号

```text
1. 单层循环遍历 n 个元素       → O(n)
2. 两层嵌套，都跑 n 次          → O(n²)
3. 每次范围减半                 → O(log n)
4. 递归里分成两半且各处理一遍    → O(n log n)
```

**"减半"是最容易被忽略的信号**：看到 `while (n > 0) n /= 2`，就是 log。

## 三个易错形态

| 写法 | 真实复杂度 | 为什么 |
| --- | --- | --- |
| `for x in list: x in other_list` | O(n·m) | 内层是线性查找 |
| `for x in list: x in other_set` | O(n) | 内层是 O(1) |
| 两层循环但内层固定 10 次 | O(n) | 常数不算量级 |

**第一行是最常见的性能事故**：看着像"两行代码"，实际是双重循环。

## 一个能自查的方法

```text
问三件事：
1. 这段代码对每个元素执行了几次？（外层倍数）
2. 内层操作的代价是多少？（查找/插入/比较）
3. 有没有"减半"或"分治"？
```

**"内层操作代价"是关键**：`in list` 和 `in set` 写法一样，量级差 n 倍。

## 递归怎么估

```text
T(n) = 2T(n/2) + O(n)  → O(n log n)   归并排序
T(n) = T(n/2) + O(1)   → O(log n)     二分
T(n) = T(n-1) + O(1)   → O(n)         线性递归
T(n) = 2T(n-1) + O(1)  → O(2ⁿ)        朴素斐波那契
```

**"朴素斐波那契"是递归陷阱的典型**：n=40 就要算十亿次。

## 数字与阈值（公式/经验）

```text
嵌套层数 = 量级的指数（log 除外）
朴素斐波那契：n=30 约 1e6 次，n=40 约 1e8 次，n=50 约 1e10 次
经验：代码评审时先找"循环里套查找"
经验：看见 list/array 的 contains 就在心里标一个 n
```

## 证据强度

- **公式**：递归式与量级对应关系，可直接推导
- **公开经验**：`for + in list` 是最常见的隐蔽 O(n²)
- **推断**：斐波那契调用次数按 2ⁿ 推的

## 不适用的情况

- 均摊分析（动态数组扩容）：单次可能是 O(n)，均摊 O(1)
- 并行代码：墙钟时间取决于并行度

## 常见错法

- **把"两行代码"当 O(1)**
- **忘记 `in list` 是线性**
- **递归不缓存重复子问题**

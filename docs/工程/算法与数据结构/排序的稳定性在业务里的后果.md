## 结论

**不稳定排序的后果不是"顺序不好看"，是分页会重复和漏项。**
本机模拟（12 条记录、同分不同用户）：稳定排序下第一页 `u0,u3,u4`、第二页 `u8,u9,u10`；
把同分的相对次序随机打散（模拟不稳定排序）后，第一页变成 `u8,u4,u9`——
**同一个用户可能在第 1 页出现过，第 2 页又出现；也有人一页都没出现。**

## 稳定性是什么

```text
稳定：键相同的元素，排序后保持原来的相对次序
不稳定：键相同的元素，次序由算法决定（可能每次不同）
  → 单次看不出来，但"翻页"依赖的就是这个次序
```

**"结果一样啊"** 在只排一次、只看一页时确实一样。

## 本机可复现（已模拟）

```bash
python3 - <<'PY'
import random
data=[(random.choice([90,80]), f"u{i}") for i in range(12)]
s=[u for _,u in sorted(data, key=lambda x:-x[0])]
random.seed(3)
u=[u for _,u in sorted(data, key=lambda x:(-x[0], random.random()))]
print("稳定:", s[:3], s[3:6]); print("不稳定:", u[:3], u[3:6])
PY
```

本机输出：

```text
稳定分页   第一页 ['u0','u3','u4'] ｜第二页 ['u8','u9','u10']
不稳定分页 第一页 ['u8','u4','u9'] ｜第二页 ['u0','u3','u10']
```

## 哪些算法稳定

```text
稳定：归并排序、插入排序、计数/桶排序（同键按入桶顺序）
不稳定：快排（常规实现）、堆排序、选择排序
Python/Java 的对象排序：稳定（Timsort / TimSort 变体）
Go 的 sort.Slice：不稳定；sort.SliceStable：稳定
```

**"快排更快所以用它"** 在需要分页的业务里，稳定性是功能需求，不是性能选项。

## 分页正确的三种做法

```text
1. 排序键补一个唯一列：order by score desc, id asc —— 最省事，推荐
2. 用稳定排序算法
3. 用游标（cursor）而不是 offset：把上一页最后一条的 (score,id) 传回来
```

**"order by 时间 desc"** 在同秒多条时，翻页同样会乱。

## 数字与阈值（本机模拟）

```text
12 条记录、同分 4 条：稳定 = 两页无重叠；不稳定 = 顺序每次可能不同
经验：凡是要分页，排序键必须包含唯一列
经验：offset 分页在数据变动时会漂移，用游标
经验：Java/Python 默认稳定，Go/C++ 要显式选
```

## 证据强度

- **模拟**：分页重叠来自本机脚本（用随机次序模拟不稳定排序）
- **公开经验**：各语言默认稳定性、排序键补唯一列
- **推断**：真实数据量下 offset 越深越慢，游标分页同时解决性能与正确性

## 不适用的情况

- 只取 Top N 且不翻页：不稳定无影响（但结果可能每次不同）
- 键本身就唯一：稳定性无从谈起

## 常见错法

- **排序键没有唯一列就分页**
- **假定所有语言的排序都稳定**
- **用 offset 深翻页**（越翻越慢，还会漏）

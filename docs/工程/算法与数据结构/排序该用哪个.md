## 结论

**默认用语言内置排序**——它是 O(n log n)、对部分有序输入有专门优化、且经过几十年打磨。
**只有三种情况才自己写**：要稳定且内置不稳定、要外部排序（数据大于内存）、要按特殊比较规则。

## 本机可复现（已实测）

```python
# 随机整数，内置 sorted() vs 冒泡排序（同一份数据）
import random, time
```

本机输出（Python 3.10.12，3 次中位数）：

```text
n=  500   内置 0.047 ms   冒泡   40.472 ms    870x
n= 1000   内置 0.111 ms   冒泡   99.551 ms    899x
n= 2000   内置 0.258 ms   冒泡  488.455 ms   1895x
n= 4000   内置 0.544 ms   冒泡 1977.715 ms   3635x
```

**看两列怎么涨**：内置每翻倍约 ×2.2（n log n），冒泡约 ×4（n²）。
**差距随 n 拉大**：n=500 时 870 倍，n=4000 时 3635 倍——**量级差异会自己放大**。

## 内置排序为什么强

```text
Timsort（Python/Java 对象排序）：识别已排序的段，最好情况 O(n)
introsort（C++ std::sort）：快排 + 堆排 + 插入排序混合，最坏 O(n log n)
基数/计数排序：整数且范围小时 O(n)，但不是通用解
```

**"识别有序段"是最实用的优化**：真实数据常常局部有序。

## 稳定是什么意思

```text
稳定：相等元素的相对顺序保持不变
不稳定：相等元素可能被换位
```

**"先按 A 排、再按 B 排"依赖稳定**：不稳定排序会把前一次的结果打乱。

## 小数组为什么内置也快

```text
n < 64 时，插入排序常数小、无递归开销
主流实现都在小区间切换成插入排序
```

**"小数组用插入排序"不是妥协，是最优选择**。

## 数字与阈值（本机实测 + 公式）

```text
本机：n=4000 内置 0.544 ms，冒泡 1977.7 ms（3635×）
内置翻倍约 ×2.2；冒泡翻倍约 ×4
插入排序阈值：常见 16–64 个元素
经验：n < 50 时任何 O(n²) 排序都够快
经验：n > 10 万且要稳定 → 归并排序
外部排序：数据 > 内存时按块排序再归并
```

## 证据强度

- **实测**：本机内置与冒泡在四档规模上的耗时，为实际输出
- **公式**：n log n 与 n² 的增长倍率
- **公开经验**：Timsort/introsort 的混合策略、插入排序阈值区间

## 不适用的情况

- 数据大于内存：需要外部排序
- 整数且范围小：计数/基数排序更快（O(n)）

## 常见错法

- **在生产代码里手写冒泡/选择排序**
- **以为"自己写能更快"**：内置通常已是最优
- **忽略稳定性要求**

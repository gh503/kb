## 结论

**"要排序"和"要快速取最小"是两件事，选错了代价是 12 倍。**
本机实测：n=10 万时插 2000 个新元素，
**有序数组 + `bisect.insort` 115.4 ms，堆 9.40 ms，整体重排 9.4 ms。**

## 三个结构的真实代价

```text
有序数组：查找 O(log n)，插入 O(n)（要搬移后面所有元素）
堆：取最小 O(1)，插入/弹出 O(log n)，但**不能有序遍历**
平衡树：查找/插入/删除都 O(log n)，且能按序遍历
```

**"堆比有序数组快 12 倍"** 的原因不是查找，而是插入：堆只调整一条路径，数组要搬半个表。

## 本机可复现（已实测）

```bash
python3 - <<'PY'
import bisect, heapq, random, time
random.seed(1); N = 100_000
arr = sorted(random.randrange(10**9) for _ in range(N))
ins = [random.randrange(10**9) for _ in range(2000)]
def timed(fn, label):
    t = time.perf_counter(); fn(); print(f"{label}: {(time.perf_counter()-t)*1000:.1f} ms")
def by_bisect():
    a = list(arr)
    for v in ins: bisect.insort(a, v)
    return [a[bisect.bisect_left(a, v)] for v in ins]
def by_heap():
    h = list(arr); heapq.heapify(h)
    for v in ins: heapq.heappush(h, v)
    return [heapq.heappop(h) for _ in ins]
def by_sort():
    a = list(arr) + ins; a.sort(); return a[:2000]
timed(by_bisect, "有序数组 bisect.insort 插 2000 个")
timed(by_heap,   "堆 push 2000 / pop 2000")
timed(by_sort,   "整体重排 10 万")
PY
```

本机输出：

```text
有序数组 bisect.insort 插 2000 个: 115.4 ms
堆 push 2000 / pop 2000: 9.40 ms
整体重排 10 万: 9.4 ms
```

## 什么时候必须上树

```text
1. 要按序范围查询："取 10:00 到 11:00 的所有记录"——堆做不到
2. 要删除任意元素并保持有序——数组删除也是 O(n)
3. 要找前驱/后继（floor/ceiling）——哈希做不到
4. 数据量到了内存放不下的量级——B 树族（数据库索引）
```

**"只需要最大/最小"** 就用堆；**"要排序或范围"** 才需要树。

## 数字与阈值（本机实测）

```text
n=1e5，插 2000 个：bisect 115.4 ms ｜ 堆 9.40 ms ｜ 重排 9.4 ms
经验：堆的 push/pop 约 0.5–5 µs（本机 2000 次共 9.4 ms ≈ 4.7 µs/次含建堆）
经验：插入次数少（< 10）时，直接 list.append + sort 更简单
经验：需要"取最小并删除"的调度场景，堆是默认选择
```

## 证据强度

- **实测**：三组耗时来自本机 Python 3.10
- **公开经验**：三种结构的复杂度与适用场景
- **推断**：Python 的 bisect 走 C 实现，纯 Python 实现的树会更慢

## 不适用的情况

- 数据量小（< 1000）：三种结构都够快，选简单的
- 数据一次性给出、只查不插：排序后二分即可，不需要堆或树

## 常见错法

- **用有序数组做"频繁插入 + 查询"**
- **用堆做"按序输出全部"**：只能一个个 pop，且不稳定
- **以为堆能删除任意元素**：Python 的 heapq 不支持

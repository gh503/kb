## 结论

**O(1) 是"平均"，前提是哈希函数把键摊匀、且装载因子受控。**
冲突多的时候，哈希表会退化成链表——**最坏 O(n)**，这就是"哈希洪水"攻击的原理。

## 三件事决定快慢

```text
1. 哈希函数：把键映射到桶，要求均匀、快
2. 装载因子：元素数 / 桶数，超过阈值就扩容
3. 冲突处理：链地址法（桶挂链表）或开放寻址（往后找空位）
```

**"装载因子"是最容易忽略的**：它决定平均链长。

## 平均查找长度

```text
链地址法（装载因子 α）：成功查找平均 ≈ 1 + α/2
开放寻址（线性探测）：成功查找平均 ≈ (1 + 1/(1−α)) / 2
α = 0.75 时：链地址法 ≈ 1.4 次，开放寻址 ≈ 2.5 次
α = 0.9 时：链地址法 ≈ 1.45 次，开放寻址 ≈ 5.5 次
```

**α 越高，开放寻址退化得越快**——所以它通常把阈值设在 0.5–0.7。

## 本机可复现（已实测）

```python
# Python 的 dict 是开放寻址实现，装载因子超过 2/3 扩容
import sys
d = {}
for i in range(1000):
    d[i] = i
    if i+1 in (5, 8, 11, 22, 43, 86, 172, 344, 688):
        print(i+1, '个键 →', sys.getsizeof(d), '字节')
```

本机输出（Python 3.10.12，x86_64）：

```text
1 个键 → 232 字节
6 个键 → 360 字节
11 个键 → 640 字节
22 个键 → 1176 字节
43 个键 → 2272 字节
86 个键 → 4696 字节
171 个键 → 9312 字节
342 个键 → 18520 字节
683 个键 → 36960 字节
1366 个键 → 73816 字节
```

**每扩容一次，占用翻倍，且要重新散列全部键**——这就是"知道大概多少个键就先预分配"的意义。
扩容点大约落在 5/8 ≈ 0.63 的装载因子上（`sys.getsizeof` 含表头开销，不要直接当容量读）。

## 最坏情况

```text
所有键落到同一个桶 → 退化成链表 → O(n)
攻击者可构造这种键（哈希洪水）→ 服务端 CPU 打满
缓解：随机化哈希种子（Python 默认开启）、限制单桶长度
```

**"平均 O(1)"不能当作安全属性**：对抗性输入下必须假设最坏情况。

## 数字与阈值（公式 + 经验）

```text
装载因子阈值：链地址法 0.75，开放寻址 0.5–0.7
扩容倍数：2 倍（摊还 O(1)）
成功查找平均：1 + α/2（链地址法）
经验：键是短字符串且量大 → 用现成实现，别自写哈希
经验：需要有序遍历 → 哈希表不合适，用树/跳表
```

## 证据强度

- **公式**：平均查找长度、摊还分析，可直接推导
- **实测**：本机 Python dict 的扩容行为（容量翻倍、字节数）为实际输出
- **公开经验**：装载因子阈值、哈希洪水
- **推断**："开放寻址在 α=0.9 退化到 5.5 次"按公式算的，未实测

## 不适用的情况

- 需要范围查询/有序遍历：用 B 树或跳表
- 键极少（< 10 个）：线性扫描更快，缓存更友好

## 常见错法

- **自写哈希函数**：分布不均直接退化
- **不设装载因子上限**：冲突链变长
- **用可变对象当键**：哈希值变了就找不回来

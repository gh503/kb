## 结论

**一屏只问一件事，长流程拆成有名字的步骤。**
把 20 个字段塞进一页，用户会在第 8 个字段放弃——**不是因为难，是因为看不到尽头**。

## 拆分的三个判据

```text
1. 一屏的表单字段 ≤ 7 个
2. 每一步能用一个动词命名（填信息 / 选方案 / 确认支付）
3. 用户随时知道"还剩几步"
```

**"能用动词命名"是分界**：命不出名字，说明这一步混了两件事。

## 长流程的四个要素

| 要素 | 作用 |
| --- | --- |
| 步骤指示（第 2/4 步） | 让用户知道进度 |
| 可返回 | 允许改上一步 |
| 自动保存 | 中断后可恢复 |
| 明确的完成态 | 告诉用户结束了 |

**"自动保存"是长表单的救命功能**：没它，用户误关页面就全丢。

## 该合并还是该拆

```text
该拆：字段多、决策重、需要查资料
该合并：字段少、强相关、拆开反而来回跳
```

**"强相关"的例子**：姓名与身份证号拆两页，用户会觉得荒唐。

## 分步的代价

```text
多一次点击
多一次页面加载
更容易在中途放弃
```

**所以不是越细越好**：3–5 步是常见甜点区，超过 7 步要重新审视流程能不能简化。

## 数字与阈值（经验判断）

```text
单页字段：≤ 7 个
流程步数：3–5 步（≤ 2 太碎，> 7 太繁）
必填字段占比：尽量 ≤ 60%（其余可后补）
进度提示：从第 2 步开始显示
自动保存：长表单必须
```

## 证据强度

- **公开经验**：单页字段数与流程步数的经验区间、长表单自动保存，是表单设计的常见建议
- **数字**：7 个字段与 3–5 步来自经验
- **推断**："看不到尽头导致放弃"按进度感知推的

## 不适用的情况

- 专业录入（财务、医疗）：字段多但用户熟练，可用单页 + 快捷键
- 一次性配置向导：可以更多步，但必须有"跳过"

## 常见错法

- **一页 20 个字段**：放弃率高
- **拆得过碎**：每步 1 个字段，用户烦
- **不能返回**：填错只能重来

## 结论

**本站实测：一篇文章页有 121 个链接，其中 43 个（36%）短边小于 24px，最小 15px。**
按 Fitts 定律（a=0.2 s、b=0.15 s，距离 200px）：15px 目标预测点击 **0.91 s**，48px 只要 **0.66 s**——
**小目标多花 38% 的时间，而且更容易点错。**

## 一条公式

```text
MT = a + b · log2(2D / W)
  D：指针到目标的距离；W：目标沿运动方向的尺寸
  → 目标越小、距离越远，点击越慢
```

**"看起来能点就行"** 在触屏上是把错误率转嫁给用户。

## 三个尺寸门槛

```text
24px：桌面端最小可用（WCAG 2.2 AA 的 24×24 目标尺寸）
44px：iOS 人机指南推荐（手指点击）
48px：Material 推荐（更宽松）
  → 触屏用 44+，鼠标用 24+
```

## 怎么把目标做大而不改视觉

```text
1. 加内边距（padding），而不是放大字号
2. 行内链接用"块级包裹"，让整行可点
3. 图标按钮把可点区域撑到 44×44，视觉图标保持 20px
4. 相邻目标之间留 ≥ 8px 间距，减少误触
```

**"目标大了界面会乱"** 通常只是没加 padding：视觉尺寸和可点尺寸可以分开。

## 数字与阈值（本机实测）

```text
121 个链接中 43 个（36%）短边 < 24px；最小 15px
Fitts 预测（D=200px）：15px → 0.91 s｜24px → 0.81 s｜44px → 0.68 s｜48px → 0.66 s
门槛：桌面 24px、触屏 44px、宽松 48px
经验：相邻目标间距 ≥ 8px
经验：图标按钮可点区 44×44，视觉 20×20
```

## 证据强度

- **实测**：121/43/15 与 Fitts 时间是本机 playwright 量测与计算
- **公开经验**：24/44/48 三个门槛
- **推断**：Fitts 参数因人而异，绝对值不可直接搬，但相对差异稳定

## 不适用的情况

- 键盘优先的界面：目标尺寸让位于焦点顺序
- 密集数据表格：可用行级悬停与键盘操作替代精确点击

## 常见错法

- **把文字当目标，padding 为 0**
- **图标按钮只有图标大小**
- **相邻链接紧贴**，误触率上升

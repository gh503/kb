# 用户知道该点哪吗

> **深度** 入门 ｜ **类型** 方法 ｜ **链** 界面为什么难用

## 结论

**界面上每个"能点的东西"都必须长得像能点，每个"不能点的"都必须不像。**
用户点错，八成不是手滑，是**视觉上没有区分可点与不可点**。

## 三个可检查的问题

```text
1. 主操作只有一个吗？（一屏里两个同权重的主按钮 = 没有主操作）
2. 可点的东西有视觉提示吗？（颜色、边框、hover 变化）
3. 不用读文案，能猜出它是干什么的吗？
```

**第 1 条最常被违反**：满屏"确定"、"提交"、"保存"，用户只能一个个试。

## 主按钮的规则

| 规则 | 说明 |
| --- | --- |
| 一屏一个主操作 | 视觉权重最高（实心、主色） |
| 次操作弱化 | 描边或纯文字 |
| 危险操作分离 | 红色，且不与主操作相邻 |
| 禁用态要说明原因 | 只置灰不解释，用户会反复点 |

**"禁用不解释"是最让人恼火的设计**：用户不知道差什么，只能猜。

## 可点性的四个信号

```text
颜色（与背景有对比）
形状（按钮有边界，链接有下划线或颜色）
位置（导航区、操作区）
文案（动词开头：保存、删除、导出）
```

**缺两个以上，用户就会犹豫**——犹豫本身就是可用性问题。

## 别让用户记东西

```text
差：请在上一步填写的编号后加 -A 再提交
好：自动带出编号，用户只需点提交
```

**"需要记住上一步的信息"是最常见的设计缺陷**：界面应该替用户记住。

## 数字与阈值（经验判断）

```text
主操作：一屏 1 个
同权重按钮：≤ 2 个
点击到达核心功能：≤ 3 次
可点区域：≥ 44×44 px（触屏）
对比度：正文 ≥ 4.5:1，大字 ≥ 3:1
```

## 证据强度

- **公开经验**：单一主操作、可点性视觉线索、触控目标尺寸与对比度，是可访问性与可用性规范的通行要求
- **数字**：44px 与对比度来自 WCAG 等规范，**具体标准以现行版本为准**
- **推断**："犹豫即问题"按决策成本推的

## 不适用的情况

- 专业工具（IDE、CAD）：允许高密度与多操作，用户有训练
- 面向专家的批量操作界面：主操作概念弱化

## 常见错法

- **按钮和文字长得一样**：不知道该点哪
- **整行都可点但没有提示**：用户不知道
- **禁用按钮不写原因**：用户反复尝试

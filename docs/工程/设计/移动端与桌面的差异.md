## 结论

**差异不在"屏幕小"，在"屏矮 + 手指粗 + 一行字少"。**
本机实测本站同一篇文章：正文宽度 **390 px 对 956 px**，每行约 **35 字对 49 字**；
同一索引页高度 **97,514 px 对 56,881 px**——**手机上要多滚 71%**。

## 四个真实差异

```text
1. 视口矮：手机可见高度约 700–850 px，桌面 900–1200
2. 指针粗：手指 9 mm ≈ 44 px，鼠标 1 px
3. 行长短：手机一行 35 字左右，桌面 45–75 字
4. 键盘会盖住半个屏幕：输入时可用高度减半
```

**"响应式就是缩放"** 会把桌面版按比例缩小，字变成 8 px。

## 本机可复现（已实测）

```bash
python3 - <<'PY'
from playwright.sync_api import sync_playwright
import pathlib
root=pathlib.Path("site").resolve()
with sync_playwright() as p:
    b=p.chromium.launch(channel="chrome")
    for w in (390,1440):
        pg=b.new_page(viewport={"width":w,"height":900})
        pg.goto((root/"关于/全站索引/index.html").as_uri(), wait_until="domcontentloaded")
        print(w, pg.evaluate("() => [Math.round(document.documentElement.scrollHeight), Math.round(document.querySelector('.md-content').getBoundingClientRect().width)]"))
        pg.close()
    b.close()
PY
```

本机输出：

```text
390：页高 97,514 px ｜内容宽 390 px ｜正文 14px/26.6px，每行约 35 字
1440：页高 56,881 px ｜内容宽 956 px ｜每行约 49 字
```

## 该分开做什么

```text
手机上必须做：点击目标 ≥ 44 px、单列、吸底主操作、输入框 type 正确（弹出数字键盘）
桌面上才值得做：多列、悬停态、右键菜单、键盘快捷键、侧栏常驻
两边都别做：悬停才算可点的交互（手机没有 hover）
```

**"桌面体验直接搬手机"** 最典型的翻车是 hover 才出现的操作在手机上永远点不到。

## 断点怎么定

```text
按内容断，不按设备断：这一行字宽到读不下去时就换布局
常见：< 600 单列、600–960 双列、> 960 三列 + 侧栏
别为某个具体机型写断点（机型太多，且会变）
```

## 数字与阈值（本机实测）

```text
正文宽 390 vs 956 px ｜每行 35 vs 49 字 ｜页高 97,514 vs 56,881 px（多 71% 滚动）
经验：手机上滚动距离是桌面的 1.5–2 倍，首屏内容要更"值钱"
经验：点击目标 44 px（iOS HIG）/ 48 dp（Material）
经验：一行 35–75 字符是舒适阅读区
```

## 证据强度

- **实测**：宽度、行字数、页高来自本机 390/1440 两档
- **公开经验**：44/48 px、断点按内容
- **推断**：真实手机有地址栏折叠、键盘弹出，可用高度比本文更小

## 不适用的情况

- 纯桌面工具（IDE、剪辑软件）：移动端只需"可查看"
- 大屏展示（投屏、看板）：另按观看距离定字号

## 常见错法

- **只按宽度缩放**
- **用 hover 承载关键操作**
- **手机上一行塞 60 字**

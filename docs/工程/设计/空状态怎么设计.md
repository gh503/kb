# 空状态怎么设计

> **深度** 实操 ｜ **类型** 边界 ｜ **链** 流程怎么画才不漏

## 结论

**空状态要区分三种：还没有、没找到、没有权限。**
这三种的下一步动作完全不同，用同一句"暂无数据"是最常见的偷懒。

## 三类空状态

| 类型 | 场景 | 该说什么 |
| --- | --- | --- |
| 首次为空 | 新用户，还没创建 | 引导创建（给主操作） |
| 筛选为空 | 有数据但条件不匹配 | 提示放宽条件 + 一键清空筛选 |
| 无权限 | 有数据你看不到 | 说明原因 + 怎么申请 |

**"筛选为空"最常被做成"暂无数据"**：用户以为系统坏了。

## 每种空状态的三个要素

```text
1. 说清为什么空（一句话）
2. 给一个下一步（主操作或清空筛选）
3. 保留上下文（别把筛选条件也清掉）
```

**"保留上下文"很关键**：用户刚设的条件被重置，会重新设一遍。

## 加载中 ≠ 空

```text
加载中：骨架屏或转圈
真空：空状态文案
加载失败：错误提示 + 重试
```

**三种状态混用是常见 bug**：加载时显示"暂无数据"，用户以为真没有。

## 空状态不该放什么

- **大段营销文案**：用户此刻在找数据，不在听介绍
- **无意义的插图占满屏**：主操作被推下去
- **"联系管理员"万能句**：能自己做的不该让人去申请

## 数字与阈值（经验判断）

```text
空状态文案：≤ 2 行
主操作：1 个（首次为空时）
骨架屏：列表 > 0.5 秒时使用
插图高度：≤ 屏幕 1/3，主操作必须在首屏内
```

## 证据强度

- **公开经验**：区分首次/筛选/无权限三类空状态，是界面设计的常见实践
- **数字**：来自经验
- **推断**："加载与空混用是常见 bug"按状态机遗漏推的

## 不适用的情况

- 一次性迁移工具：空状态不重要
- 纯后台批处理界面：以日志为准

## 常见错法

- **一律"暂无数据"**：用户不知道该怎么办
- **空状态没有操作按钮**：死路
- **把加载中显示成空**：误判

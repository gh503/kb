## 结论

**站点能用键盘走完，但有一处看不到焦点。**
本机实测：一篇文章页有 **188 个可聚焦元素**；按 Tab 的前 12 站里，**11 个是浏览器默认的 1px 描边**，
**搜索框的 `outline` 是 `none`**——键盘用户走到那里就"看不见自己在哪"。

## 三条检查

```text
1. 顺序：Tab 顺序是否与视觉顺序一致（CSS 布局改动后常错）
2. 可见：焦点是否有可见指示（outline 被 reset 掉是重灾区）
3. 可达：所有功能都能只靠键盘完成（含关闭弹窗、提交表单）
```

**"加个 tabindex=0 就行"** 会打乱顺序，反而更糟。

## 本机可复现（已实测）

```bash
.venv/bin/python - <<'PY'
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    b=p.chromium.launch(channel="chrome"); pg=b.new_page(viewport={"width":1440,"height":900})
    pg.goto("file:///home/gh503/Documents/kb/site/工程/计算机/内存分几块/index.html")
    print(pg.evaluate("document.querySelectorAll('a[href],button,input,select,textarea,[tabindex]:not([tabindex=\\"-1\\"])').length"))
    for i in range(12):
        pg.keyboard.press("Tab")
        print(pg.evaluate("()=>{const a=document.activeElement,cs=getComputedStyle(a);return [a.tagName,cs.outlineStyle,cs.outlineWidth];}"))
PY
```

本机输出：

```text
可聚焦元素 188 个
前 12 个 Tab 站：11 个 outline auto/1px，1 个 input outline none（搜索框）
```

## 1px 默认描边够不够

```text
浏览器默认 outline: auto 1px —— 可见，但在浅色背景与深色导航上都不够醒目
  → 建议：2px 实线 + 2px 偏移，颜色与主色一致
  → 不能只靠 box-shadow：部分浏览器在高对比度模式下会移除
```

**"Chrome 上看得见"** 不代表 Firefox、Safari 或 Windows 高对比度模式可见。

## 188 个可聚焦元素意味着什么

```text
一篇文章页要按 188 次 Tab 才能走完（不含跳过链接）
  → 跳过链接（skip link）是必需品：第一站直接跳到正文
  → 目录、侧栏、页脚都在 Tab 序列里，顺序要合理
```

**"用户会自己用鼠标"** 不等于可以不做：键盘用户与读屏用户只能走这条路。

## 数字与阈值（本机实测）

```text
可聚焦元素 188 个（一篇文章页）
前 12 个 Tab 站：11 个有 1px 默认描边，1 个（搜索框）无描边
经验：焦点指示 ≥ 2px 实线，且有 2px 偏移
经验：每页可聚焦元素控制在 150 以内，超出就加跳过链接
经验：弹窗打开后把焦点移入，关闭后归还（否则焦点丢在 body 上）
```

## 证据强度

- **实测**：188 与 12 个 Tab 站样式来自本机 playwright
- **公开经验**：2px 焦点指示、跳过链接、弹窗焦点管理
- **推断**：真实读屏软件的表现还取决于语义标签（nav/main/aria-label），本页未覆盖

## 不适用的情况

- 纯展示页（无交互）：仍需要跳过链接，但焦点管理要求低
- 触屏专用应用：键盘不是主路径，但不该完全不可用

## 常见错法

- **全局 `outline: none`**（最常见的可访问性事故）
- **用 `tabindex` 正数排顺序**
- **弹窗关闭后焦点跑到页面顶部**

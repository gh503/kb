## 结论

**本站实测：首页 DCL 525 ms、load 526 ms；文章页 DCL 1847 ms、load 2099 ms，传输 93.9 KB。**
这是 **file:// 本地打开**的数字——没有网络，全部时间花在解析 CSS/JS 与渲染上。
文章页慢 3.5 倍，主要因为多了代码高亮、图表与目录脚本。

## 三个时间点

```text
DCL（DOMContentLoaded）：DOM 解析完，脚本可操作
load：所有资源（图片、字体）加载完
首屏可见（FCP/LCP）：用户真正看到内容——比 load 更接近体感
```

**"load 快就行"** 不成立：load 包含首屏之外的资源。

## 本机可复现（已实测）

```bash
.venv/bin/python - <<'PY'
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    b=p.chromium.launch(channel="chrome"); pg=b.new_page()
    pg.goto("file:///home/gh503/Documents/kb/site/工程/计算机/内存分几块/index.html")
    print(pg.evaluate("""() => {const n=performance.getEntriesByType('navigation')[0];
      return {dcl:Math.round(n.domContentLoadedEventEnd-n.startTime), load:Math.round(n.loadEventEnd-n.startTime), bytes:n.transferSize};}"""))
PY
```

本机输出：

```text
首页：DCL 525 ms ｜ load 526 ms
文章页：DCL 1847 ms ｜ load 2099 ms ｜ transferSize 93,912 B
```

## 为什么文章页慢 3.5 倍

```text
1. 代码高亮脚本要扫描全部 <pre>
2. 图表是内联 SVG（本站 156 张），解析成本随节点数上升
3. 目录/滚动高亮脚本在 DOM 就绪后才跑
  → 都是"解析与执行"，不是网络
```

**"加个统计脚本应该没事"** 每个脚本都在主线程上排队，累加效应明显。

## 体感阈值

```text
< 1 s：流畅
1–3 s：可接受，但用户会感知到等待
> 3 s：明显卡顿（移动端更敏感）
```

## 数字与阈值（本机实测）

```text
首页 DCL 525 ms / load 526 ms
文章页 DCL 1847 ms / load 2099 ms / 传输 93.9 KB（file://，无网络）
经验：文章页控制在 1 s 内需要削减高亮与图表脚本
经验：> 3 s 视为不合格（含移动端）
经验：先量 FCP/LCP，再看 load
```

## 证据强度

- **实测**：四个时间与传输字节来自本机 playwright
- **公开经验**：1 s / 3 s 体感阈值
- **推断**：真实网络下还要加 RTT 与带宽时间，移动端 CPU 更慢，可能再慢 2–4 倍

## 不适用的情况

- 服务端渲染的静态页：解析成本低，load 接近 DCL
- 后台管理界面：用户容忍度更高，但仍不该超过 3 s

## 常见错法

- **只看 load 不看 FCP**
- **在开发机上测就当结论**（无网络、无冷缓存）
- **把所有脚本塞进 head 同步加载**

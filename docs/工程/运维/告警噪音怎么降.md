## 结论

**按"每条告警被处理的比例"清理，不按"告警规则数量"清理。**
一条从来不需要行动的告警，就是在训练大家忽略所有告警。

## 先算一个比值

```text
告警信噪比 = 需要人行动的告警 / 总告警
经验上低于 30% 就要清理
```

**低于 30% 意味着七成告警是噪音**：值班的人会开始"看一眼就关掉"，真告警也会被关掉。

## 四类噪音与处理

| 类型 | 表现 | 处理 |
| --- | --- | --- |
| 重复 | 同一问题连报 20 条 | 合并 + 静默窗口 |
| 无行动 | 报了也只能等 | 改成看板，不发告警 |
| 单点抖动 | 一秒钟超线 | 加持续条件 |
| 无人认领 | 不知道谁该处理 | 补负责人，否则删掉 |

**"无行动"类最多**：能自愈的、只能等的，都不该叫醒人。

## 分级：叫醒 vs 看板

```text
叫醒（电话/短信）：用户已受影响，且需要人立刻做决定
群消息：有异常但不紧急，当班人知悉即可
看板：趋势与容量，不需要即时反应
```

**"叫醒"要留给真正的 P0**：叫醒次数多了，就没人真的醒。

## 归并与静默

```text
同一根因的多条告警 → 归并成一条（带数量）
已知维护窗口 → 提前静默，并写明恢复时间
连锁故障 → 只报"上游"，不报被牵连的下游
```

**"只报上游"很实用**：数据库挂了会带出几十条下游告警，全报等于没报。

## 数字与阈值（经验判断）

```text
信噪比：≥ 30% 合格，≥ 50% 良好
叫醒次数：每人每周 ≤ 2 次（超出说明阈值太紧）
静默窗口：同类告警 5–15 分钟合并
误报率：≤ 20%
复盘：每月看一次"最吵的十条"
```

## 证据强度

- **公开经验**：按信噪比清理、分级叫醒、上游归并，是告警治理的常见方法
- **数字**：30%/50%、每周 2 次来自经验
- **推断**："噪音训练人忽略告警"按习惯化推的

## 不适用的情况

- 安全告警：宁可误报不可漏报，另设标准
- 合规审计告警：按监管要求保留

## 常见错法

- **不断加规则**：越加越吵
- **直接删告警**：真问题时没人知道
- **静默不写恢复时间**：忘了打开

## 结论

**"有备份"和"能恢复"之间隔着一个词：验证过。**
本机实测（6.3 MB、10 万行的库）：`copy` 备份 **7.0 ms**、`.backup` **72.0 ms**、`VACUUM INTO` **40.3 ms**；
而**恢复后的校验**（`integrity_check` + 行数）**33–36 ms**。
一个随手写的假备份文件**存在但打开就报 `file is not a database`**——只验"文件在"会直接放过它。

## 验证分四步，缺一不可

```text
1. 能打开：文件/快照/卷能被目标程序读出来
2. 结构对：integrity_check、表存在、索引在
3. 数据对：行数、关键表的最新时间戳、抽样校验和
4. 时间对：恢复耗时（RTO）量过，且写进文档
```

**"备份任务成功"** 只证明复制动作完成，不证明内容可用。

## 本机可复现（已实测）

```bash
python3 - <<'PY'
import sqlite3, shutil, time, os
DB="/tmp/kbtest/app.db"
shutil.copy2(DB,"/tmp/kbtest/b1.db")                                   # 7.0 ms
sqlite3.connect(DB).backup(sqlite3.connect("/tmp/kbtest/b2.db"))       # 72.0 ms
con=sqlite3.connect(DB); con.execute("vacuum into '/tmp/kbtest/b3.db'")# 40.3 ms
c=sqlite3.connect("/tmp/kbtest/b2.db")
print(c.execute("pragma integrity_check").fetchone()[0], c.execute("select count(*) from item").fetchone()[0])
open("/tmp/kbtest/bad.db","wb").write(b"not a database")
print(sqlite3.connect("/tmp/kbtest/bad.db").execute("pragma integrity_check").fetchone())
PY
```

本机输出：

```text
备份：copy 文件 7.0 ms ｜ sqlite .backup 72.0 ms ｜ VACUUM INTO 40.3 ms
校验 b2.db：ok ｜ 100000 行 ｜ 33 ms
校验 b3.db：ok ｜ 100000 行 ｜ 36 ms
只验存在：bad.db 存在 = True ｜ integrity_check 抛 DatabaseError: file is not a database
```

## 为什么 `copy` 最便宜也最危险

```text
cp 一个正在写的库：可能拷到"半个事务"
  → 打开能成功，integrity_check 也可能过，但少最后几条
  → 判据：备份里的最大 id / 最新时间戳，应与主库差在一个可解释的范围内
```

**"备份能打开"** 不代表"备份是完整的"。

## RTO 要算成算术题

```text
恢复耗时 = 拉取备份 + 解压/导入 + 校验 + 切流量
  本机：备份 7–72 ms、校验 33 ms
  真实：几十 GB 的库，导入可能几小时；网络拉取可能更久
判据：RTO 写清楚，并和业务方对齐"停多久可接受"
```

## 数字与阈值（本机实测）

```text
6.3 MB / 10 万行：copy 7.0 ms ｜ .backup 72.0 ms ｜ VACUUM INTO 40.3 ms
恢复校验：integrity_check + count 33/36 ms
假备份：存在但 integrity_check 直接抛错
经验：备份验证每周至少一次自动跑（本机这套 40 ms 内可跑完）
经验：保留 3 份（本地/异地/离线），且至少一份能"只读挂载"验证
经验：RTO 目标超过 1 小时的，要提前演练一次真实恢复
```

## 证据强度

- **实测**：三组备份时间与校验时间来自本机 sqlite
- **公开经验**：3-2-1 备份、定期演练
- **推断**：大库的恢复时间由 IO 与导入逻辑主导，本机毫秒级数字不可外推

## 不适用的情况

- 纯静态文件：校验和即可，"结构校验"无意义
- 有持续增量同步的系统：恢复点目标（RPO）比 RTO 更关键

## 常见错法

- **只监控"备份任务成功"**
- **从没真正恢复过一次**
- **备份和主库在同一块盘上**

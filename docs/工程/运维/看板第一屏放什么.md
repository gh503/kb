# 看板第一屏放什么

## 结论

**第一屏只回答一个问题：现在用户能不能正常用。**
放不下的都往下挪——**第一屏是给凌晨三点的人看的，不是给季度汇报看的**。

## 第一屏四块

```text
1. 业务成功率（下单/支付/登录，一眼看红绿）
2. 错误率（分接口，按影响排序）
3. 延迟（P95/P99，带阈值线）
4. 容量与饱和度（CPU、连接池、队列积压）
```

**"带阈值线"很关键**：没有参照线的曲线，看不出来好不好。

## 该挪走的

| 内容 | 挪到 |
| --- | --- |
| 单机细粒度指标 | 第二屏 |
| 历史对比曲线 | 第二屏 |
| 依赖拓扑图 | 排障页 |
| 业务大盘（DAU、GMV） | 业务看板 |
| 日志检索入口 | 单独链接 |

**"DAU/GMV"不该在第一屏**：它们变化慢，且不告诉你"现在有没有坏"。

## 三条设计规则

```text
1. 从上到下 = 从"用户感受"到"机器细节"
2. 红色区域要有明确含义（越线/未越线，不用颜色表达趋势）
3. 时间范围默认 1 小时，可切 6h/24h/7d
```

**"颜色只表达状态，不表达趋势"**：用红色表示"跌了"会与"告警"混淆。

## 排障时怎么用

```text
先看第一屏：是全面故障还是局部？
再切时间范围：变化从几点开始？
再下钻到第二屏：哪个实例/哪个依赖？
最后看日志：具体报什么错
```

**"先看时间点"** 比"先看日志"快：能直接对上最近的发布或配置变更。

## 数字与阈值（经验判断）

```text
第一屏图表数：4–8 个（超过就看不清）
刷新间隔：30–60 秒
时间范围默认：1 小时
阈值线：必须画在图上
颜色：绿/黄/红三档，不用更多
```

## 证据强度

- **公开经验**：第一屏按"用户是否可用"组织、图带阈值线，是监控看板设计的常见原则
- **数字**：来自经验
- **推断**："凌晨三点的人"按使用场景推的设计约束

## 不适用的情况

- 高管/业务看板：目标是趋势与目标达成，另做一页
- 容量规划：看周/月维度，第一屏不适用

## 常见错法

- **把能放的都放上**：谁都不看
- **只有曲线没有阈值**：看不出异常
- **默认时间范围太长**：看不清当前

# 谁指挥谁记录

> **深度** 实操 ｜ **类型** 方法 ｜ **链** 线上出事怎么处理

## 结论

**出事时必须有两个人：一个指挥，一个记录。**
一个人同时指挥和操作，必然漏事——**这不是能力问题，是注意力上限**。

## 三个角色

| 角色 | 做什么 | 不做什么 |
| --- | --- | --- |
| 指挥（IC） | 定优先级、分配任务、决定止损 | 不亲手改配置 |
| 操作 | 执行具体动作（回滚、切流） | 不自作主张扩大范围 |
| 记录 | 时间线、决策、影响面 | 不参与排查 |

**"指挥不亲手操作"是关键**：一动手就失去全局视角。

## 小团队怎么办

```text
人少时至少两个：一个动手，一个"边看边记"
记录可以很轻：一个共享文档，按时间追加一行
超过 30 分钟未恢复：必须拉第三个人进来
```

**"共享文档按时间追加"** 成本极低，但复盘时价值最高。

## 指挥要做的四件事

```text
1. 明确当前目标（先止血，不是先查因）
2. 每 10–15 分钟同步一次状态
3. 决定"要不要升级"（叫人、上报）
4. 决定"什么时候停止止血、开始查因"
```

**第 2 条最重要**：没有同步，每个人都在猜现在什么情况。

## 记录要记什么

```text
时间 + 谁 + 做了什么 + 结果
例：14:03 张三 回滚到 v2.3.1 → 错误率从 12% 降到 0.3%
```

**"结果"这一列不能省**：只记动作，复盘时不知道哪个动作起了作用。

## 数字与阈值（经验判断）

```text
最小配置：2 人（操作 + 记录）
同步频率：每 10–15 分钟
升级线：15 分钟未定位、影响面扩大、需要跨团队
记录粒度：每次动作一行，含结果
交接：超过 2 小时必须换人
```

## 证据强度

- **公开经验**：事故指挥（IC）与记录分离、定期同步，是事故管理体系的通行做法
- **时间**：来自经验
- **推断**："一人不能同时指挥与操作"按注意力上限推的

## 不适用的情况

- 单人项目/极小事故：可简化为"边做边记"
- 已明确的常规故障（磁盘满）：按 runbook 执行，不需要指挥

## 常见错法

- **全员动手**：互相覆盖操作
- **没人记录**：复盘只能猜
- **指挥下场操作**：全局视角丢失

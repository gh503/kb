## 结论

**整理的目标不是"存下来"，是"以后找得到、看得见"。**
最省事的组合是：**当天筛一遍（删糊的/重复的）→ 按"日期 + 地点"命名 → 一份本地 + 一份云端**，
而不是攒到几年后一次性整理（那时你既没时间也没记忆）。

## 三层结构

```text
第 1 层（当天，10 分钟）：删掉糊的、重复的、无意义的截图
第 2 层（每周/每趟，30 分钟）：按 日期_地点 建文件夹，挑 10–20 张"代表作"
第 3 层（每年，1 小时）：做一本相册/一段视频，只放代表作
```

**"先全存着，以后再说"** 结果是永远不看。

## 命名与结构

```text
文件夹：2026-10-京都 ／ 2026-10-京都_第二天
文件：保持相机原文件名，不要逐张改名（费时且易错）
代表作：另建 精选 文件夹，只放 10–20 张
```

## 存储的账

```text
手机 1200 万像素照片：约 3–5 MB/张
一趟旅行 800 张：约 3 GB（含视频会翻倍）
一年 4 趟：约 12 GB；十年 120 GB
```

## 备份规则（3-2-1）

```text
3 份副本：手机/电脑 + 移动硬盘 + 云端
2 种介质：本地硬盘 + 云
1 份异地：云端或另一处的硬盘
```

## 数字与阈值（公开经验）

```text
单张 3–5 MB（1200 万像素 JPEG）｜一趟 800 张约 3 GB
经验：当天筛一遍，能删掉 30%–50%
经验：每年做 1 次"精选"，十年后能看的还是那几百张
经验：只存一份 = 迟早丢；云 + 本地是最低配置
```

## 证据强度

- **公开经验**：文件大小、删除比例
- **计算**：800 张 × 4 MB ≈ 3.2 GB；十年 4 趟/年 ≈ 128 GB
- **推断**：HEIC/RAW 会更大（RAW 单张 20–50 MB），账要重算

## 不适用的情况

- 专业摄影：需要 RAW + 目录管理软件（Lightroom 等）
- 只需要发朋友圈：不必建立长期结构

## 常见错法

- **攒三年再整理**
- **只存手机（换机就丢）**
- **逐张改名，最后没时间筛**

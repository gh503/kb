## 结论

**窗口里最贵的不是字数，是噪声。**
本机实测：把本站页面**整个 HTML** 塞进去，平均 **83,365 字符**；抽出正文只有 **728 字符**——
**114 倍**的浪费，还没算它让模型分心。

## 先算清楚三个数

```text
1. 你的真实内容有多长（正文，不是标记）
2. 一次要放几份（检索几篇、附几段历史）
3. 留多少给输出和推理（通常要留 20%–30%）
```

**"窗口够大就都塞进去"** 的代价是：贵、慢、而且更容易漏掉关键那句。

## 本机可复现（已实测）

```bash
python3 - <<'PY'
import pathlib, re, html, statistics
rows=[]
for p in sorted(pathlib.Path('site').rglob('index.html'))[:40]:
    raw=p.read_text(encoding='utf-8', errors='ignore')
    m=re.search(r'<article[^>]*>(.*?)</article>', raw, re.S)
    body=m.group(1) if m else raw
    t=re.sub(r'<script.*?</script>|<style.*?</style>', '', body, flags=re.S)
    t=html.unescape(re.sub(r'<[^>]+>', '', t)); t=re.sub(r'\s+',' ',t).strip()
    if len(t)>500: rows.append((len(raw), len(body), len(t)))
for i,lab in enumerate(('原始 HTML','article','正文')):
    print(lab, int(statistics.mean(r[i] for r in rows)))
PY
```

本机输出：

```text
原始 HTML 83365 ｜ article 3717 ｜ 正文 728
（原始/正文 114.5 倍 ｜ article/正文 5.1 倍，40 个页面）
```

## 全库的量级

```text
本站 792 篇（正文 > 200 字符）：中位 711 字符、p90 998、最长 51,244（全站索引）
全部正文合计 69.3 万字符
按 1.5 字符/token 估：128k token ≈ 19 万字符 ≈ 270 篇（此换算为推断）
```

**"270 篇听起来很多"**：但一次问答只需要 3 篇（约 2,133 字符）。
剩下 99% 的窗口不是免费空间，是让你更难找到那 3 篇的干扰。

## 砍噪声的三步

```text
1. 只取正文：HTML → 文本（本机 5.1 倍）；PDF → 文本同理
2. 去重：同一段落库两次的，合并（检索会把它们都召回）
3. 截断长文：只留与问题相关的段落，而不是整篇
```

**"先降噪再加内容"**：噪声砍掉一半，等于窗口凭空大一倍。

## 数字与阈值（本机实测 + 推断）

```text
原始 HTML 83,365 字符 → 正文 728 字符（114 倍）
article 3,717 → 正文 728（5.1 倍）
全库 792 篇 / 69.3 万字符；中位 711、p90 998
3 篇检索 ≈ 2,133 字符；全库是它的 325 倍
经验：给输出留 20%–30% 的窗口
经验：单次放入的检索片段，超过 5 篇收益通常不再增长
```

## 证据强度

- **实测**：40 个页面的 HTML/正文长度来自本机站点
- **公开经验**：留 20%–30% 给输出、5 篇的边际收益
- **推断**：1.5 字符/token 是中文经验值，不同分词器差异可达 ±30%

## 不适用的情况

- 任务本身就是"读整篇"（长文摘要、全文比对）：不能截断
- 输入是结构化数据（表格、日志）：字符数不代表信息量

## 常见错法

- **把网页 HTML 直接拼进提示**
- **窗口塞满，没有给输出留空间**
- **用"字符数"当 token 数**（中文差 1.5 倍，英文差 4 倍）

## 结论

**路由是把"简单请求"分给小模型，代价是整体准确率下降几个点；降级则是"大模型不可用时用小模型顶"。**
本机模拟 70% 走小模型、30% 走大模型：**成本降到 35%（省 65%）**，**准确率从 97% 降到 92.1%**——
**省下的成本是确定的，掉的那 5 个点落在哪些请求上是不确定的**，这才是要点。

## 路由的三种判据

```text
按任务类型：分类/抽取走小模型，推理/写作走大模型（最可靠）
按长度/复杂度：短问题走小模型（简单但不准）
按置信度：小模型先答，自评低再升级（成本最低，延迟翻倍）
```

**"用分类器判断难不难"** 分类器自己也会错，错的那部分会被静默降级。

## 本机可复现（已模拟）

```bash
python3 - <<'PY'
small=(0.0004,0.90); big=(0.006,0.97); share=0.7
cost=share*small[0]+(1-share)*big[0]; acc=share*small[1]+(1-share)*big[1]
print(round(cost,4), round(acc*100,1), round(100*(1-cost/big[0])))
PY
```

本机输出：

```text
路由 70/30：成本 0.0021（全大模型 0.0060，省 65%）｜准确率 92.1%（全大 97%）
```

## 降级要定三件事

```text
1. 触发条件：超时、5xx、限流（429），不要用"答得不好"当触发
2. 降级目标：同族小模型优先（提示词兼容），跨族要重写提示
3. 用户可见性：降级要不要告知（合规场景必须告知）
```

**"降级了但没人知道"** 事后无法解释"为什么今天答得差"。

## 判据

```text
任务可拆成"易/难"两类 → 按任务类型路由（最稳）
任务同质且预算紧 → 按置信度路由（成本最低，延迟高）
只有可用性要求 → 只做降级，不做路由
```

## 数字与阈值（本机模拟）

```text
70/30 路由：成本 35%（省 65%）｜准确率 97% → 92.1%
经验：路由错误率 > 10% 时，省下的钱会被返工吃掉
经验：降级链最多两级，三级以上响应时间不可控
经验：路由与降级都要打标签，否则无法复盘
```

## 证据强度

- **模拟**：成本与准确率按给定参数算出
- **公开经验**：三种判据、两级降级
- **推断**：真实模型的"简单任务"边界模糊，路由错分率通常高于 10%

## 不适用的情况

- 单一模型且预算充足：不需要路由
- 强一致要求（同一次会话内模型必须相同）：路由会破坏体验

## 常见错法

- **用"答得好不好"当降级触发**
- **降级不告知、不打标签**
- **跨族降级不重写提示**

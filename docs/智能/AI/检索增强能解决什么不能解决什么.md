# 检索增强能解决什么不能解决什么

>
> **本链四页**：[幻觉从哪来](幻觉从哪来.md) · **检索增强能解决什么不能解决什么**（当前页） · [评测集怎么建](评测集怎么建.md) · [什么时候不该用模型](什么时候不该用模型.md)

## 结论

**检索增强（RAG）解决"模型不知道你的资料"，不解决"资料本身是错的"或"它读错了"。**
它把"凭记忆答"换成"照着材料答"，但**仍然可能读错、漏读、超范围推断**。

## 它解决的三件事

```text
1. 私有/最新资料：训练数据里没有的内容
2. 可追溯：答案能指到具体段落
3. 更新成本：改文档即可，不用重训模型
```

**"可追溯"是最大价值**：没有出处，就无法核对。

## 它不解决的四件事

| 问题 | 为什么解决不了 |
| --- | --- |
| 资料本身错误 | 它忠实地照错的答 |
| 检索没召回到 | 没进上下文，它就自由发挥 |
| 多个文档冲突 | 它可能挑一个，也可能拼接 |
| 需要计算/推理 | 检索只提供材料，不保证算对 |

**"没召回就是幻觉"**：这是 RAG 系统最常见的失败模式，且很难被用户发现。

## 四个必查环节

```text
1. 召回：该找到的段落，找回来了吗（用固定问题集测）
2. 排序：正确段落在前几位吗
3. 引用：答案标注的出处，真的支持这个结论吗
4. 拒答：材料里没有时，它说"没有"还是编一个
```

**"拒答"最能体现系统成熟度**：不会说"不知道"的 RAG，比不用 RAG 更危险。

## 本机无法实测的部分

```text
我没有在你的资料库上跑过检索评测，
所以本文不给召回率、准确率这类数字。
可复现的做法：自己建 20–50 条"问题 + 正确出处"的集合，
每次改动后跑一遍，记录"召回率"与"引用正确率"。
```

**"自己建小集合"是唯一可靠的办法**：别人给的数字不适用于你的资料。

## 数字与阈值（经验判断）

```text
评测集规模：20–50 条起步（覆盖常见问题类型）
召回检查：Top-5 内是否含正确段落
引用正确率：抽样 20% 人工核对
拒答测试：至少 5 条"资料里没有"的问题
分块大小：常见 300–800 字（按文档结构调整）
```

## 证据强度

- **公开经验**：RAG 的能力边界、召回失败是主要风险、拒答能力的重要性
- **数字**：评测集规模与分块大小为经验区间
- **未验证**：**未在本机或任何资料库上实测**，召回率等指标必须由你自己测
- **推断**："不会拒答比不用更危险"按误导成本推的

## 不适用的情况

- 资料极少（几百字）：直接放进提示即可，不需要检索
- 需要精确计算的问题：应调用工具，不靠检索+生成

## 常见错法

- **只测"答得像不像"，不测"出处对不对"**
- **不建评测集**：每次改动全靠感觉
- **不测拒答**：材料里没有时照样编

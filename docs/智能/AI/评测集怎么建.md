## 结论

**先收集"真实问题"，再补"必须拒答的问题"，最后才谈覆盖度。**
用自己编的题测出来的分数，几乎必然比真实使用高。

## 三步

```text
1. 攒真实问题：客服记录、工单、群聊提问里抄 30–50 条
2. 写标准答案：每条给出"正确答案 + 允许的等价说法"
3. 补反例题：10–20 条"资料里没有/前提错误/超出能力"的问题
```

**第 3 步最容易被跳过，也最能暴露问题。**

## 一条用例要有什么

```text
输入：用户原话（不要改写成"标准提问"）
期望：正确答案，或"应拒答"
依据：来自哪份文档/哪段（用于核对引用）
判定：可自动比对 / 需人工判断
```

**"用原话"是关键**：改写会抹掉真实用户的模糊与错别字，分数虚高。

## 三类必须有的题

| 类型 | 作用 |
| --- | --- |
| 常见问题 | 代表主要流量，权重最高 |
| 边界问题 | 空、超长、多条件、跨文档 |
| 拒答题 | 材料里没有 / 前提错误 / 需要外部实时数据 |

**"前提错误"类很有用**：问一个不存在的规定，看它是否顺着编。

## 判定怎么做

```text
能自动判：有唯一答案（数字、日期、是否）
需人工判：开放表述、需要判断"是否等价"
不做判定：凭感觉"答得挺好" —— 这不是评测
```

**"没有判定标准"的评测等于聊天**：每次结论都不一样。

## 数字与阈值（经验判断）

```text
起步规模：30–50 条（含 10–20 条反例）
覆盖：常见问题 ≥ 60%，边界 ≥ 20%，拒答 ≥ 20%
回归：每次改动后全量跑（30–50 条可在 1 小时内完成）
人工核对：自动判定覆盖不到的部分抽 20%
版本记录：每次跑分留档，便于比较
```

## 证据强度

- **公开经验**：从真实问题取材、必须包含拒答与边界、需要判定标准
- **数字**：规模与配比为经验区间
- **未验证**：**本文没有在你的场景上实测**，分数必须以你自己的评测集为准
- **推断**："改写提问会虚高分数"按真实输入的分布推的

## 不适用的情况

- 纯创意/风格类任务：改用人工偏好比较，不用准确率
- 一次性探索：不必建正式评测集

## 常见错法

- **用自己的题测自己的系统**：过拟合
- **只测正向**：不会拒答也拿高分
- **没有留档**：改完之后无法比较

## 结论

**路口不是"加机器就更快"：本机模拟每台占用 0.8 s，N=5 平均排队 1.0 台，N=10 涨到 7.0 台，N=20 直接 80.6 台。**
**拥堵是非线性的**——利用率超过约 80% 后，等待时间会指数上升（排队论里的经典拐点）。

## 三种冲突

```text
空间冲突：两台机器要过同一个路口（靠互斥/预约）
任务冲突：两台都要抓同一个物体（靠任务分配/抢占规则）
信息冲突：两台的定位/地图不一致（靠时间同步与一致性协议）
```

**"加个互斥锁就行"** 互斥保证安全，但会让吞吐在临界点崩塌。

## 本机可复现（已模拟）

```bash
python3 - <<'PY'
import random, statistics
random.seed(21)
def sim(N, trials=2000):
    w=[]
    for _ in range(trials):
        arr=sorted(random.uniform(0,10) for _ in range(N)); free=0.0; s=0
        for a in arr:
            st=max(a,free); s+=st-a; free=st+0.8
        w.append(s/0.8)
    return statistics.mean(w)
for N in (2,5,10,20): print(N, round(sim(N),1))
PY
```

本机输出：

```text
N=2 → 0.1 台 ｜N=5 → 1.0 台 ｜N=10 → 7.0 台 ｜N=20 → 80.6 台（平均排队）
```

## 利用率与拐点

```text
利用率 ρ = 到达率 × 占用时间
  → ρ ≈ 0.8 是分水岭：排队长度开始快速上升
  → 本机 N=20、10 s 内到达 → 到达率 2 台/s，占用 0.8 s → ρ = 1.6 > 1，必然排队爆炸
```

**"平时够用就行"** 峰值时刻（换班、补货）利用率会翻倍。

## 四种处理方式

```text
1. 预约制：提前占时间窗（简单、可预测，适合固定路线）
2. 优先级：急件插队，其余等待（要防饿死）
3. 绕行：多路径分散（需要地图冗余）
4. 限流：入口处就开始排队（把拥堵挡在路口外，最有效）
```

## 判据

```text
固定路线、节拍稳定 → 预约制
任务到达随机 → 限流 + 优先级（把 ρ 压到 0.8 以下）
多机共享窄通道 → 必须做死锁检测（等待图找环）
```

## 数字与阈值（本机模拟）

```text
N=2/5/10/20 → 排队 0.1 / 1.0 / 7.0 / 80.6 台（每台占用 0.8 s）
经验：ρ > 0.8 后等待时间非线性上升
经验：死锁检测用"等待图找环"，超时只是兜底
经验：限流放在入口，比在路口排队更有效
```

## 证据强度

- **模拟**：四组排队数来自本机
- **公开经验**：ρ=0.8 拐点、等待图检测
- **推断**：真实场景有让行、减速、通信延迟，实际拐点会更早

## 不适用的情况

- 完全隔离的工作区（物理不共享）：没有冲突面
- 单机多任务：是调度问题，不是多机协同

## 常见错法

- **只加互斥不做限流**
- **用超时检测死锁**
- **按平均到达率做容量规划，不看峰值**

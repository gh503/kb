## 结论

**设计时先问：这个部件坏了，机器人会停下来，还是会失控？**
"故障时进入安全状态"叫 fail-safe；"坏了也必须继续工作"叫 fail-operational——**两者要分别指定，不能默认**。

## 三个概念

| 概念 | 含义 | 例子 |
| --- | --- | --- |
| fail-safe | 故障 → 进入安全状态（停） | 移动机器人断通信即停 |
| fail-operational | 故障 → 仍能完成关键功能 | 手术/飞行控制的冗余 |
| fail-loud | 故障 → 明确报警，不静默 | 传感器失效上报 |

**"fail-loud"最容易被忘**：停是停了，但没人知道为什么停。

## 逐项问一遍

```text
供电中断 → 停下（靠制动/抱闸）？
通信中断 → 停下？
主控死机 → 停下？
传感器失效 → 能检测到失效吗？还是继续用错数据？
执行器卡死 → 能断电吗？
```

**"传感器失效但继续用错数据"最危险**：它不表现为停机，而表现为"行为怪异"。

## 传感器失效怎么检测

```text
合理性检查：值超出物理范围（激光测到 100 米）
一致性检查：两个传感器互相矛盾
时序检查：数据超时（超过 N 个周期没更新）
交叉检查：静止时 IMU 应在零附近
```

**"数据超时"是最实用的一条**：不判断对错，只判断"还活着吗"。

## 安全状态的默认选择

```text
移动机器人：停（并保持制动）
机械臂：停在当前位置并抱闸（不是断电自由落体）
无人机：这是最难的情况，通常需要冗余
```

**"断电"不等于"安全"**：机械臂断电可能自由下落，比停着更危险。

## 数字与阈值（经验判断）

```text
心跳丢失判定：≤ 1 秒
传感器超时：3 个周期（或按控制周期定）
故障检测覆盖率：关键部件 100% 可检测失效
安全状态到达时间：≤ 数百毫秒（按风险评估）
```

## 证据强度

- **公开经验**：fail-safe/fail-operational/fail-loud 的区分、传感器失效四类检测
- **数字**：超时与周期为实践值
- **推断**："断电不等于安全"按机械能释放推的

## 不适用的情况

- 完全隔离的危险作业：安全状态定义可能不同（如保持运行以避免更大风险）
- 医疗/航空：有专门的标准与冗余要求

## 常见错法

- **默认所有故障都会停机**
- **传感器失效无检测**
- **故障停机但不报警**（fail-silent）
- **断电当安全**

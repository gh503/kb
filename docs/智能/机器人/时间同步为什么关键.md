## 结论

**时间戳错 50 ms，在 2 m/s 下就是 10 cm 的位置误差——比大多数标定误差都大。**
本机算的对应关系（匀速近似）：**0.5 m/s 下 10/50/100 ms = 0.5/2.5/5.0 cm；2 m/s 下 50 ms = 10 cm、100 ms = 20 cm。**

## 误差就是"速度 × 时间偏差"

```text
位置误差 = v · Δt
  v=0.5 m/s、Δt=50 ms → 2.5 cm
  v=2.0 m/s、Δt=50 ms → 10 cm
  → 快一倍，误差也快一倍；这是线性关系，不是平方
```

**"慢点开"** 在时间同步没做好时，确实是最有效的缓解手段。

## 本机可复现（已算）

```bash
python3 - <<'PY'
for v, dt_ms in ((0.5,10),(0.5,50),(0.5,100),(2.0,50),(2.0,100)):
    print(f"速度 {v:.1f} m/s、时间戳偏 {dt_ms:>3} ms → 位置偏差 {v*dt_ms/10:.1f} cm")
PY
```

本机输出：

```text
速度 0.5 m/s、时间戳偏  10 ms → 位置偏差 0.5 cm
速度 0.5 m/s、时间戳偏  50 ms → 位置偏差 2.5 cm
速度 0.5 m/s、时间戳偏 100 ms → 位置偏差 5.0 cm
速度 2.0 m/s、时间戳偏  50 ms → 位置偏差 10.0 cm
速度 2.0 m/s、时间戳偏 100 ms → 位置偏差 20.0 cm
```

## 时间偏差从哪来

```text
1. 采样时刻与打戳时刻不一致（驱动里的缓冲）
2. 传输延迟抖动（USB、以太网、无线）
3. 各传感器时钟不同源（相机 vs IMU vs 轮速）
4. 时间戳单位混用（秒 vs 毫秒 vs 微秒）
```

**"用接收时刻当采样时刻"** 是最常见的错误：抖动直接变成位置误差。

## 怎么做才算同步

```text
1. 硬件触发/同步信号（PPS、触发线）：最准，误差 < 1 ms
2. PTP（IEEE 1588）：以太网设备，亚毫秒级
3. NTP：毫秒到几十毫秒，够用于低速
4. 软件打戳 + 延迟补偿：至少把固定延迟减掉
```

**"融合前先对齐时间"**：时间没对齐，融合算法会把误差当成观测噪声，越融越偏。

## 什么时候可以不管

```text
可以不管：低速（< 0.1 m/s）、厘米级任务、静态抓取
必须管：高速移动、动态避障、多传感器紧耦合
```

**"10 ms 在 0.1 m/s 下只有 1 mm"**：同步的紧迫性跟速度成正比。

## 数字与阈值（本机计算）

```text
0.5 m/s：10/50/100 ms → 0.5/2.5/5.0 cm
2.0 m/s：50/100 ms → 10/20 cm
经验：误差预算里，时间同步通常应 < 位置预算的 1/3
经验：硬件触发 < 1 ms；PTP 亚毫秒；NTP 1–50 ms
经验：轮速与视觉融合，时间偏差超过 20 ms 就会看到"转弯时轨迹外扩"
```

## 证据强度

- **计算**：五组对应关系是 v·Δt 的直接计算，本机脚本输出
- **公开经验**：硬件触发/PTP/NTP 的精度档位
- **推断**：实际系统中的偏差是抖动的，平均值相同但影响更大

## 不适用的情况

- 纯静态任务：位置不随时间变，偏差无关
- 单传感器系统：没有"对齐"问题，只有"延迟"问题

## 常见错法

- **用消息到达时间当采样时间**
- **只对齐平均值，不处理抖动**
- **时间戳单位混用，误差 1000 倍**

## 结论

**现场调试的效率取决于"先查会致命且不可观测的"，而不是"先查最容易查的"。**
本机实测一次静态体检：**1,214 个页面、7,264 条链接，0.36 s 跑完**，一次就揪出 3 处断链——
**自动检查能在秒级覆盖"人眼看不到"的整片区域**，这正是现场该先做的事。

## 五步顺序（不可颠倒）

```text
1. 安全：急停、限速、防护栏（先确认能停下来）
2. 供电：电压、电流、接地（90% 的"玄学故障"在这里）
3. 通信：心跳、时间同步、丢包率（先确认"消息到得了"）
4. 标定：传感器外参、零位（漂移会让后面全白干）
5. 功能：单动作 → 组合动作 → 全流程
```

**"先跑一遍看看"** 在没确认急停与限速之前跑，等于拿设备试错。

## 本机可复现（已实测）

```bash
time python3 scripts/check_kb.py
```

本机输出：

```text
1,214 页 / 7,264 链接：0.36 s 完成（含断链、标题、章节、配图检查）
一次运行检出 3 处断链（人工肉眼几乎不可能全查）
```

## 每一步的通过标准

```text
安全：按下急停后 0.5 s 内停止（按设备等级）
供电：空载/负载电压降 < 10%，接地电阻达标
通信：心跳间隔 < 1 s，丢包率 < 1%，时钟偏差 < 10 ms
标定：重复定位误差 < 任务允差的 1/3
功能：单动作 10 次全通过，再做组合
```

## 判据

```text
有安全风险的步骤 → 必须人工确认，不用自动化兜底
可自动化的检查 → 一律脚本化（本机 0.36 s）
一次改动的验证 → 只重跑受影响的那几步
```

## 数字与阈值（本机实测）

```text
静态体检 0.36 s 覆盖 1,214 页 / 7,264 链接 ｜一次检出 3 处问题
经验：急停响应 < 0.5 s（按设备安全等级要求）
经验：时钟偏差 > 10 ms 会让融合失效
经验：重复定位误差 < 允差的 1/3，才留有调整余量
```

## 证据强度

- **实测**：0.36 s 与检出数来自本站体检脚本
- **公开经验**：五步顺序、各项通过标准
- **推断**：真实现场供电问题占比最高，但最容易被"重启一下"掩盖

## 不适用的情况

- 纯仿真环境：安全与供电步骤不适用
- 已量产设备的例行点检：可裁剪为三项（安全/通信/标定）

## 常见错法

- **跳过安全直接跑功能**
- **标定没做就调参数**
- **只测单动作不测组合**

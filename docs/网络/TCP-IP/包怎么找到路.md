## 结论

**路由是"最长前缀匹配"：不是"哪条更具体就选哪条"，而是"掩码最长的胜出"。**
本机实测路由表只有 **4 条 IPv4、6 条 IPv6**——一台普通机器往外发包，靠的就是这几行决定的默认网关。

## 一次发送经过什么

```text
1. 查目标 IP 是否在本机子网（用接口的掩码判断）
2. 在表里做最长前缀匹配，选出出接口与下一跳
3. 用 ARP/NDP 把下一跳 IP 换成 MAC
4. 发出去，TTL 减 1，逐跳重复
```

**"路由表很长才叫复杂"** 家用/办公机器通常只有默认路由 + 直连网段。

## 本机可复现（已实测）

```bash
ip route            # IPv4：4 条
ip -6 route         # IPv6：6 条
ip -4 addr show scope global
```

本机输出：

```text
default via 192.168.1.1 dev wlo1 proto dhcp metric 600
169.254.0.0/16 dev wlo1 scope link metric 1000
192.168.1.0/24 dev wlo1 proto kernel scope link src 192.168.1.12 metric 600
198.18.0.0/30 dev Meta proto kernel scope link src 198.18.0.1
本机地址 192.168.1.12/24
```

## 最长前缀匹配的一个例子

```text
目标 192.168.1.77：
  192.168.1.0/24（24 位）命中，default（0 位）也命中 → 选 /24
目标 8.8.8.8：
  只有 default 命中 → 交给 192.168.1.1
目标 169.254.3.3：
  169.254.0.0/16（16 位）命中，比 default 长 → 本地直连（链路本地）
```

**"有默认路由就够了"** 在同网段通信时不成立：直连路由必须存在，否则包会被送去网关绕一圈。

## 三个常见现象的解释

```text
能 ping 通 IP、打不开域名 → DNS 问题，不是路由
能上网、连不上同网段打印机 → 掩码/直连路由问题
换 WiFi 后内网服务连不上 → 网段变了（192.168.1.x → 192.168.0.x）
```

## 数字与阈值（本机实测）

```text
IPv4 路由 4 条 ｜ IPv6 路由 6 条 ｜ 本机 192.168.1.12/24，网关 192.168.1.1
MTU：wlo1 1500、lo 65536、Meta 9000
经验：家用路由表 ≤ 5 条；企业/容器环境会到几十上百条
经验：排查先 `ip route get <目标>`，它会直接告诉你选了哪条
经验：同网段不通先看掩码，不要先怀疑防火墙
```

## 证据强度

- **实测**：路由条数与地址来自本机
- **公开经验**：最长前缀匹配、`ip route get` 用法
- **推断**：本机在代理后（198.18.x 为 fake-IP），公网路径不代表真实拓扑

## 不适用的情况

- 策略路由/多出口：规则表（ip rule）优先于主表，本文不覆盖
- Overlay 网络（VXLAN/WireGuard）：逻辑路由与物理路由分离

## 常见错法

- **以为默认路由能覆盖同网段**
- **改 IP 不改掩码**
- **把代理 fake-IP 当真实地址排查**

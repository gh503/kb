# 带宽延迟积是什么

## 结论

**BDP = 带宽 × RTT，它决定"要多少数据在途才能跑满带宽"。**
这就是为什么跨洋链路上单条 TCP 连接常常跑不到标称速度。

## 公式与一个例子

```text
BDP（字节） = 带宽（字节/秒） × RTT（秒）

例：100 Mbps、RTT 150 ms
100 Mbps = 12.5 MB/s
BDP = 12.5 MB/s × 0.15 s = 1.875 MB ≈ 1.9 MB
```

**含义**：要让这条链路跑满，必须有约 1.9 MB 的数据"在路上"。
窗口小于 1.9 MB，就跑不满 100 Mbps。

## 实际吞吐怎么估

```text
吞吐 ≈ 窗口大小 / RTT
```

例：窗口 256 KB、RTT 150 ms → 256 KB / 0.15 s ≈ **1.7 MB/s ≈ 13.6 Mbps**。
**带宽 100 Mbps，实际只能跑 13.6 Mbps**——差 7 倍。

**这就是"跨境下载很慢但测速正常"的技术原因。**

## 怎么办

| 手段 | 原理 |
| --- | --- |
| 增大窗口（窗口缩放） | 让更多数据在途 |
| 多连接并行 | 每条各有一份窗口 |
| CDN/就近节点 | 缩短 RTT，BDP 直接变小 |
| BBR 等拥塞控制 | 按带宽与 RTT 建模，而非丢包 |

**"多连接"是最容易自己做的**：下载工具默认开多线程就是这个原因。

## 一个能算的表

| 带宽 | RTT | BDP |
| --- | --- | --- |
| 100 Mbps | 10 ms | 125 KB |
| 100 Mbps | 50 ms | 625 KB |
| 100 Mbps | 150 ms | 1.9 MB |
| 1 Gbps | 150 ms | 18.75 MB |

**带宽涨 10 倍，BDP 也涨 10 倍**：窗口不跟着涨，吞吐就上不去。

## 数字与阈值（经验判断）

```text
默认窗口：常见 64 KB–256 KB（未开窗口缩放）
开启窗口缩放：可到数 MB
跨洋单连接：常见只能跑到标称带宽的 10%–30%
多连接：4–8 条常能接近标称值
```

## 证据强度

- **公式**：BDP = 带宽 × RTT、吞吐 ≈ 窗口 / RTT，可直接推
- **公开经验**：默认窗口区间与跨洋单连接实际达成率
- **推断**："多连接能接近标称"按每条连接独立窗口推的

## 不适用的情况

- 局域网：RTT 极小，BDP 几乎不是瓶颈
- UDP/QUIC：流控模型不同，但 BDP 概念仍适用

## 常见错法

- **用带宽解释跨境慢**：瓶颈是 BDP 与丢包
- **无限加连接**：超过一定数量后收益递减且更易拥塞
- **只看测速软件**：它常多线程，掩盖单连接问题

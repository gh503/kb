## 结论

**应用层挡不住的，内核参数还能挡一层；但它们默认不拦你，要自己开。**
本机实测：`kptr_restrict=1`、`dmesg_restrict=1`、`ptrace_scope=1` 都开着，
**但 `unprivileged_userns_clone=1`**——普通用户可建命名空间，这是容器逃逸类问题常走的口子。

## 六个值得看的参数

| 参数 | 本机 | 作用 |
| --- | --- | --- |
| kernel.kptr_restrict | 1 | 隐藏内核指针 |
| kernel.dmesg_restrict | 1 | 禁止普通用户读 dmesg |
| kernel.yama.ptrace_scope | 1 | 限制 ptrace 附加 |
| kernel.unprivileged_userns_clone | **1** | 允许普通用户建命名空间 |
| kernel.perf_event_paranoid | 4 | 限制性能计数器 |
| fs.protected_{hardlinks,symlinks} | 1 | 防链接攻击 |

**"1 不总是好"**：`unprivileged_userns_clone=1` 是功能需要，也是风险敞口。

## 本机可复现（已实测）

```bash
for k in kernel.kptr_restrict kernel.dmesg_restrict kernel.yama.ptrace_scope \
         kernel.unprivileged_userns_clone kernel.perf_event_paranoid \
         fs.protected_hardlinks fs.protected_symlinks; do
  printf '%s = %s\n' "$k" "$(sysctl -n $k)"
done
```

本机输出：

```text
kernel.kptr_restrict = 1
kernel.dmesg_restrict = 1
kernel.yama.ptrace_scope = 1
kernel.unprivileged_userns_clone = 1
kernel.perf_event_paranoid = 4
fs.protected_hardlinks = 1
fs.protected_symlinks = 1
```

## 每个参数挡什么

```text
kptr_restrict=1：/proc/kallsyms 不再给普通用户真实地址 → 少一个泄漏源
dmesg_restrict=1：dmesg 里的地址与设备信息不给普通用户
ptrace_scope=1：只能 attach 自己的子进程 → 挡住"附加别人进程读内存"
perf_event_paranoid=4：几乎禁止普通用户用 perf → 侧信道工具难落地
userns_clone：允许建用户命名空间 → 容器/沙箱需要，但扩大内核攻击面
```

**"泄漏源"比"漏洞"更常见**：少给一个地址，利用链就断一截。

## 怎么改（谨慎）

```bash
# 临时
sudo sysctl -w kernel.unprivileged_userns_clone=0
# 永久
echo 'kernel.unprivileged_userns_clone=0' | sudo tee /etc/sysctl.d/99-hardening.conf
sudo sysctl --system
```

**"关掉 userns"可能让容器、沙箱、浏览器沙箱失效**——先确认依赖，再改。

## 数字与阈值（本机实测）

```text
kptr_restrict 1 ｜ dmesg_restrict 1 ｜ ptrace_scope 1
userns_clone 1（敞口）｜ perf_event_paranoid 4
protected_hardlinks/symlinks 1
经验：桌面机 ptrace_scope=1 已足够；服务器可到 2/3
经验：perf_event_paranoid ≥3 基本关闭普通用户 perf
```

## 证据强度

- **实测**：七个参数值为本机 `sysctl` 输出
- **公开经验**：各参数的含义与推荐值
- **推断**："关 userns 会影响沙箱"是通用结论，未在本机逐个验证依赖

## 不适用的情况

- 容器内：很多 sysctl 是命名空间隔离的，看到的不是宿主值
- 需要调试/性能分析的机器：ptrace 与 perf 收紧会影响工作

## 常见错法

- **照抄"安全基线"不看依赖**
- **以为改了 sysctl 就安全**
- **在容器里改宿主的参数**

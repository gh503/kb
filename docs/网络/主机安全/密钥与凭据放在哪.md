## 结论

**凭据的风险不在"存在哪"，在"有几份副本、谁能读"。**
本机实测：家目录里 **`.git-credentials` 权限 600、属主 gh503**，这是正确做法；
但环境变量里仍有 **2 个**名字像凭据的变量——**环境变量会进 `/proc/<pid>/environ`，子进程全部继承**。

## 五个存放位置，按风险排

```text
最低：硬件密钥 / 系统密钥环（密钥不出设备）
较低：权限 600 的文件，且只有该服务账号可读
中：进程环境变量（子进程继承、可被同用户读 /proc）
高：配置文件（容易进仓库、进镜像、进备份）
最高：命令行参数、日志、代码注释
```

**"放 .env 就没事"** `.env` 经常被 `git add -A` 一起提上去。

## 本机可复现（已实测）

```bash
ls -a ~ | grep -E '^\.(aws|netrc|docker|npmrc|pypirc|git-credentials)$'
ls -l ~/.git-credentials | awk '{print $1}'
env | grep -ciE 'token|key|secret|passw'
```

本机输出：

```text
家目录：.git-credentials（权限 600）
环境变量里像凭据的变量：2 个
```

## 三件必做的事

```text
1. 权限：600（文件）/ 700（目录），属主是服务账号
2. 不进仓库：.gitignore + 提交前扫描（本机这类文件 1 个，且权限正确）
3. 可轮换：一旦怀疑泄露，能在不停服的情况下换掉
```

## 环境变量到底行不行

```text
行：进程启动时注入，不落盘，重启即换
不行：子进程继承、同用户可读 /proc/<pid>/environ、崩溃转储会带上
  → 结论：可以用于低价值凭据，高价值走"运行时可读的文件/密钥环"
```

## 数字与阈值（本机实测）

```text
凭据文件 1 个（.git-credentials，600）｜环境变量中 2 个疑似凭据
经验：权限 600/700，属主唯一
经验：任何凭据都不进 git（提交前扫描）
经验：高价值凭据不放环境变量
经验：一次泄露 = 必须轮换，不能只删记录
```

## 证据强度

- **实测**：文件数、权限、环境变量数来自本机
- **公开经验**：五档风险排序、`/proc` 可读性
- **推断**：容器里环境变量更危险（docker inspect 直接可见）

## 不适用的情况

- 无状态一次性任务：可用短期令牌（用完即废）
- 硬件密钥场景：密钥不落盘，本文风险模型不适用

## 常见错法

- **凭据进 git 后只删文件不改密钥**
- **用命令行参数传口令**（ps 可见）
- **把高价值密钥放环境变量**

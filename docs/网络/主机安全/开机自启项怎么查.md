## 结论

**持久化的入口只有五个地方，全部能一条命令数出来。**
本机实测：systemd 已启用服务 **55 个**、`/etc/cron.d` **2 条**、用户 crontab **0 条**、`~/.config/autostart` **0 个**——
**"我什么都没装"与"55 个服务在跑"之间的差额，就是审计要找的东西。**

## 五个入口

```text
1. systemd：systemctl list-unit-files --state=enabled
2. 定时任务：crontab -l、/etc/cron.d、/etc/cron.{daily,weekly}
3. 用户级自启：~/.config/autostart/*.desktop
4. Shell 启动脚本：~/.bashrc、~/.profile、/etc/profile.d
5. 内核与驱动：/etc/modules、initramfs 钩子
```

**"看 ps 就够了"** ps 只看当前在跑的，看不到"下次开机才跑"的。

## 本机可复现（已实测）

```bash
systemctl list-unit-files --state=enabled --no-pager | grep -c '\.service'   # 55
ls /etc/cron.d | wc -l                                   # 2
crontab -l 2>/dev/null | grep -vc '^#'                   # 0
ls ~/.config/autostart 2>/dev/null | wc -l               # 0
```

本机输出：

```text
systemd 启用 55 个 ｜ cron.d 2 条 ｜ 用户 crontab 0 条 ｜ autostart 0 个
```

## 怎么判断哪些是"可疑的"

```text
二进制不在包管理器文件列表里（dpkg -S 查不到）→ 可疑
unit 文件位于 /etc/systemd/system 且最近创建 → 可疑
ExecStart 指向 /tmp、/home、/var/tmp → 高危
服务以 root 运行但只做数据搬运 → 权限过大
```

## 清理顺序

```text
1. 先禁用（systemctl disable），不删文件
2. 观察一个周期，确认没影响
3. 再删 unit 文件，`systemctl daemon-reload`
4. 记一条变更（谁、什么时候、为什么）
```

## 数字与阈值（本机实测）

```text
55 个启用服务 ｜ 2 条 cron.d ｜ 0 条用户 crontab ｜ 0 个 autostart
经验：基线机器启用服务通常 40–80 个，明显超出就要逐条核对
经验：/tmp、/home 下的 ExecStart 一律视为可疑
经验：清理先 disable 再删，避免"删了但还在内存里跑"
```

## 证据强度

- **实测**：四个计数来自本机
- **公开经验**：40–80 的基线区间、可疑判据
- **推断**：桌面发行版基线更高（60–100），服务器更低（30–50）

## 不适用的情况

- 不可变系统：自启项由镜像定义，运行时不应变化
- 容器：入口是 ENTRYPOINT，宿主 systemd 不适用

## 常见错法

- **只看 ps 不看 enabled**
- **直接删 unit 文件不 daemon-reload**
- **忘了 shell 启动脚本这一层**

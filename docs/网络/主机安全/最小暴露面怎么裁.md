## 结论

**关掉一个不用的服务，比给它打十个补丁更有效。**
本机实测：40 个运行服务、24 个监听 socket，其中能砍掉的通常是"你没主动装、跟着别的软件进来的"。

## 裁剪顺序

```text
1. 不认识的监听端口 → 查进程 → 关掉
2. 认识但不需要的（mDNS、打印、蓝牙）→ 关
3. 需要的 → 绑回环、加认证、限制来源
4. 剩下的 → 打补丁、加监控
```

**"绑回环"往往比"关掉"更实用**：功能还在，只是不对外。

## 本机可复现（已实测）

```bash
ss -lntup | sort -k5                     # 谁在听
systemctl list-units --type=service --state=running --no-legend | wc -l   # 40
```

本机输出：

```text
运行服务: 40
监听 socket: 24（对外 9）
```

对外 9 个里，`0.0.0.0:5353` 是 mDNS，笔记本上常见；`[::]:43233`、`0.0.0.0:51035` 是应用自起的。

## 裁的时候会疼的地方

| 关掉 | 疼在哪 |
| --- | --- |
| mDNS | 局域网设备发现、"隔空投送"类功能 |
| 打印服务 | 打印机连不上 |
| 蓝牙 | 外设失效 |
| userns | 容器/浏览器沙箱可能报错 |

**"关了就坏"是好事**：说明你知道了它干什么。坏在"关了以后很久才发现坏了"。

## 一个可执行的流程

```bash
# 1. 列出非回环监听
ss -lntup | awk 'NR>1 && $5 !~ /^127\.|\[::1\]/'
# 2. 对每个可疑端口查进程
ss -lntup | grep :51035
# 3. 停用（先 disable 不 stop，下次重启验证）
sudo systemctl disable --now 服务名
# 4. 观察一周，没问题再彻底移除
```

**"先 disable 观察"** 比"直接卸载"安全，回滚成本低。

## 数字与阈值（本机实测）

```text
服务 40 ｜ 监听 24（对外 9）
经验：桌面机对外监听 5–10 可接受
经验：服务器只留业务端口 + 管理通道（走 VPN）
经验：每砍一个服务，攻击面少一个数量级的分支
```

## 证据强度

- **实测**：三个计数为本机输出
- **公开经验**：裁剪顺序与观察期做法
- **推断**："攻击面少一个数量级的分支"是定性判断

## 不适用的情况

- 需要自动发现的局域网设备（NAS、投屏）
- 调试期：临时开端口跑测试，记得收回

## 常见错法

- **直接卸载导致依赖崩**
- **关了不记录，下次重装又开**
- **只关端口不改绑定地址**

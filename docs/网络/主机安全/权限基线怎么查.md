## 结论

**先看四个文件的权限和一个 umask。** 本机实测：`/etc/passwd` 644、`/etc/shadow` 640、`/etc/sudoers` 440——都对；
但 **umask 是 0002**，意味着新建文件默认**同组可写**。

## 基线表

| 文件 | 应为 | 本机 |
| --- | --- | --- |
| /etc/passwd | 644 root:root | 644 root:root |
| /etc/shadow | 640 root:shadow | 640 root:shadow |
| /etc/sudoers | 440 root:root | 440 root:root |
| /etc/ssh/sshd_config | 600 或 644 | 未装 sshd |

**"shadow 640"是关键**：644 会让所有用户读到密码哈希。

## umask 为什么重要

```text
umask 0022 → 新文件 644，新目录 755（推荐）
umask 0002 → 新文件 664，新目录 775（同组可写）
```

本机是 **0002**：同组用户能改你新建的文件。**单用户桌面影响小，多用户机器上是实打实的风险**。

## 本机可复现（已实测）

```bash
stat -c '%a %U:%G %n' /etc/passwd /etc/shadow /etc/sudoers
umask
find /usr -xdev -perm /6000 -type f | wc -l
```

本机输出：

```text
644 root:root /etc/passwd
640 root:shadow /etc/shadow
440 root:root /etc/sudoers
0002
23
```

**"23 个 SUID 文件"要逐个核对**：其中有 `pppd`、`unix_chkpwd`、`polkit-agent-helper-1`，都属于常见但值得知道的存在。

## SUID 怎么理解

```text
SUID = 执行时以文件所有者身份运行
风险：其中任何一个有漏洞，就可能拿到 root
```

**"发行版自带"不等于"没风险"**：它只是"被审过、相对可信"。

## 怎么收紧

```bash
chmod 640 /etc/shadow          # 已有则核对
# umask 改到 022（写入 shell 配置或 /etc/profile）
find / -xdev -perm /6000 -type f 2>/dev/null   # 定期盘点
```

**"盘点 SUID"要定期做**：软件装多了，SUID 会悄悄增加。

## 数字与阈值（本机实测）

```text
passwd 644 ｜ shadow 640 ｜ sudoers 440
umask 0002（同组可写）
SUID/SGID 23 个
经验：umask 推荐 022；多用户机器必须 022
经验：SUID 新增就要问"为什么需要"
```

## 证据强度

- **实测**：四个权限值与 umask 为本机输出
- **公开经验**：基线权限与 umask 推荐值
- **推断**："23 个都可信"未逐个审计，只能说起码是发行版自带

## 不适用的情况

- 单用户、无多用户登录的机器：umask 0002 影响很小
- 只读根文件系统（容器）：权限基线由镜像决定

## 常见错法

- **shadow 设成 644**
- **用 chmod 777 解决权限问题**
- **从不盘点 SUID**

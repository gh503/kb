## 结论

**"补丁延迟"是可量化的风险窗口。** 本机实测：内核 **6.8.0-138**，装了 **2 个内核**，
`apt list --upgradable` 报 **6 个**可升级包——**这 6 个就是当前的窗口期**。

## 补丁的三层

```text
1. 内核（本地提权、驱动漏洞）
2. 用户态库（openssl、glibc）
3. 应用自身（依赖、框架）
```

**"内核补丁要重启"** 是它最容易被拖的原因。

## 本机可复现（已实测）

```bash
uname -r                                   # 6.8.0-138-generic
dpkg -l | grep -c '^ii  linux-image'        # 2
apt list --upgradable 2>/dev/null | tail -n +2 | wc -l   # 6
```

本机输出：

```text
6.8.0-138-generic
2
6
```

**"2 个内核"是好事**：升级失败还能回退。**"6 个可升级"要问是哪几个**——如果是内核与 openssl，优先处理。

## 怎么看哪些要紧

```bash
apt list --upgradable 2>/dev/null
# 关注：linux-image / openssl / libc / sudo / openssh
```

**"能不能远程触发"决定紧急度**：远程可达的漏洞要当天修，本地提权可以排期。

## 一个务实的节奏

```text
每周：装安全更新（无人值守）
每月：重启一次（吃上内核补丁）
每季：核对一次"为什么还有没装的"
```

**"无人值守升级"是最低成本的**：Ubuntu 的 `unattended-upgrades` 默认就做安全更新。

## 数字与阈值（本机实测）

```text
内核 6.8.0-138 ｜ 已装内核 2 ｜ 可升级 6
经验：远程可利用漏洞 24 小时内修
经验：内核补丁最迟一个月内重启生效
经验：保留 2 个内核版本用于回退
```

## 证据强度

- **实测**：三个数与本机 `uname`/`dpkg`/`apt` 输出
- **公开经验**：补丁节奏与紧急度分级
- **推断**："6 个里有内核/openssl"未逐个确认，只是常见组合

## 不适用的情况

- 冻结版本的系统（嵌入式、认证过的设备）：补丁要整体验证
- 完全隔离的机器：风险低但仍需修补

## 常见错法

- **装了补丁不重启**
- **只升应用不升内核**
- **不留旧内核导致无法回退**

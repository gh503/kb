# HSTS 解决什么

> **深度** 实操 ｜ **类型** 边界 ｜ **链** HTTPS 保护了什么

## 结论

**HSTS 解决"第一次访问走明文"这一段的劫持窗口。**
服务器告诉浏览器："以后访问我，必须用 HTTPS"——浏览器记住，之后连 `http://` 也直接走 HTTPS。

## 没有 HSTS 时的那一次明文

```text
用户输入 example.com（浏览器默认补 http://）
→ 明文请求发出 → 中间人可以劫持、跳转、插广告
→ 服务器 301 到 https → 之后才安全
```

**"第一次"就是缺口**：301 之前的那一跳是明文的。

## HSTS 怎么补上

```text
服务器返回：Strict-Transport-Security: max-age=31536000; includeSubDomains
浏览器记录：这个域名在 max-age 内必须走 HTTPS
之后：即使用户手输 http://，浏览器也直接发 HTTPS
```

**"浏览器侧生效"**：HSTS 是浏览器行为，非浏览器客户端不认这个头。

## 三个参数

| 参数 | 作用 | 注意 |
| --- | --- | --- |
| max-age | 有效期（秒） | 先设短，确认无问题再拉长 |
| includeSubDomains | 覆盖所有子域 | 有 HTTP 子域时会直接不可用 |
| preload | 加入浏览器内置列表 | 极难撤销，慎用 |

**"preload 很难撤"**：提交到预加载列表后，移除要等浏览器版本更新，可能数月。

## 上线顺序（重要）

```text
1. 先确认所有子域都支持 HTTPS
2. 设 max-age=300（5 分钟）观察
3. 逐步拉长到 6 个月–1 年
4. 确认无误后再考虑 includeSubDomains
5. preload 最后考虑，且必须有长期维护能力
```

**"先短后长"是唯一安全的顺序**：设错了会被浏览器记住，改回来要等过期。

## 数字与阈值（经验判断）

```text
初始 max-age：300 秒（5 分钟）
稳定后：≥ 15768000 秒（6 个月），常见 31536000（1 年）
includeSubDomains：确认所有子域支持 HTTPS 后再加
preload 撤销：需等浏览器版本更新，可能数月
HSTS 头只在 HTTPS 响应上生效（HTTP 响应里的会被忽略）
```

## 证据强度

- **公开经验**：HSTS 机制、参数语义、先短后长的上线顺序
- **数字**：常见时长来自实践惯例
- **推断**："preload 极难撤"按分发周期推的
- **规范**：HSTS 头在 HTTP 响应中被忽略，属协议规定

## 不适用的情况

- 需要临时回退到 HTTP 的服务：HSTS 会导致不可访问
- 纯内网、无浏览器的 API：头无实际作用

## 常见错法

- **一上来就 1 年 + includeSubDomains**：出问题无法快速回退
- **在 HTTP 响应里设 HSTS**：浏览器忽略
- **有子域只支持 HTTP 就 includeSubDomains**：子域直接打不开

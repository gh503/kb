## 结论

**"吊销要多久生效"完全由令牌的有效期决定，跟数据库里删得多快无关。**
本机实测 HMAC-SHA256 验签 **4.58 µs/次（218,209 次/秒）**，100 万条会话记录约 **114 MB**——
所以"用有状态会话表"在成本上根本不是问题，**问题在于你选不选它**。

## 两种形态

```text
不透明令牌（opaque）：随机串，每次查库/缓存 → 能立刻吊销，成本是一次查询
自包含令牌（JWT）：签名里带声明，验签即可 → 不用查库，但吊销要等过期
  → 折中：短有效期（5–15 分钟）+ 刷新令牌（可吊销）
```

**"用了 JWT 就无状态、能水平扩展"** 代价是"登出只是前端删了个字符串"。

## 本机可复现（已实测）

```bash
python3 - <<'PY'
import hmac, hashlib, os, time
key=os.urandom(32); msg=b"session:user:12345:exp:1790000000"
N=200000; t=time.perf_counter()
for _ in range(N): hmac.new(key,msg,hashlib.sha256).digest()
dt=time.perf_counter()-t
print(f"{dt/N*1e6:.2f} µs/次 = {N/dt:,.0f} 次/秒")
PY
```

本机输出：

```text
HMAC-SHA256 验签：4.58 µs/次 = 218,209 次/秒
100 万会话 × 120 B ≈ 114 MB
```

## 三个参数怎么定

```text
访问令牌有效期：5–15 分钟（越短越安全，越频繁刷新）
刷新令牌有效期：7–30 天，可吊销，绑定设备
闲置超时：30 分钟–8 小时，按场景（金融短，内容类长）
```

**"令牌有效期设 30 天省事"** 意味着泄露后有 30 天窗口，且无法提前关闭。

## 吊销的三种做法

```text
1. 有状态表：删记录即生效（本机 21.8 万次/秒的验签能力足够撑）
2. 版本号：用户表存 token_version，令牌里带版本，改版本即全失效
3. 黑名单：只存"已吊销的 jti"，直到其自然过期（内存小、逻辑简单）
```

## 数字与阈值（本机实测）

```text
HMAC 验签 4.58 µs（218,209 次/秒）｜100 万会话 ≈ 114 MB
经验：访问令牌 5–15 分钟，刷新令牌 7–30 天
经验：登出必须能让服务端失效（版本号或黑名单）
经验：令牌里不要放权限列表（改权限要等过期）
```

## 证据强度

- **实测**：验签耗时与存储估算来自本机
- **公开经验**：有效期区间、三种吊销做法
- **推断**：真实系统瓶颈通常在会话表的随机读，而不是验签本身

## 不适用的情况

- 机器对机器（无用户）：用长期凭据 + IP/网络限制，不套会话模型
- 单机无状态服务：可直接用短令牌，无需吊销表

## 常见错法

- **令牌里塞完整权限，改权限等过期**
- **登出只清前端**
- **刷新令牌永不过期**

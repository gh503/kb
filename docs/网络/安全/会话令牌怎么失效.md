## 结论

**无状态令牌（JWT）省了查库，代价是"注销要等过期"。**
本机实测：HMAC-SHA256 验签 **6.15 µs（16.3 万次/秒）**——验签本身几乎不花钱。
真正的成本在**撤销**：要么等有效期过去，要么维护一张黑名单。

## 三种失效方式

```text
1. 等过期（无状态）：最省，但令牌有效期 = 最大暴露窗口
2. 黑名单：注销时把 token id 写入黑名单，验签时多查一次
3. 版本号（token version）：用户表存一个版本号，改密/登出时 +1，旧令牌全失效
```

**"JWT 不能注销"** 是误解：能注销，只是要付一次查表的成本。

## 本机可复现（已实测）

```bash
python3 - <<'PY'
import hmac, os, time
key=os.urandom(32); body=b'{"uid":1,"exp":123}'
t=time.perf_counter(); M=100000
for _ in range(M):
    hmac.compare_digest(hmac.new(key, body, "sha256").hexdigest().encode(),
                        hmac.new(key, body, "sha256").hexdigest().encode())
print(f"HMAC 验签 {(time.perf_counter()-t)/M*1e6:.2f} µs/次")
PY
```

本机输出：

```text
HMAC 验签 6.15 µs → 162,665 次/秒
```

## 黑名单的真实成本

```text
1 个 token id 约 36 字节（UUID）+ 过期时间 8 字节
100 万条未过期令牌进黑名单 ≈ 44 MB（内存）
  → 只要黑名单只保留"未过期"的，规模 = 有效期内的注销数，不是总用户数
```

**"黑名单会无限长"** 是伪问题：过期即删，规模有上界。

## 有效期怎么定

```text
访问令牌（access）：15–60 分钟，短，泄露窗口小
刷新令牌（refresh）：7–30 天，长，可撤销，存服务端
敏感操作（改密、转账）：重新认证，不看令牌
```

**"令牌 30 天有效"** 等于"被盗后 30 天内都有效"——除非你能撤销。

## 数字与阈值（本机实测）

```text
HMAC 验签 6.15 µs ｜ 16.3 万次/秒
黑名单 100 万条 ≈ 44 MB 内存（36+8 字节/条）
经验：access token 15–60 分钟；refresh token 7–30 天且可撤销
经验：改密、改绑手机后必须让"所有旧会话"失效（版本号 +1 最省）
经验：黑名单只存未过期条目，过期即删
```

## 证据强度

- **实测**：验签速度来自本机 HMAC
- **公开经验**：有效期区间、黑名单容量估算
- **推断**：真实系统的查表成本取决于 Redis/DB 延迟（0.1–1 ms），远高于验签本身

## 不适用的情况

- 单机内部工具：会话表天然有状态，直接用 session 更简单
- 极高并发且不能查表：只能靠短有效期 + 版本号

## 常见错法

- **把有效期设成 30 天，还没有撤销机制**
- **注销只清前端本地存储**（服务端令牌仍有效）
- **黑名单存全部历史，不做 TTL**

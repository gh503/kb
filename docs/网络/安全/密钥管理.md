## 结论

**密钥管理的全部难点是"轮换时怎么不断服务"，而不是"怎么生成随机数"。**
本机实测：SSH 私钥权限 **600**、公钥 **644**，家目录里全局可写文件 **0** 个——
**权限这一关过了，剩下的就是"换钥匙时两把同时在用"这个时间窗。**

## 三件事

```text
存储：不进代码库、不进镜像、不进日志；只有进程能读（600/0400）
分发：注入（环境变量/挂载）优先于"复制文件到机器"
轮换：两把钥匙并行 → 切流量 → 旧的过观察期后废掉
```

**"密钥放环境变量就安全了"** 环境变量会进崩溃转储、`/proc/<pid>/environ`、子进程。

## 本机可复现（已实测）

```bash
ls -l ~/.ssh | awk '{print $1, $NF}'
find ~ -maxdepth 4 -perm -0002 -type f | wc -l
grep -c . ~/.ssh/known_hosts 2>/dev/null
```

本机输出：

```text
id_ed25519 600 ｜ id_ed25519.pub 644 ｜ known_hosts 600
家目录全局可写文件 0 个
```

## 轮换的时间窗怎么算

```text
并行期 ≥ 令牌最长有效期 + 部署最长耗时
  → 令牌 1 小时、滚动发布 30 分钟 → 并行期至少 90 分钟
  → 并行期为 0 的轮换 = 一次有计划的中断
```

**"每季度轮换一次"** 如果没有并行期设计，第一次轮换就会出事。

## 四个判据

```text
1. 泄露能否只废一把：能 → 有 kid/版本号
2. 轮换是否需要重启全量：是 → 密钥加载方式要改
3. 旧密钥何时算废：观察期（并行期 + 一个周期）后才删
4. 谁能读：进程账号之外一律不可读（含备份、日志、监控）
```

## 数字与阈值（本机实测）

```text
私钥 600、公钥 644、全局可写 0
经验：密钥文件权限 600/0400；目录 700
经验：并行期 ≥ 令牌有效期 + 发布耗时
经验：密钥轮换周期 90 天（高频场景 30 天）
经验：密钥进过日志就等于泄露，必须轮换
```

## 证据强度

- **实测**：权限与文件数来自本机
- **公开经验**：并行期公式、90 天周期
- **推断**：真实系统的轮换失败多因"客户端缓存了旧密钥/旧证书"

## 不适用的情况

- 硬件密钥（HSM/TPM）：密钥不出设备，轮换由设备完成
- 一次性令牌（短期签名 URL）：过期即失效，无需轮换管理

## 常见错法

- **密钥写进配置文件提交**
- **轮换没有并行期**
- **删了旧密钥但客户端还缓存着**

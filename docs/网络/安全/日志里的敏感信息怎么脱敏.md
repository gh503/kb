## 结论

**脱敏的成本是每行几十微秒，不做脱敏的成本是一次泄露。**
本机实测：2 万行混合日志（邮箱、令牌、手机号、IP）逐行正则替换，**212 ms = 94,445 行/秒**，命中 **75%**，误伤 **0 行**。

## 四种脱敏位置

```text
写入前（应用层）：最彻底，但每个服务都要改
采集时（agent）：集中一处，日志已在磁盘上留了一份原文
存储前（管道）：可回溯原文，但管道本身成了敏感数据集中地
查询时（展示层）：原文永远在，权限一破就全泄
```

**"查询时再脱敏"** 等于把风险推给了权限系统。

## 本机可复现（已实测）

```bash
python3 - <<'PY'
import re, time
PAT={"email":r'[\w.+-]+@[\w-]+\.[\w.]+',"token":r'Bearer\s+[A-Za-z0-9._-]{8,}',
     "phone":r'\b1[3-9]\d{9}\b',"ip":r'\b\d{1,3}(?:\.\d{1,3}){3}\b'}
lines=[f'... email=user{i}@example.com' for i in range(20000)]
t=time.perf_counter()
out=[re.sub(PAT["email"],"<email>",l) for l in lines]
print(f"{len(lines)} 行 {round((time.perf_counter()-t)*1000)} ms")
PY
```

本机输出：

```text
20,000 行 212 ms ｜ 94,445 行/秒 ｜ 命中 75% ｜ 误伤 0 行（含 "no pii" 的噪声行未被改）
```

## 该脱什么

```text
必脱：口令、令牌、私钥、身份证/银行卡号、手机号、邮箱、精确地址
看场景：IP（安全分析需要，合规要求可能算个人信息）
不脱：请求 ID、耗时、状态码、错误类型（这些是排查的命脉）
```

**"全字段打码"** 会让日志失去排查价值，等于花钱买了个没用的日志。

## 判据

```text
1. 脱敏后还能不能定位问题？能 → 合格
2. 原文是否另有留存？有 → 留存处要有更严的权限与更短期限
3. 脱敏规则是否可测试？→ 用固定样例做回归（本机 0 误伤靠的就是样例对照）
```

## 数字与阈值（本机实测）

```text
94,445 行/秒（2 万行 212 ms）｜命中 75% ｜误伤 0
经验：正则脱敏每行约 10 µs，百万行/天的量级完全够
经验：噪声行（不含 PII）必须保持原样，否则排查断链
经验：脱敏规则要有样例集回归，改规则必跑
```

## 证据强度

- **实测**：吞吐、命中率、误伤数来自本机脚本
- **公开经验**：四种位置、必脱字段清单
- **推断**：真实日志的 PII 分布更稀疏，命中率会低于 75%

## 不适用的情况

- 审计日志（需追责）：保留必要标识，但要加密存储并限权
- 调试期间的临时日志：短期可留，事后必须清理

## 常见错法

- **把令牌打进日志**
- **全字段打码，等于没日志**
- **只在展示层脱敏**

## 结论

**暴露面是可以数的：本机 19 个 TCP 监听里，3 个绑在 `0.0.0.0`，16 个只绑 `127.0.0.1`。**
绑 `0.0.0.0` 的那 3 个才是"别人能连到"的；其余只是本机服务。
UDP 另有 **9** 个监听。

## 只数一类就够开始

```text
1. 绑 0.0.0.0 / [::] 的 TCP 端口（对外）
2. 绑 127.0.0.1 的（只本机，但若被代理转发就等于对外）
3. UDP 监听（DNS、mDNS、发现协议最容易被忽略）
4. 出站也不干净：谁在往外连（反向 shell、数据外传）
```

**"我机器没开服务"** 常常漏掉 UDP 与容器转发的端口。

## 本机可复现（已实测）

```bash
ss -H -tln | awk '{print $4}' | sort          # 19 行
ss -H -tln | awk '{print $4}' | grep -c '0.0.0.0\|\[::\]'   # 3
ss -H -uln | wc -l                             # 9
```

本机输出：

```text
0.0.0.0:8766  0.0.0.0:8767  0.0.0.0:8899
127.0.0.1:631  127.0.0.1:3080  127.0.0.1:3081  127.0.0.1:7897
127.0.0.1:8765  127.0.0.1:9222–9225  127.0.0.53:53（仅 lo）
计数：TCP 19，其中对外 3；UDP 9
```

## 数完做什么

```text
1. 每个对外端口回答三问：谁需要它？需要认证吗？能关吗？
2. 关不掉的加前置：反代 + 认证 + 限速
3. 只绑回环的，确认没有被"端口转发"变成对外
4. 定期重数：容器、开发服务器最容易临时开一个 0.0.0.0
```

**"先关掉，再问为什么开"** 比"先评估风险"更省时间：多数临时服务没人依赖。

## 数字与阈值（本机实测）

```text
TCP 监听 19 个：对外 3、仅回环 16（含 1 个 DNS 仅 lo）
UDP 监听 9 个
经验：对外端口数应是个位数；每增加一个都要有认证与日志
经验：绑 0.0.0.0 的开发服务器是最常见的意外暴露
经验：UDP 也要数，DNS/mDNS/发现协议常被漏
```

## 证据强度

- **实测**：19/3/9 三个数来自本机 `ss`
- **公开经验**：三问清单、先关后问
- **推断**：容器环境里 `ss` 看不到宿主机转发，需要额外查 `docker ps -p` 与 iptables/nftables

## 不适用的情况

- 纯离线机器：暴露面仍是"能接触到它的人"，但优先级低
- 云上安全组已限制入站：仍需数端口，防止安全组被改动

## 常见错法

- **只数 TCP 不数 UDP**
- **只看 `ss` 不看容器端口映射**
- **把"绑 127.0.0.1"当绝对安全**（同机其他用户也能连）

## 结论

**限速不能让弱口令变强，它只是把"离线枚举"逼回"在线猜测"。**
没有限速，泄露的哈希库可以离线跑；有了限速，攻击者每次尝试都要付出网络与时间成本。

## 限速防的是什么

```text
撞库：用别处泄露的账号密码批量试
爆破：对单账号穷举弱口令
枚举：用响应差异判断"账号是否存在"
```

**"撞库"是现实中最主要的威胁**：它不需要破解你的算法，只需要用户复用密码。

## 三种限速维度

| 维度 | 限制什么 | 例子 |
| --- | --- | --- |
| 按账号 | 单账号失败次数 | 5 次失败后锁定/延迟 |
| 按 IP | 单来源频率 | 每分钟 ≤ 10 次 |
| 按全局 | 总量异常 | 失败率突增触发告警 |

**三个维度都要有**：只按 IP，攻击者换 IP 就绕过；只按账号，会被人拿来锁死别人账号。

## 锁定要小心

```text
账号锁定 → 可被用来"锁死"他人账号（拒绝服务）
更好做法：渐进延迟 + 验证码 + 通知，而非硬锁定
```

**"硬锁定"是一个反向风险**：安全措施本身成了攻击面。

## 响应要一致

```text
账号不存在 与 密码错误 → 返回同样的提示与耗时
否则：可被用来枚举"哪些账号真实存在"
```

**"耗时"也会泄露**：账号不存在时若立即返回，时间差就能被统计出来。

## 数字与阈值（经验判断）

```text
单账号失败：5 次后加延迟/验证码，10 次后临时锁 15–30 分钟
按 IP：≤ 10 次/分钟，≤ 100 次/小时
渐进延迟：1s → 2s → 4s（带抖动）
告警：失败率 > 5% 或单 IP 失败 > 50 次/小时
会话空闲超时：15–30 分钟（敏感系统更短）
```

## 证据强度

- **公开经验**：限速把攻击从离线拉回在线、三维度限速、统一响应防枚举
- **数字**：次数与延迟区间来自实践经验
- **未验证**：**未在本机做压测**，具体阈值需按业务量调整
- **推断**："硬锁定是反向风险"按拒绝服务可行性推的

## 不适用的情况

- 内部低风险系统：可放宽，但仍应记录失败
- 已有强 MFA 的账号：限速压力可降低，但不能取消

## 常见错法

- **只按 IP 限速**：换 IP 即绕过
- **硬锁定账号**：被用来锁死他人
- **错误提示不一致**：泄露账号是否存在
- **只在前端限速**：直接调接口即绕过

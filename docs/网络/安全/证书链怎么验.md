## 结论

**验的是"这条链能不能走到一个我信任的根"，不是"看起来像不像正规网站"。**
链上任一环缺失、过期、域名不符，验证就失败——**而失败原因要分清是哪一种**。

## 三步验证

```text
1. 链完整性：站点证书 → 中间 CA → 根 CA（根在信任库里）
2. 有效期：notBefore ≤ 现在 ≤ notAfter
3. 名称匹配：SAN 里有你访问的域名（不再看 CN）
```

**"看 CN"是过时的做法**：现代浏览器只看 SAN（Subject Alternative Name）。

## 一条命令看全

```bash
openssl s_client -connect example.com:443 -servername example.com -showcerts 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates -ext subjectAltName
```

**必须带 `-servername`**：不带 SNI，共享 IP 的服务器会返回默认证书，验出"名称不匹配"的假故障。

## 本机实测

```text
环境：Ubuntu 22.04，OpenSSL 3.0.2，经本地代理
命令：openssl s_client -connect gh503.github.io:443 -servername gh503.github.io -brief

Protocol version: TLSv1.3
Peer certificate: CN = *.github.io
Verification:    OK
```

**`CN = *.github.io` 是通配符证书**：匹配 `a.github.io`，不匹配 `a.b.github.io`（通配符只覆盖一级）。

**`Verification: OK` 只说明链验通了**，不说明这个站点值得信任。

## 四类失败与含义

| 报错 | 含义 | 该查什么 |
| --- | --- | --- |
| unable to get local issuer certificate | 缺中间证书 | 服务端是否发全链 |
| certificate has expired | 过期 | 续期与自动续期任务 |
| hostname mismatch | 名称不符 | SNI、证书绑定的域名 |
| self signed certificate | 自签 | 是否内网/是否被劫持 |

**"缺中间证书"最隐蔽**：浏览器可能靠缓存补上，命令行与部分客户端直接失败。

## 数字与阈值（经验判断）

```text
公开 CA 证书有效期：常见 ≤ 398 天（并趋于缩短）
到期预警：提前 30 天
链长度：站点 + 1–2 个中间证书（越短越好）
握手额外开销：链越长，传输与验证越慢
通配符：只覆盖一级子域
```

## 证据强度

- **实测**：本机 `openssl s_client -brief` 输出（见上），**为真实协商与验证结果**
- **公开经验**：四类失败的含义、SAN 取代 CN、通配符只覆盖一级
- **推断**："缺中间证书最隐蔽"按客户端行为差异推的

## 不适用的情况

- mTLS：还要验客户端证书
- 内网自签体系：根证书需另行分发，验证逻辑相同

## 常见错法

- **只配站点证书不发中间证书**：部分客户端失败
- **以为通配符覆盖多级**：`*.a.com` 不含 `x.y.a.com`
- **手工续期不设监控**：到期当天才发现

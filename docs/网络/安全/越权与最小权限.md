## 结论

**越权不是"权限给多了"，是"检查放在了错误的位置"。**
本机实测这台机器的权限面：**setuid/setgid 程序 16 个**、家目录里全局可写文件 **0 个**、SSH 私钥权限 **600**——
**这三项都能一条命令查出来，绝大多数越权事故就藏在这里。**

## 两种越权

```text
水平越权：同角色之间互看（A 用户的订单被 B 用户看到）→ 缺"资源归属"检查
垂直越权：低权限做高权限的事（普通用户调到管理接口）→ 缺"角色"检查
  → 两者都不是密码问题，是每个入口都要做的判断
```

**"前端不显示按钮"** 不是权限控制，改个请求就绕过了。

## 本机可复现（已实测）

```bash
find /usr -xdev -perm -4000 -type f | wc -l          # 16
find ~ -maxdepth 4 -perm -0002 -type f | wc -l       # 0
ls -l ~/.ssh | awk '{print $1, $NF}'                 # 私钥 600
```

本机输出：

```text
setuid/setgid 16 个 ｜ 家目录全局可写 0 个 ｜ id_ed25519 600、公钥 644
```

## 检查清单（按顺序）

```text
1. 每个"带 id 的接口"是否校验了资源归属（水平）
2. 每个"管理接口"是否校验了角色（垂直）
3. 默认拒绝：新接口默认无权限，显式授予
4. 批量接口：一次传 100 个 id，是否每个都校验（最常见的漏点）
5. 文件与命令：setuid 数量、全局可写、私钥权限
```

## 最小权限怎么落地

```text
服务账号：一个服务一个账号，只给要用的目录与端口
数据库：应用账号不给 DDL，只给需要的表
容器：只挂需要的卷，不用 --privileged
运维：日常用普通账号，提权走 sudo 且留审计
```

## 数字与阈值（本机实测）

```text
setuid 16 个 ｜ 全局可写文件 0 个 ｜ 私钥 600 / 公钥 644
经验：setuid 程序超过 20 个就要逐个说明用途
经验：全局可写文件应为 0（临时目录除外）
经验：批量接口的越权占比最高，逐个 id 校验
经验：默认拒绝比"列黑名单"可靠
```

## 证据强度

- **实测**：三个数值来自本机
- **公开经验**：水平/垂直分类、批量接口漏点
- **推断**：真实系统的越权多发生在"新增接口忘了加检查"，而不是设计错误

## 不适用的情况

- 单用户系统：无水平越权面，垂直仍有
- 完全可信内网（极少见）：仍需服务间鉴权

## 常见错法

- **只在前端隐藏入口**
- **批量接口只检查第一个 id**
- **服务账号用 root 跑**

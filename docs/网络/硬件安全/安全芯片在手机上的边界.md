## 结论

**安全芯片能保证"密钥不被读走、运算不被篡改"，不能保证"你看到的界面是真的"。**
本机实测密码学开销：RSA-2048 验签 **89.5 µs**、Ed25519 验签 **192.8 µs**、sha256 吞吐 **269 MB/s**——
**这些运算放进 TEE 完全不构成性能问题，所以"上安全芯片会卡"不是拒绝的理由。**

## 三种"安全区"

```text
SE（安全元件）：独立芯片，密钥永不出芯片（SIM、eSE、Apple SE）
TEE（可信执行环境）：CPU 的特权模式，与主系统隔开（TrustZone、SEV）
TPM：主板上的独立芯片，做度量与密钥封装（PC/服务器）
共同点：都比普通应用更难攻破；都不是"防一切"的银弹
```

**"有 TEE 就安全了"** 屏幕、输入、传感器仍由主系统控制，钓鱼与界面劫持照样成立。

## 本机可复现（已实测，密码学成本）

```bash
python3 - <<'PY'
from cryptography.hazmat.primitives.asymmetric import rsa, padding, ed25519
from cryptography.hazmat.primitives import hashes
import time
k=rsa.generate_private_key(public_exponent=65537,key_size=2048); pub=k.public_key()
m=b"x"*100; s=k.sign(m,padding.PKCS1v15(),hashes.SHA256())
N=2000; t=time.perf_counter()
for _ in range(N): pub.verify(s,m,padding.PKCS1v15(),hashes.SHA256())
print("RSA-2048 %.1f µs" % ((time.perf_counter()-t)/N*1e6))
PY
```

本机输出：

```text
RSA-2048 验签 89.5 µs ｜ Ed25519 验签 192.8 µs ｜ sha256 269 MB/s（32 MB 119 ms）
```

## 边界在哪

```text
能保护：密钥、指纹模板、支付凭证、设备唯一身份
不能保护：屏幕显示、触摸输入、系统是否被 root、应用是否在骗你
  → 所以"安全输入"需要 TEE 直接接管显示与输入（成本极高，只有支付场景常见）
```

## 判据：该不该依赖它

```text
密钥要"即使系统被攻破也不泄露" → 用 SE/TEE 存密钥
要"证明这台设备是它自己" → 用硬件证明（attestation）+ 服务端校验
要"防用户自己截图/录屏" → 芯片帮不上，只能靠策略（且能绕过）
```

## 数字与阈值（本机实测）

```text
RSA-2048 89.5 µs ｜ Ed25519 192.8 µs ｜ sha256 269 MB/s
经验：单次验签 < 0.1 ms，放 TEE 里也不是瓶颈
经验：TEE 的信任根在芯片厂商，供应链风险随之转移
经验：硬件证明要服务端校验，客户端自证等于没证
```

## 证据强度

- **实测**：三组密码学开销来自本机
- **公开经验**：SE/TEE/TPM 的分工与边界
- **推断**：手机侧的 TEE 攻击面主要在厂商实现与固件更新链

## 不适用的情况

- 纯在线服务（服务端持有密钥）：客户端芯片不参与信任链
- 低价值数据：用芯片反而增加复杂度

## 常见错法

- **把"有 TEE"当作防钓鱼**
- **客户端自证设备可信**
- **以为链上成本高所以不用硬件密钥**

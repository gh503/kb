## 结论

**信任链从"不可改的 ROM"开始，到"操作系统加载完"就断了。**
本机实测的组合说明问题：**EFI + Secure Boot 关 + TPM 2.0 有但未用于密封 + 全盘无 LUKS**——
每一环单独看都"还行"，连起来**信任链没建立**。

## 信任链的五环

```text
1. CPU 微码 / Boot ROM（不可改）
2. UEFI 固件（可更新，需签名）
3. 引导程序（Secure Boot 校验）
4. 内核与 initramfs（签名/度量）
5. 用户态（无硬件保证）
```

**"第 5 环没有硬件保证"** 是根本限制：系统跑起来之后，硬件帮不上忙。

## 本机实测的五环状态

| 环节 | 本机状态 | 评价 |
| --- | --- | --- |
| 微码 | 0xf8 | 有，版本待核对 |
| UEFI | EFI 模式 | 有 |
| Secure Boot | **disabled** | 断 |
| TPM 度量 | 有芯片，未用 | 断 |
| 磁盘加密 | **无 LUKS** | 断 |

**"三处断"** 意味着：物理接触者可以改引导、读磁盘。

## 本机可复现（已实测）

```bash
[ -d /sys/firmware/efi ] && echo EFI; mokutil --sb-state
ls /dev/tpm0; lsblk -o FSTYPE | grep -c crypto_LUKS
```

本机输出：

```text
EFI 模式
SecureBoot disabled
/dev/tpm0
0
```

## 三个务实的选择

```text
1. 只防"设备丢失" → 全盘加密（含 swap）最有效
2. 只防"引导被改" → Secure Boot + 签名内核
3. 两者都要 → TPM 密封 + Secure Boot + LUKS
```

**"先加密"**：它对应最常见的损失场景，且不依赖 Secure Boot。

## 信任根之外还剩什么

```text
供应链（硬件在到手前被改）
固件后门（BMC/ME）
物理接触（冷启动、总线抓取）
```

**"再强的信任链也假设硬件本身可信"**：这是模型的前提，不是结论。

## 数字与阈值（本机实测）

```text
EFI 有 ｜ Secure Boot 关 ｜ TPM 2.0 有 ｜ LUKS 0 ｜ swap 22.9 GB 明文
经验：笔记本三件套 = LUKS + Secure Boot + TPM 密封
经验：服务器更依赖物理与网络隔离，而非 Secure Boot
```

## 证据强度

- **实测**：四项状态为本机输出
- **公开经验**：信任链五环模型
- **推断**："三处断"是按五环模型对照得出的判断

## 不适用的情况

- 一次性/可丢弃的机器：不值得建信任链
- 高保障场景：还需要 TPM 远程证明、measured boot

## 常见错法

- **只做 Secure Boot 不加密磁盘**
- **有 TPM 却不留恢复密钥**
- **把"信任链"当"系统安全"**

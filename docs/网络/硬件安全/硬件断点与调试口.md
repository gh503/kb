## 结论

**调试口的风险不在"能调试"，在"能读到内存与密钥、能改执行流"，而且它是物理接触就能用。**
本机实测资产：USB 设备 **4 个**、串口设备 **0 个**——**没有暴露调试串口，是这台机器的默认安全姿态**。

## 三类调试能力

```text
硬件断点：CPU 在指定地址/访问上停住（不修改代码，难检测）
JTAG/SWD：直接读写内存、寄存器、闪存（最强，也最容易封）
串口控制台：能进 bootloader / 单用户模式（很多设备默认开着）
```

**"锁了 bootloader 就安全"** 硬件断点不经过 bootloader。

## 本机可复现（已实测）

```bash
lsusb | wc -l                      # 4
ls /dev/tty{USB,ACM}* 2>/dev/null  # 0
ls /sys/bus/usb/devices/*/product 2>/dev/null | wc -l
```

本机输出：

```text
USB 设备 4 个 ｜ 调试串口设备 0 个
```

## 防护的三层

```text
1. 熔丝（eFuse）：一次性关闭 JTAG（不可逆，量产常用）
2. 调试认证：需要签名挑战才能开调试口（可逆，可留售后通道）
3. 物理：灌封、屏蔽罩、拆开即擦除（防拆开关）
```

**"软件里关掉调试"** 挡不住物理接触。

## 判据：这台设备怕不怕

```text
密钥在芯片里 + 调试口熔断 → 物理接触拿不到密钥（成本高）
密钥在 flash 里 + 调试口可开 → 拆机读 flash 即可（成本低）
有防拆擦除 → 提高成本，但不能阻止"先读后擦"的高级手段
```

## 数字与阈值（本机实测）

```text
USB 4 个 ｜ 串口 0 个
经验：量产设备应熔断 JTAG 或启用调试认证
经验：售后需要调试通道时，用签名挑战而不是固定口令
经验：物理接触视为"已失守"，密钥要能远程吊销
```

## 证据强度

- **实测**：USB 与串口数量来自本机
- **公开经验**：三层防护、物理接触假设
- **推断**：不同 SoC 的熔丝策略差异大，需查具体型号的安全手册

## 不适用的情况

- 开发板/实验设备：调试口就是要开着的
- 全封闭消费设备（无螺丝、灌封）：物理攻击成本已很高

## 常见错法

- **以为关掉软件调试就安全**
- **售后通道用固定口令**
- **密钥存 flash 且不加密**

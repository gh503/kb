## 结论

**每一项缓解都有代价，`/sys` 里那一行文字告诉你的不只是"安全"，还有"你付了什么"。**
本机实测：17 个条目里，**4 项写了 `SMT disabled`**——那是拿超线程换安全。

## 三个词的区别

```text
Mitigation: …   → 已启用某种缓解（有代价）
Not affected    → 硬件/微码层面不存在该问题
Vulnerable      → 没有缓解（危险）
```

**"Mitigation" 之后那串细节才是关键**：写了什么被关掉了。

## 本机可复现（已实测）

```bash
cat /sys/devices/system/cpu/vulnerabilities/meltdown      # Mitigation: PTI
cat /sys/devices/system/cpu/vulnerabilities/mds           # Mitigation: Clear CPU buffers; SMT disabled
grep -qw smep /proc/cpuinfo && echo smep 有               # 硬件特性
```

本机输出（关键几项）：

```text
meltdown    Mitigation: PTI
spectre_v2  Mitigation: IBRS; IBPB: conditional; STIBP: disabled; RSB filling; ...
l1tf        Mitigation: PTE Inversion; VMX: conditional cache flushes, SMT disabled
mds         Mitigation: Clear CPU buffers; SMT disabled
retbleed    Mitigation: IBRS
```

## 读法：从右往左

```text
"Mitigation: Clear CPU buffers; SMT disabled"
→ 做了什么：清缓冲区
→ 代价是什么：关掉超线程
→ 为什么：MDS 依赖 SMT 共享缓冲
```

**"看到 SMT disabled 就知道性能掉了"**：超线程通常带来 20%–30% 的多线程吞吐。

## 硬件特性也要看

```bash
for f in smep smap pti md_clear ibpb ibrs ssbd; do
  printf '%-8s %s\n' $f "$(grep -qw $f /proc/cpuinfo && echo 有 || echo 无)"
done
```

本机输出（全有）：

```text
smep 有 ｜ smap 有 ｜ pti 有 ｜ md_clear 有 ｜ ibpb 有 ｜ ibrs 有 ｜ ssbd 有
```

**"有标志" ≠ "已启用"**：`pti` 标志说明 CPU 支持，是否开启看上面的 vulnerabilities 条目。

## 数字与阈值（本机实测）

```text
17 条条目：多数 Mitigation，4 项含 SMT disabled
meltdown → PTI；spectre_v2 → IBRS + RSB filling
CPU 标志 smep/smap/pti/md_clear/ibpb/ibrs/ssbd 全部存在
经验：SMT 关闭的代价约 20%–30% 多线程吞吐
```

## 证据强度

- **实测**：条目文本与 CPU 标志为本机输出
- **公开经验**：SMT 的性能代价区间
- **推断**："4 项 SMT disabled"由文本计数得出

## 不适用的情况

- 单线程为主的负载：SMT 关闭影响小
- 新一代 CPU：部分问题在硬件层已消除（`Not affected`）

## 常见错法

- **只看有没有 "Mitigation"**
- **忽略 `SMT disabled` 的性能含义**
- **把 CPU 标志当"已启用"**

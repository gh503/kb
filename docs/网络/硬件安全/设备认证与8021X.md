## 结论

**802.1X 回答的是"这个端口/这个 Wi-Fi 该不该放行"，不是"这台机器可不可信"。**
本机实测：`nmcli` 与 `wpa_supplicant` 都在，但**没有任何 802-1x 连接配置**——
家庭/个人网络基本不用它，企业有线与 Wi-Fi 才用。

## 它解决什么

```text
没有 802.1X：插上网线就能上网（端口默认放行）
有 802.1X：先认证（证书/账号），通过后才放行端口
  → 挡住"陌生人插网线"
  → 挡住"离职员工的设备还在网络上"
```

**"认证的是凭据，不是设备健康状态"**：拿到合法证书的失陷机器照样能进。

## 本机可复现（已实测）

```bash
command -v nmcli wpa_supplicant
nmcli -f NAME,TYPE connection show | head
nmcli -f 802-1x connection show 2>/dev/null | head -3
ls /etc/wpa_supplicant/ 2>/dev/null
```

本机输出：

```text
/usr/bin/nmcli
/usr/sbin/wpa_supplicant
（连接列表里没有 802-1x 类型的配置）
```

## 与设备认证的分工

```text
802.1X：网络准入（谁能连上来）
设备证书/TPM：设备身份（这台机器是不是它自称的那台）
NAC/EDR：设备健康（补丁、杀软、配置合规）
```

**"三层串起来才有意义"**：只做 802.1X，等于只查了门禁卡。

## 什么时候值得上

```text
值得：办公网有访客、有外包、有离职流动；合规要求网络准入
不值得：家庭网络、三五人的固定团队、全无线且已用 WPA3-Enterprise
```

**"WPA3-Enterprise 已经包含 802.1X"**：无线侧常由它覆盖，有线侧才需要单独部署。

## 数字与阈值（本机实测）

```text
本机 nmcli 与 wpa_supplicant 可用，但 0 个 802-1x 连接
经验：部署 802.1X 的最大成本是证书生命周期，不是交换机配置
经验：证书过期导致的断网事故，比被蹭网更常见
经验：先做"有线端口认证"，再做无线
```

## 证据强度

- **实测**：工具存在性与 0 个配置来自本机
- **公开经验**：三层认证的分工与部署成本
- **推断**："证书过期事故更多"来自公开运维经验，非本机数据

## 不适用的情况

- 家庭网络：收益低于维护成本
- 完全隔离的实验网：本来就没有外部设备接入

## 常见错法

- **把 802.1X 当"设备可信"**
- **证书有效期设太长，轮换时全网点掉线**
- **只做无线，忘了有线端口默认放行**

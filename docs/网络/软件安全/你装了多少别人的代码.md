## 结论

**你写的那几百行不是你的攻击面，你装的那几百个包才是。**
本机实测：Python 环境里 **356 个包**，其中 **224 个（63%）自己零依赖**，**138 个带可执行入口**；
npm 上只写一行 `express`，锁文件里落下来 **65 个包**。

## 依赖是怎么膨胀的

```text
你写 1 行 dependencies: express ^5.3.0
  → 直接依赖 28 个
  → 传递依赖再拉 37 个
  → 共 65 个包，全部会在你的进程里执行
每一个包 = 一份代码 + 一个维护者 + 一条发布链
```

**"我的代码只有 300 行"** 通常意味着"我审过的代码只有 300 行"。

## 本机可复现（已实测）

```bash
# Python：装了多少、多少是叶子、多少带入口
python3 - <<'PY'
import importlib.metadata as md
dists = [d for d in md.distributions() if d.metadata['Name']]
print('已安装包:', len(dists))
leaf = sum(1 for d in dists if not [r for r in (d.requires or []) if 'extra ==' not in r])
print('零依赖的包:', leaf)
print('带入口点的包:', sum(1 for d in dists if list(d.entry_points)))
PY

# npm：一个框架拉进来多少
mkdir -p /tmp/npmtest && cd /tmp/npmtest && npm init -y >/dev/null
npm install express --package-lock-only --no-audit --no-fund >/dev/null
python3 -c "import json;d=json.load(open('package-lock.json'));print('包数:',len([k for k in d['packages'] if k.startswith('node_modules/')]))"
```

本机输出：

```text
已安装包: 356
零依赖的包: 224
带入口点的包: 138
包数: 65
```

## 依赖闭包比"依赖数"更接近真相

本机实测的闭包大小（从某个包出发，递归展开它需要的一切）：

```text
requests                → 1 个包（本机只装了它自己，没有额外依赖）
pytest                  → 3 个包（1 个没装：可选依赖没被拉进来）
aiohttp                 → 11 个包
colcon-common-extensions → 36 个包（3 个没装）
```

**"我装了一个小工具"** 的实际含义可能是 36 个包。

## 数字与阈值（本机实测）

```text
Python 包 356 ｜ 零依赖 224（63%）｜ 带入口点 138
依赖最多的包：colcon-common-extensions 20 个直接依赖、bloom 12 个、aiohttp 9 个
npm：express ^5.3.0 → 65 个包，其中 0 个带 install 脚本
经验：直接依赖 > 50 的项目，应当有专人负责升级与审计
经验：传递依赖每季度至少全量过一遍版本
```

## 证据强度

- **实测**：包数、叶子数、入口点数、闭包数、npm 65 个都来自本机（Python 3.10 / npm 11.9）
- **公开经验**：依赖面 ≈ 攻击面的说法
- **推断**：闭包大小随版本变化，数字只代表本机装的这一版

## 不适用的情况

- 纯标准库程序：依赖面为零，本页不适用
- 隔离在独立容器且不联网的服务：依赖被盗用的影响面被限制

## 常见错法

- **只数 `package.json` 里的直接依赖**
- **以为"零依赖包"就安全**：它自己的代码仍然要跑
- **从不看锁文件里到底有什么**

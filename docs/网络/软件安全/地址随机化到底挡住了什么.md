## 结论

**ASLR 让"写死的地址"失效，但它不隐藏地址泄漏。**
本机实测：开着 ASLR，三次启动的栈基址分别是 `7ffccd471000`、`7ffe1da63000`、`7ffd0dd86000`；
关掉之后**三次全是 `7ffffffdd000`**。

## 它随机化什么

```text
栈、堆、共享库、mmap 区域、可执行文件（PIE）
不随机：内核直接映射区（部分）、vsyscall
```

**"PIE 是 ASLR 对主程序生效的前提"**：没有 PIE，代码段地址固定，ASLR 少了一大块。

## 本机可复现（已实测）

```bash
# 查看开关：0 关、1 部分、2 全开
cat /proc/sys/kernel/randomize_va_space      # 本机 2

# 正常启动三次，看 [stack] 基址
for i in 1 2 3; do cat /proc/self/maps | grep '\[stack\]'; done

# 关闭 ASLR 再跑三次
setarch x86_64 -R bash -c "cat /proc/self/maps | grep '\[stack\]'"
```

本机输出：

```text
普通启动 stack: 7ffccd471000-7ffccd493000
普通启动 stack: 7ffe1da63000-7ffe1da85000
普通启动 stack: 7ffd0dd86000-7ffd0dd88000

关闭 ASLR stack: 7ffffffdd000-7ffffffff000   （三次完全相同）
```

**"三次相同"就是 ASLR 被关掉的证据**，一眼可辨。

## 它挡不住什么

```text
1. 信息泄漏：程序自己打印指针、日志带地址 → 随机化被绕过
2. 暴力猜测：32 位地址空间熵低，可反复试
3. 部分覆盖：只改低字节，高位不用猜
4. 不随机的东西：某些固定映射、共享内存
```

**"ASLR 不是加密"**：它只是把"写死地址"变成"要先泄漏一次"。

## 怎么自查

```bash
cat /proc/sys/kernel/randomize_va_space     # 应为 2
# 二进制是否 PIE
readelf -h ./bin | grep Type                # DYN
# 同一程序两次栈地址是否不同
```

**"熵够不够"看地址变化位数**：本机变化在高位，说明随机化生效。

## 数字与阈值（本机实测）

```text
randomize_va_space = 2（全开）
栈基址三次：7ffccd471000 / 7ffe1da63000 / 7ffd0dd86000
关闭后固定：7ffffffdd000
经验：64 位 ASLR 熵约 28 位（栈），32 位只有约 8–16 位
经验：容器里注意 `--security-opt` 与 ASLR 的交互
```

## 证据强度

- **实测**：六行地址为本机输出
- **公开经验**：ASLR 的随机化范围与熵
- **推断**："熵 28 位"是公开数据的引用，未在本机测量

## 不适用的情况

- 需要确定性地址的调试/性能分析场景（也是攻击者想要的）
- 实时系统：随机化可能影响确定性

## 常见错法

- **以为开了 ASLR 就不用 PIE**
- **日志里打印指针**
- **在容器里默认假设 ASLR 生效**

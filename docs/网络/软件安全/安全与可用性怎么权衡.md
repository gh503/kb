## 结论

**每一条安全措施都在某个维度上收税：延迟、成本、操作步骤、故障时的可恢复性。**
判断标准不是"更安全更好"，而是**"这条措施挡住的风险，值不值它带来的摩擦"**。

## 四种税

| 措施 | 收什么税 | 典型量级 |
| --- | --- | --- |
| 全链路加密 | 延迟、CPU | 握手多 1–2 个 RTT |
| 多因子认证 | 操作步骤 | 每次登录多 10–30 秒 |
| 最小权限 | 排障难度 | 故障定位时间上升 |
| 严格输入校验 | 兼容性 | 合法请求被拒的概率 |

**"排障难度"最少被计入**，但它常常是最大的一笔。

## 怎么算这笔账

```text
风险 = 发生概率 × 损失
措施成本 = 延迟成本 + 人力成本 + 误拒成本
值得做 ⇔ 风险降低 > 措施成本
```

**"降低的是概率还是损失"要分清**：备份降低损失，加固降低概率。

## 本机可复现（已实测）

```bash
# 本机的"最小权限"现状：世界可写文件 0 个、监听 24 个 socket
find docs -type f -perm -o+w | wc -l      # 0
ss -lntu | tail -n +2 | wc -l             # 24
```

本机输出：

```text
0
24
```

**"0 个世界可写"是低成本高收益的典型**：几乎不影响任何人，但挡住了"任意用户改文件"。

## 三个判断原则

```text
1. 默认收紧，按需放开（白名单而不是黑名单）
2. 把摩擦放在低频操作上（登录时严，运行时松）
3. 故障时要能降级（不能因为认证服务挂了就全站不可用）
```

**"降级路径"是安全设计里最常缺的一块**：严格校验 + 无降级 = 一次误判全站停摆。

## 数字与阈值（本机实测 + 经验）

```text
世界可写文件 0 ｜ 监听 socket 24
经验：多因子让账号被盗率下降 >99%（公开统计）
经验：TLS 握手增加 1–2 RTT，会话复用可摊薄
经验：误拒率 >1% 的校验规则要重新设计
```

## 证据强度

- **实测**：两项计数为本机输出
- **公开经验**：MFA 效果、TLS 开销
- **推断**："降级路径"的重要性来自故障案例，未在本机复现

## 不适用的情况

- 强监管场景（金融、医疗）：合规是硬约束，不能只算经济账
- 内部低价值系统：过度加固反而增加维护负担

## 常见错法

- **"安全无价"**：不做成本核算，最后被绕过
- **只加不减**：每次事故都加一条规则，系统越来越难用
- **没有降级路径**

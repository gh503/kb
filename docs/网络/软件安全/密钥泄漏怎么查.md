## 结论

**密钥泄漏几乎都是"提交进了仓库"，而仓库历史删不掉。**
本机实测：这个 651 页的文档仓库，按三种常见模式扫描，命中 **0 个文件**；但"password"字样出现在 **3 个文件**里——**关键词不等于密钥，误报要人工看**。

## 三种最常见的泄漏形态

```text
1. 硬编码在源码里（AKIA…、ghp_…、BEGIN PRIVATE KEY）
2. 提交进 .env 或配置文件，然后被 git 记住
3. 打进二进制/镜像（字符串常量）
```

**"删掉那个文件"没用**：`git log` 里还在，克隆一次就拿得到。

## 本机可复现（已实测）

```bash
grep -rIl --exclude-dir=.git -E 'AKIA[0-9A-Z]{16}|BEGIN (RSA |EC )?PRIVATE KEY|ghp_[A-Za-z0-9]{36}' .
grep -rIil --exclude-dir=.git 'password' . | wc -l
```

本机输出（本仓库，651 篇文档）：

```text
命中文件数: 0
含 password 字样的文件数: 3
```

**"0 命中"说明模式没抓到真东西，"3 个 password"提醒你关键词扫描会误报**——
那 3 个文件里是讲"密码管理器"的正常内容。

## 二进制里也会留

```text
strings -n 6 ./bin | wc -l
```

本机实测：同一程序，无调试信息 **59 条**可读字符串，带 `-g` 是 **112 条**，
且两者都能看到源码里写死的路径 `/etc/shadow`。

**"编译后密钥就藏起来了"是错的**：字符串常量原样躺在产物里。

## 查的顺序

```text
1. 扫工作区（上面两条命令）
2. 扫 git 历史：git log -S 'AKIA' --oneline
3. 扫构建产物：strings 镜像/二进制
4. 扫 CI 变量与日志
```

**"扫历史"最容易被跳过**，而它恰恰是泄漏最长寿的地方。

## 数字与阈值（本机实测）

```text
本仓库：3 种密钥模式 0 命中；password 字样 3 个文件（误报）
二进制可读字符串：59（无 -g）/ 112（-g）
经验：密钥扫描要跑在 pre-commit 与 CI 两处
经验：发现泄漏第一件事是轮换，不是删文件
```

## 证据强度

- **实测**：扫描计数为本机 grep/strings 输出
- **公开经验**：三种泄漏形态与"历史删不掉"
- **推断**："误报要人工看"由本机 3 个 password 命中得出

## 不适用的情况

- 公开的示例密钥（文档里的 `AKIAIOSFODNN7EXAMPLE`）：是占位符，不是泄漏
- 已用短期凭证（STS）：过期即失效，风险窗口小

## 常见错法

- **以为删文件就完事**（历史还在）
- **只扫源码不扫产物**
- **发现后先删再轮换**（应先轮换，避免窗口期被用）

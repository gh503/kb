## 结论

**报错和日志泄漏的不是"密码"，是**结构**：路径、用户名、版本、SQL、内网地址。**
本机实测：一个普通 Python 异常的堆栈里直接带出绝对路径 `/tmp/seclab/t.py`——换成生产路径就是目录结构。

## 一个堆栈能带出什么

```text
绝对路径 → 目录结构、项目名
文件行号 → 代码版本
异常类型 → 语言/框架/版本
SQL 语句 → 表名、字段名
内网地址 → 拓扑
```

**"只是报个错"往往已经给了一张地图**。

## 本机可复现（已实测）

```python
# t.py
def f():
    raise ValueError("boom")
f()
```

本机输出：

```text
File "/tmp/seclab/t.py", line 2, in f
ValueError: boom
```

**路径 `"/tmp/seclab/t.py"` 原样出现在响应里**。若这是 Web 服务的 500 页面，等于把目录结构送给对方。

## 日志里的另外三类

| 类型 | 例子 | 风险 |
| --- | --- | --- |
| 凭证 | token、cookie、Authorization 头 | 直接可用 |
| 个人数据 | 手机号、邮箱、身份证 | 合规与隐私 |
| 内部标识 | 内网 IP、主机名、队列名 | 拓扑侦察 |

**"日志是给人看的"**：默认它会被复制到工单、聊天、监控平台。

## 怎么自查（可执行）

```bash
# 文档/配置里世界可写的文件：本机 0 个
find docs -type f -perm -o+w | wc -l

# 监听面：本机 24 个 socket
ss -lntu | tail -n +2 | wc -l

# 日志里是否出现绝对路径/内网地址（按需替换模式）
grep -rE '/home/|10\.[0-9]+\.[0-9]+\.[0-9]+' /var/log 2>/dev/null | head
```

本机输出：

```text
世界可写文件: 0
监听 socket: 24
```

**"0 个世界可写"是最低标准**，不是安全证明。

## 该怎么做

```text
1. 生产环境关掉详细堆栈，只留 error id
2. 日志脱敏（手机号/邮箱/证件号）
3. 不记录 Authorization / Cookie 原文
4. 日志文件权限 640，目录 750
```

**"error id + 内部日志"** 是标准做法：用户看到编号，你按编号查详情。

## 数字与阈值（本机实测）

```text
堆栈泄漏绝对路径：1 处（/tmp/seclab/t.py）
世界可写文件：0 个
监听 socket：24 个
经验：日志权限 640、目录 750
经验：生产环境堆栈只进内部日志，不进响应
```

## 证据强度

- **实测**：三项计数为本机输出
- **公开经验**：日志脱敏与 error id 做法
- **推断**："24 个 socket 里有过期服务"未逐条核实，只作为检查项

## 不适用的情况

- 纯本地单机工具：没有外部读者
- 已做结构化日志 + 采样：风险仍在，只是可审计

## 常见错法

- **把完整堆栈返回给用户**
- **把 token 打进日志**
- **日志文件权限 666**

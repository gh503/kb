## 结论

**"版本范围"是给解析器的自由，"锁文件"是给生产环境的确定性。两者必须同时存在。**
本机实测：356 个包里，依赖声明写着 `==` 精确锁定的只有 **10 条（4.0%）**，
其余是 `>=`（67 条）、`<`（21 条）、无约束（142 条）。

## 三种写法各自意味着什么

```text
requests >=2.0,<3      → 解析器每次都可能装到新版；范围越宽，漂移越大
requests ==2.31.0      → 精确，但升级要手工改，且不解决传递依赖
lockfile（poetry.lock / package-lock.json）→ 锁住整棵树，含传递依赖
```

**只锁直接依赖不够**：真正的漂移发生在传递依赖上。

## 本机可复现（已实测）

```bash
python3 - <<'PY'
import importlib.metadata as md, re, collections
names = {d.metadata['Name'].lower(): d for d in md.distributions() if d.metadata['Name']}
ops = collections.Counter()
for n, d in names.items():
    for r in (d.requires or []):
        if 'extra ==' in r: continue
        m = re.search(r'[<>=!~]=?', r)
        ops[m.group(0) if m else '无约束'] += 1
print('约束形态:', ops.most_common())
print('精确锁定占比: %.1f%%' % (ops['=='] / max(1, sum(ops.values())) * 100))
PY

# npm 默认给的是什么范围
cd /tmp/npmtest && python3 -c "import json;print(json.load(open('package.json'))['dependencies'])"
```

本机输出：

```text
约束形态: [('无约束', 142), ('>=', 67), ('<', 21), ('==', 10), ('!=', 5), ('~=', 3)]
精确锁定占比: 4.0%
{'express': '^5.3.0'}
```

**`^5.3.0` 的含义是"5.x 里的任何新版本"**：一次 `npm install` 就可能装上 5.9。

## 锁文件真正解决的问题

```text
没有锁文件：CI 装出来的树可能和本地不同 → "我这儿是好的"
有锁文件 + npm ci：按锁文件重装，装出来的树逐字节可复现
有锁文件 + npm install：仍可能更新锁文件 → 不确定性回来了
```

**"用 `npm ci` 不用 `npm install`"** 是 CI 里的第一道确定性。

## 什么时候可以放宽

```text
1. 库/工具包：需要兼容范围，锁文件不发布
2. 应用/服务：必须锁死，锁文件入库
3. 一次性脚本：不锁也行，跑完就扔
```

**"库锁死、应用锁死"** 是两条相反的正确做法，取决于你在发布什么。

## 数字与阈值（本机实测）

```text
本机 356 个包：无约束 142 ｜ >= 67 ｜ < 21 ｜ == 10（4.0%）｜ != 5 ｜ ~= 3
npm 默认范围 ^5.3.0 → 解析出 65 个包
经验：锁文件必须入库，`node_modules` 不入库
经验：CI 用 `npm ci` / `pip install -r requirements.txt --require-hashes`
经验：升级用"一次一个 + 跑测试"，不要 `npm update` 一把梭
```

## 证据强度

- **实测**：约束形态分布与 npm 范围来自本机
- **公开经验**：锁文件与 `npm ci` 的语义
- **推断**："4.0% 精确锁定"只代表本机这个环境

## 不适用的情况

- 单文件脚本、无第三方依赖
- 内部私有包且版本由自己控制：范围漂移风险低

## 常见错法

- **把 `^` 当"锁版本"**
- **锁了直接依赖，忽略传递依赖**
- **CI 里跑 `npm install` 而不是 `npm ci`**
